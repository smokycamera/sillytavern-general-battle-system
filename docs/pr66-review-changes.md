## 1. 不再绕过 32/64

所有规则版本的新开战统一计数：仅实际 ready 且 hp>0 的卡片参与容量判定；不按编队人数或车辆数计数。默认至多32张进入小战，33—64进入会战，超过64拒绝。纯旧规则、纯V2和混合名单使用同一判定；引擎 start 也校验上限。

新建旧规则/混合会战同样准备每阵位容量并冻结 formationSlots；旧规则机动在下令和实际执行时均检查容量，避免多单位同时移入造成超额。旧规则不擅自转换成V2，不把人物改成编队，不凭新规则自动起飞。混合规则显式空中/敌侧阵位仍受旧战斗引擎约束，会明确拒绝，不能误称所有V2能力均可混用。

已开始的历史战斗不重新套人数限制，没有 formationSlots 的旧快照维持原规则。二次API自动设计和分层地图仍属于原V2路径；本轮没有把旧战斗引擎换成V2地图引擎。

## 2. 工事全向防护

取消工事防护对南北朝向的依赖，所有攻击方向一致。完好工事原防护值3、受损值1、被摧毁0不变；不是增加一套新的叠加防护。旧存档保留的 facing 不影响全向防护，新建工事不写 facing。面板显示“全向防护”，边框不再指向南侧。

## 3. 六类场景、独立门计划

`scene` 从环境和地图尺寸中独立出来：

- `field`：普通野战，沿用原环境与路网生成。
- `city_siege`：城市攻防，城防轮廓、城门、破口独立。
- `city_streets`：城区巷战，街道与整块建筑街区，不自动强加城墙或夺旗。
- `building_siege`：围攻一座可进入的目标建筑/院落，内外空间与入口明确；墙体显示“外墙”，不是“城墙”。
- `interior`：连续走廊、侧室、隔墙、房门、室内掩体。扩容仍保持室内，不变成室外城区。
- `trenches`：相连战斗壕、交通壕、无人地带和弹坑，不是孤立工事逐格随机散布。

副API可用如下字段决定0—4个门及每个门的独立状态：

```json
{
  "scene": "city_siege",
  "shape": "enclosure",
  "gatePlan": [
    {"sector": "front_center", "state": "closed"},
    {"sector": "left", "state": "open"},
    {"sector": "rear", "state": "destroyed"}
  ],
  "breaches": {"count": 1, "width": 2, "sector": "right"},
  "landmarks": [{"kind": "square", "anchor": "core", "label": "内城广场"}]
}
```

数组长度就是门数；空数组表示无门。完整、开启、摧毁按各门分别处理；毁门不占墙体破口数量。旧 gates/gateState 仍兼容，gatePlan 优先。方位无对应墙段会在本地选择最近合法位置并说明；没有空间则扩图或明确拒绝，不悄悄少生成门。无城防的野战、巷战、堑壕场景不接受非空门计划。

建筑围攻复用现有墙、门与控制区机制，并非新增多层室内或建筑倒塌模拟。普通野战主要保留原生成器，本轮没有重写每一种野外环境。

## 4. 地标：必须返回，但不要求逐字证据

正向要求副API返回1—5个有效地标；允许根据场景推断空间细节和概括名称，不再要求名称逐字出现在正文，也不再以“无确定证据就省略”约束模型。

新增 building、room、cover、position 等表达，室内可用会客室、桌柜掩体、走廊转角，不需要凭空出现林间掩体。保留名称转义与合法枚举等必要校验，这些不妨碍合理命名。

API漏返、空列表、全部项目无效时中止开战准备，明确提示重试或关闭LLM地图设计；不本地填随机保底地标，不额外自动请求模型。正常返回仍是一次开战准备请求。纯本地随机模式仍有符合场景的地标；这与移除API保底是两回事。

## 5. 地图可读性

普通空街道格不再常驻“街道”文字，点选、title 和 aria-label 仍保留地形详情；地标、单位、结构、耐久、目标和危险区继续显示。建筑采用整块地块生成和相邻轮廓合并，减少逐格斜纹与随机建筑碎片。室内与建筑围攻的结构命名分别使用“隔墙/门”和“外墙/门”。
