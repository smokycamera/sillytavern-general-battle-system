# 第二轮战斗 AI 性能优化（2026-10-24）

基线为 test `f2d9131`（2.10.6，包含PR #147的室内森林断言修复），使用V32规则。本轮版本2.10.7；按用户要求完成必要验证后直接发布test，不查询或等待CI。

## 改动

- 没有盾的单位不进入能量盾、重击判定或盾牌磨损的无效计算；盾牌查询的规则版本与单位一致时复用单位，不再在每一攻击段复制完整技能和装备对象。规则不一致时保留覆盖版本的副本。
- 同一次96种子伤损抽样中，技能状态及屏障规格固定，普通武器的基础缓存只跟踪真正变化的人数、状态、实体盾余量与屏障余量。火炮保留完整目标状态；普通无盾、无屏障目标的穿透参数可跨成员减员复用。
- 对同一只读战场内内容相同的buff假设共用战场上下文，复用此前已计算的行动、来袭及可达位置。上下文、目标变化或进入下一次决策时隔离；范围外仍重建上下文。
- 小战AI的同步只读评分显式允许复用技能、装备和生成记录等不变分支的完整序列化结果。普通预览默认不启用这一假设，原地编辑技能或装备仍会立即失效。没有删去影响伤害的状态字段。

战斗规则、候选范围、96次抽样、随机数消费顺序、提示词、动态上下文和世界书均保持原有约定。新地图、技能爆发校准及最新断言修复均保留。

## 有限实测

同机Node v24.16.0、esbuild打包运行。采用固定种子、V32、每单位20名成员、混合弓兵与长兵器、每人8项技能；道具场景额外有4种携行道具。每行测一次单位决策，不包含模型请求、UI渲染或宿主保存。前后串行运行，不与测试或类型检查并行。以下为最终实现与2.10.6的对比，均未启用CPU采样器。

| 场景 | 2.10.6 | 2.10.7 | 耗时减少 |
|---|---:|---:|---:|
| 8单位，常规AI选位与技能选择 | 13.88秒 | 10.43秒 | 24.9% |
| 32单位三方，驻守意图下的技能选择 | 25.12秒 | 18.02秒 | 28.3% |
| 32单位三方，技能加道具选择 | 37.04秒 | 27.66秒 | 25.3% |

三项完整战斗快照SHA-256分别在前后相同：

- 8单位：`2b07774254c5c9c6bffddfc66d4273cf1221e3a505d7b3b752127f9cd6cb7774`。
- 32单位技能：`0f82326fe95636dbc42a27ff5b8a5825c71f87c24cc29e78e5c2fdad6dfc1ed5`。
- 32单位技能加道具：`205e38ee1bd64c2f36215a8243712a5267f82d4b48054962453004c11ced8586`。

独立伤害预览组数前两项仍为847、3658；道具场景从4378降至4344，减少的是重复计算，每组仍完整执行96种子抽样。

这些是单次诊断样本，不是多轮统计或所有战场的承诺。密集技能场景仍有明显计算开销。另一次明确指定目标的buff和道具指令执行只需约8–13毫秒，说明“按已给定指令施放”与“AI从大量技能、目标中选择”应分别诊断；模型响应时间没有通过付费调用测量。

最终原始结果：`artifacts/ai-skills-v32/final/before.json` 与 `artifacts/ai-skills-v32/readonly-parts/after.json`。中间阶段的CPU采样结果只用于定位热点，不混入上表。

复现：

```powershell
$env:BENCH_CASE='8-auto-skills,32-hold-skills,32-hold-items'
$env:BENCH_DIR='artifacts/ai-skills-v32/reproduce'
node scripts/run-benchmark-ai-skills.mjs f2d9131
```
