# 效果来源迁移与结算复核（2026-10-26）

版本：3.0.22。修复分支：codex/fix-effect-source-migration。战斗规则仍为V38。

## 原因与修复

UnitRecord外层保存当前conditions，traitSources及traitLevelModel保存在精确snapshot中。原迁移检查外层conditions时只读取外层来源，因此合法effectSourceId被误判为“状态的效果来源记录损坏”，随后整条档案被隔离，参战名单也出现缺失引用。原deploy/effect测试只检查事务与实体化，没有走保存后的迁移入口。

现在先完整验证snapshot，再使用该快照的来源和模型验证外层状态。状态数值、冻结规格、来源编号、剩余期限及档案版本不重算。状态来源真正缺失、撤销、到期、重复或不含该状态时仍隔离并保留原件；缺少快照时不会凭状态名字重建来源。屏障也验证来源关系，避免读档时静默丢弃损坏的保护记录。

## 相邻问题排查

1. 普通技能可能把状态合并进同名剧情状态，剧情到期或撤销会吞掉尚有效的技能。合并现在区分effectSourceId，两份状态分别保留时钟；同组属性仍沿用取强逻辑。
2. 多份剧情毒、燃烧或流血原先会按来源逐份结算。现在同种同通道持续伤害每次只结算最强的一份，分别保留每个来源的期限；强效到期后弱效继续，不删除原来源。没有剧情来源的旧状态继续使用原路径。
3. 已检查spawn count、未部署档案、effect/deploy两种顺序、rounds/battles/permanent、部分解除与clear all、净化/驱散、撤销、同消息重放、屏障混用与消耗、整轮时钟、战果提交及小战/会战快照。
4. 原生服务覆盖宿主保存→从磁盘重载→迁移复核→ready→继续修改；面板覆盖含统一效果的详情、无迁移警告、撤销后保存与重载。

本次未修改提示词、动态上下文模板或世界书指令；旧战斗、地图、装备与技能不重新编译。
