## 正文与取证方法

历史环境描述由下列机构资料改述；八名单位、局部战场截取范围、开战时点与夺取目标为测试补充，正文中明确区分。没有向模型提供A1–D4答案、目标JSON、期望地图尺寸或程序检查清单。

- 骑士堡：使用十字军时期医院骑士团堡垒的山脊、上堡、中庭、礼拜堂、两重防御与南侧人工壕沟。[UNESCO](https://whc.unesco.org/en/list/1229/)、[Museum With No Frontiers](https://islamicart.museumwnf.org/database_item.php?id=monument%3BISL%3Bsy%3BMon01%3B25%3Ben)。
- 威尼斯：截取圣马可广场、码头及隔水街区，要求体现岛岸、水道与多桥，而非复刻整座城市。[UNESCO](https://whc.unesco.org/en/list/394/)、[意大利文化部](https://unesco.cultura.gov.it/projects/venezia/)。
- 君士坦丁堡：只取西部陆墙段；西面护壕、外墙、夹道、内墙，北南两端可见海岸，城内在东侧。[Columbia University Istanbul Documentation Project](https://mcid.mcah.columbia.edu/istanbul-documentation-project/land-walls-constantinople)、[土耳其文化和旅游部](https://www.ktb.gov.tr/EN-113756/istanbul-city-walls.html)。
- 小城堡选择洛赫兰扎：狭窄半岛上的厅堂式住宅改建为L形塔楼住宅，主要堡体由主楼及小翼部组成，没有大片街区。[Historic Environment Scotland](https://www.historicenvironment.scot/visit/all/lochranza-castle/)。
- 市政厅采用1419年7月30日第一次布拉格掷窗事件；截取人群尚在厅外、准备突入释放囚徒的时点，没有采用1618年布拉格城堡事件，也没有把后世塔楼形制移入1419年。[Prague City Tourism](https://prague.eu/en/objevujte/new-town-hall-novomestska-radnice/)。

## 实际贴合度

### 骑士堡：堡垒骨架有了，形状和关键建筑不足

- 两重防御、夹道、城门、内外部署及实际高差存在。城外随机住宅为0，前面清理旧底图房屋的修复生效。
- 第一份回答的主堡内部容量不足，第二份回答的礼拜堂内部容量不足；第三份回答通过生成，却删掉了礼拜堂，把上堡用工事地点代替。最终没有还原“可进入主堡＋礼拜堂”的完整组合。
- 原文的山脊形、不规则堡体仍被4个中央分区构成的矩形轮廓替代；南侧人工壕沟被画成横贯整图的水沟，周围山脊的约束未还原。
- 因而只能算“能辨认的双墙堡垒”，不能算骑士堡建筑还原合格。

### 威尼斯：水城关系明显不合格

- 圣马可广场、教堂、总督府、码头与步兵陆地部署有实际结果。
- 全图775格只有25格水，占3.2%；实际为一条横贯地图的直水道、一座桥，两边是大片陆地建筑。
- 原文的岛岸、多条水道、多桥连接没有生成。模型还主动补入钟楼等地标，命名建筑放置又使compact场景扩大到25×31。
- 名称正确、地图可用，都不能补偿水城骨架缺失。

### 君士坦丁堡：真实调用时把城墙段围成了封闭方堡

- 西向正面、两重墙与夹道存在，攻方在西、守军在墙内，目标合法。
- `walls=double`被当成闭合围城，最终图是一座封闭长方堡，不是原文的西部陆墙段。重试还把可进入的守军院落改成广场。
- 原文的北侧金角湾、南侧海岸均没有真正生成；只剩纵向护壕。最初脚本“上下两侧都有水格”的条件会把一条贯通地图的水沟误算成两片海，人工审图明确判为失败。

这一项属于最初用户所报“城墙被强制围方形”的范围，已补最小程序修正：双重墙只决定纵深；未明确闭合且城区跨到地图边缘时，沿连续城墙段生成，不自动封闭成盒子。中央明确的闭合双墙堡垒仍保留。

保存的同一组模型回复离线重放后，第一份回答即可生成21×27的开放纵向双墙，保留可进入的守军院落，完成部署、开战与快照恢复。新增API调用0次。原始真实调用25×31、3次布置的记录和图片全部保留；不把离线结果改写成新的真实模型首次成功率。南北海岸仍未还原。

### 洛赫兰扎：地图尺寸小，堡体比例和形制不对

- 9×15的整体地图已在小型档位，水面和西侧陆地接近道路存在，城外没有新增随机住宅。
- 主要问题是堡院占了全图57%，L形住宅被`courtyard`模板改为有大院落和完整外墙的矩形院堡；模型还补入“庭院”。
- 因而“地图没放大”并不等于“小堡大小正确”。这里还需要独立的小型塔楼／厅堂住宅骨架，不能继续靠整座院堡模板缩放。

### 布拉格市政厅：攻守流程成立，建筑仍被院堡化

- 正确选中建筑围攻；攻方在厅外、守方在内，关闭的大门与监牢目标都可用。
- 第一份回答把厅前广场放到建筑围攻模板的院内空间，导致容量失败；第二份改成外部position后才可用。
- 最终仍套用`forecourt`前后院模板，市政厅外围出现闭合院墙和多道内部分隔。原文没有这个独立城防外郭。
- 厅前广场只命名一格，不能把“广场标签存在”当成足够的广场面积。窗户与楼层尚无本次可验证的独立几何，不能声称还原了掷窗的垂直空间。

## 原因与修复边界

1. 当前尺寸已不会一见city分区就把整图至少扩到29×29，但命名建筑的5×5外壳、内部容量与逐级扩大整张地图仍会把少量地标推到567—775格。局部容量不足会全图增长，compact不能保证结果紧凑。
2. 多个city分区可以合并为凹形轮廓；如果模型只给矩形分区阵列，程序并不会从“山脊”“L形”“梯形”等叙述中自动恢复更细的轮廓。
3. `double`将“墙有两重”和“城市四面闭合”混在一起的程序问题已修正并重放；其余四图未因本次重放发生变化。
4. `building_siege`仍从六种院落骨架开始构建。小型塔楼住宅和贴街市政厅都容易被变成独立院堡；这一点是本次新审计确认的结构限制，没有用改提示词掩盖。
5. 重试可能通过删除或降格关键地点来满足生成器，因此“没有走显式回退”也不能证明忠于原文。原始调用全为最终完整采用，但骑士堡已经丢失礼拜堂。
