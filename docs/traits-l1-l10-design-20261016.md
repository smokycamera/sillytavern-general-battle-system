# 特质 L1–L10 扩展：策划与数值评审稿

> 后续规格：见[第二阶段规格](traits-phase2-spec-20261016.md)。新输入默认L1、L为机制规格、旧名称兼容、新版守护统一及第二批阶梯以该文为准。本文保留首轮讨论与候选值，冲突之处已被后续规格覆盖。

日期：2026-10-16。状态：基于当前源码的首版方案，尚未实施、尚未经过战斗仿真。本文的候选数值不能描述成已经验证的平衡结果。

职责：本聊天负责范围、机制、数值与验收；6.1 sol 负责按规格实现、接入、修复和提交验证证据。当前只新增策划文档，不改变战斗规则。

## 1. 结论与范围

建议保留现有五项专精的分级体系，将大部分其他特质接入同一套 L1–L10 系统。采用“数值成长、机制进阶、性质开关”三种处理方式，不统一按等级乘十。

当前 `engine/src/data/traits.ts` 在停用项之前有 49 项可选特质。建议合并四组强弱名称后得到 45 个规范类别，其中 34 类列入分级目标、11 类保留有无。停用项和身体/装备自动派生项不计入此口径。34 类是目标范围，下面明确区分已有实现、可进入首批实现的候选参数、仍需补齐逐级机制的项目。

- L1–L2：初步具备这一专长。
- L3–L4：稳定运用，但未达到旧版完整强度。
- L5：以目前普通版本效果为基准。
- L6–L8：专家水平，增强核心收益或解锁对应技巧。
- L9–L10：顶尖专长，仍保留装备、身体、行动、地形和目标前提。

特质等级表达专长深度，与训练等级、武器规格分别记录。不自动令训练 L10 的单位拥有全部 L10 特质。本次先做效果分级；不顺带增加熟练度、经验、自动升级或新成长货币。

L5 是数值与规则语义的兼容锚点；新规则新增的组合约束或记账方式须单独列出差异，不能承诺新旧规则逐事件完全一致。进行中的旧战斗则必须按原规则继续结算。

## 2. 现有基础与关键问题

已存在：

- `engine/src/trait-levels.ts`：五项专精的 L1–L10、缺省 L5、来源取最高级、累计说明。
- `engine/src/data/traits.ts`：等级解析、校验、规范输出；目前仅允许五项专精。
- 单位、祝福来源、技能和佩戴道具已具有等级传递的部分链路。
- 旧规则通过战斗快照保存版本；五项分级当前依附于 V15 的 `itemModel`。

不能仅扩大 `GRADED_TRAITS`：

1. `bonus.ts`、`recovery.ts`、`afflictions.ts`、`morale.ts`、`observation.ts`、`skill-effects.ts`、移动与阵形代码仍有常数或只判断特质存在的逻辑。
2. `skillTraitReason` 可能因为已有同名特质直接拒绝授予，没有比较等级。其 AI 预估创建的临时来源也未始终带上实际授予等级。
3. `traitStatContributions` 与 `bakedTraitStats` 会影响基础属性。不能在基础值已经包含旧加成时，再把新等级的完整加成加一遍。
4. 步枪类编队会自动获得散兵。扩展等级解析时必须把自动来源计入，默认 L5；本体显式 L1 不应覆盖更强的自动 L5。
5. `items.ts::traitPoints` 对分级特质直接收取 `ceil(L/2)`。若只扩大名单，再生原本 6 点的佩戴成本会在 L5 变成 3 点；这是隐含降价。
6. 通用技能目前会同时用 power 影响授予等级和持续期。等级、持续时间、范围一起上升会放大总收益，不能只检查单目标单轮数值。
7. 伤害预览与 AI 有缓存和不同估值入口，需要确保等级、有效来源、规则版本改变后不会使用旧结果。

### 3.3 暂保留有无：11 类

非生物、天生护甲、不溃、飞行、机械化、航渡、登城、不屈、先锋部署、骑射、抵近射击。

这些特质表达身份、通行资格、特定行动或一次性保命规则。强行分十级容易改变“能不能做”的含义，或者为了填十格添加不相关加成。飞得更快可由速度/机动表达，鳞片更硬由护甲规格表达。以后若确有玩法需求，可分别设计“飞行操控”“骑射专精”等成长，不在这次自动增加。

迁移顺序：先把每一个来源的旧 id 投影为规范 id 与锚点等级，再在有效来源间取最大等级。保留原 sourceId、期限、装备依赖、撤销状态和已消费的限次记录。不能把临时大守护迁成永久守护 L8。

旧版非分级名称后人为写的 L 数字，以前可能被丢弃。已丢失的信息不猜回；历史快照按当时实际记录处理。旧强名称在新规则中默认为对应锚点等级，新输入若要指定其他等级，使用规范名称。

## 5. 数值候选与算法

以下为首轮校准输入，不是最终平衡结论。对原本具有多个组成效果的特质，不能只接表中的主轴就宣称整个特质完成。

破甲实际加值 `min(等级预算, max(0, floor(基础穿透 / 3)))`。当前穿透曲线已经支持小数插值，不需要为此添加新的穿透随机检定。被武器上限限制时，相邻等级可以暂时没有实际增益，界面说明原因。

统率半径先保持小战3格/会战1阵位，现有重整规则沿用。顾及普通个体士气上限和编队基础值，不把这组数字自动乘到整个阵营。

淬毒固定3轮，强度随命中时的有效等级写进状态，之后失去该特质不反向改写已经施加的毒。毒伤倍率接到实际分支与 AI `poisonValue`，攻击降低1的附带效果暂保留；另查技能毒与武器毒的现有去重逻辑。不能只改提示文案或只改 `ActiveCondition.magnitude` 而遗漏旧伤害分支。

再生保留现有编队人数换算和恢复上限，不换成最大生命百分比。小数恢复涉及取整：新规则候选使用可保存的小数余量，仅在存在合法伤口/伤兵时累计，满血、失能、到期或来源切换的处置必须在实现前明确；不得囤积满血治疗用于以后爆发，也不得每个额外行动再生一次。余量方案尚需由实现审计确认适用结算位置。

医护建议将新增规则的伤兵余量统一为固定百分比分母的记账：每次新伤亡按当时有效比例累加，整数部分成为可救伤兵，余量只代表未凑满的一名。等级/来源变化不重算过去伤亡；旧档的余量编码必须按原规则读取，不能直接当成新百分比余量。

### 5.2 插值可以复用，不能代替每项设计

一般连续正收益用三个锚点 `(L1, x1)、(L5, x5)、(L10, x10)` 分段线性插值：

```text
L <= 5: x(L) = x1 + (x5 - x1) * (L - 1) / 4
L >  5: x(L) = x5 + (x10 - x5) * (L - 5) / 5
伤害倍率应插值“额外部分”：1 + bonus(L)
```

有旧强版本锚点的特质使用显式数组，不让插值偏离 L8 旧效果。减伤用有效生命 `EHP = HP / (1 - r)` 检查边际收益：25%减伤约1.333倍EHP，45%约1.818倍；二者在仅考虑此减伤时相差约36.4%，不是只增加20%生存能力。

克制类同时提高命中与伤害，要看 `命中概率 × 命中后伤害`，不能只看表面的×1.5。命中上限、穿透阈值、护盾和实际可造成的生命损失均影响真实收益。

### 5.3 必须另外定逐级表的机制项

以下机制方向已确定，完整 L1–L10 表仍待专项设计与小规模验证，不能交给实现者临时猜常数：

- **恐惧**：L5保留普通恐惧，L8保留恐怖惊退；压力数组已给。攻击惩罚档位、残余压力与抵消关系沿现有心理模型补表，不能仅因 id 合并丢失或重复惊退。
- **工事/拒马/散兵/游击**：多收益加副作用。分别建立命中、防御、减伤、展开或机动的组合表；L5完整对应现状。散兵L1就承担完整近战代价而只有极小减伤可能成为陷阱，需比较同一编队有无散兵。
- **坚韧/身法/工兵**：低级部分抵抗或部分减免，L5拿到原先完整能力，L6–L10增加本领域收益。推拉完全免疫、困难地形完全减免、无视工事必须是明确门槛，不按浮点真假判断。
- **潜伏/侦察**：共同设计一张“潜伏等级×侦察等级×距离”的确定性判定表，优先避免每次查询重掷骰。L5对L5保留旧反隐距离，贴身接敌仍暴露。小战与会战分别写距离档位，不直接四舍五入复制。夜视与墙体仍可缩小实际可见集合。
- **射击专家/冲锋强化/狂暴/近战特化**：命中等整数参数存在档位。d20中的+0.2不能直接声称增加1%命中；不可为凑十级私改全局命中规则。需要时用少量相关条件收益填充阶梯，并检查命中达到上限时仍不会升级退步。狂暴代价不与正收益同比增加。
- **对空**：命中与伤害可沿克制类候选表，另设计逐级减轻地对空射程损耗的门槛，使L5保留原本免损耗。

同一适用场景中应“升级不变弱”。不要求每个等级对所有装备与地图都有收益，但也不接受用多位小数掩盖整级永远无效；参数被取整或上限吞掉时，应补相关机制或调整分组。

## 6. 统一来源与叠加

```text
来源等级 = 显式等级，否则规范普通特质L5 / 旧强名称对应锚点
有效等级 = max(本体, 有效祝福, 有效技能, 当前佩戴品, 自动派生来源)
不存在有效来源时 = 0
```

有来源与“当前动作符合使用前提”是两件事。等级可以存在，但没盾、重装、失能、离开工事等状态仍令相应效果不生效。

- 同一特质取最高级，不相加；旧强弱名称归一后也只算一次。
- 同一效果组按现有取强语义处理，不能全局把所有特质改成取强或全局改成相乘。
- 不同作用组先保留现有组合方式，再做组合校准。若要加新的总减伤上限或增伤软上限，作为独立数值变更记录，不偷改已有结算。
- 较强临时来源结束后重新解析剩余来源，不把原本L3永久写成L8。
- 授予是否有价值需比较“未来持续区间内的有效等级”。本体L3可接受临时L8；剩1轮L8可接受持续3轮L6，因为后两轮仍有收益；同一来源id的重复事件仍不得续期。
- 工事重建属于独立的状态收益，即使等级不提高，也不能被简单的同级去重吞掉。
- 技能授予等级与持续时间分开计算和展示，AI与实际执行调用同一解析入口。当前技能power到特质等级的映射可先沿用，但仍需审计技能成本与范围收益。

## 7. 佩戴成本与临时增益预算

等级不等于统一价格。保留原L5成本作为基准，并为旧强版本保留对应锚点成本。

候选算法：用 `(1,C1)、(5,C5)、(8,C8)、(10,C10)` 分段插值并向上取整；没有L8锚点时跳过。首轮取 `C1=max(1,ceil(C5*.4))`，`C10=max(ceil(C5*1.6),ceil(C8*1.25))`。具体C10仍须校准，算法只是禁止隐含降价的起点。

- 再生：C5=6，不因分级降成3。
- 守护/破甲/恐惧：C5=3、C8=6，对应原大守护/破甲大师/恐怖。
- 原五项地形专精先沿用当前 `ceil(L/2)`，避免同时重做已有体系。
- 其他特质从当前实际预算读取，不按名称猜价格。单位永久特质暂不新增装备预算约束。

旧物品的已编译效果和配方版本需保留。新价格用于新编译/明确更新的物品，不能读档时重算成超预算就拒绝旧装备；合并id也不能绕过原本不能由佩戴品授予的身体类限制。技能“守护”目前已有替换到守护状态的路径，本次不因为特质同名就自动改成授予guardian。

## 8. 工程约束

1. 新增独立的特质分级规则标记，候选 `traitLevelModel: 'traits-levels-v1'`，由新战斗规则冻结并投影到单位。实际命名和下一规则包序号由实现时现有分支决定。
2. 无新标记：五项专精继续按原V15门控，其余特质按旧逻辑；合并旧名称也不能影响旧战斗。
3. 建立一份纯参数定义和一个统一的有效等级/效果解析入口，供实际结算、预览、AI、面板说明与世界书机制说明使用。避免把完整参数表在多个调用点复制。
4. 防止循环依赖：目前 `trait-levels` 依赖 `trait-sources`，后者也需要分级属性时应拆出纯数据与来源归集层，不能互相调用形成递归。
5. 等级变化使用净修正处理已烘焙属性。旧 `genAudit` 无等级时按历史语义解释，不用新默认强度重建基础值。
6. 校验、档案、导入导出、正文spawn/unit_set/bless、技能、道具、自动来源、战斗快照和回写全部接通；展示累计当前效果，并能解释未生效的前提。
7. 没有完成执行器与预览链路的特质，不提前加入可选分级名单。纯参数表完整不等于该特质已完成。
8. 当前工作区已有大量其他未提交改动。实现者先核对当前状态，按文件/代码块明确本次变更，不能还原其他人的修改。

## 9. 校准与验收

先用确定性检查验证边界，再对真正不确定的组合做成对仿真，不把所有等级排列组合穷举一遍。

- 单项扫描：L1–L10参数单调、L5锚点、旧强名称锚点、装备前提与上限。离散档位额外抽查L4/5、L7/8等门槛。
- 三档实战：优先L1/L5/L10；同编成、同地图和同种子对照。有明显偏差再扩到其他等级。
- 覆盖个体/编队、小战/会战、适用/不适用地形、有/无真实防护或身体前提。使用训练和装备的低、中、高档检查是否意外跨越规格差。
- 组合优先：守护+再生+吸血；盾墙+工事+散兵；恐惧+统率+顽固；潜伏+偷袭+侦察；多个克制标签重叠；医护+恢复和多段小额伤亡。
- 指标：预期伤害、真实生命损失、存活轮数、恢复量、行动消耗、伤兵与永久伤亡、胜负/平局、回合长度、AI选技和位置、缓存结果一致性。不能只看胜率。
- 仿真先每个关键场景约40–80对种子发现问题，报告样本量与不确定性；接近阈值或高方差场景再扩样本。相同种子是控制条件，不保证改规则后的随机序列逐次相同。
- 工程必验：本体L3+临时L8到期回L3；撤装备/撤祝福；短高长低来源交替；自动散兵L5；别名去重；保存恢复；相同事件重放；旧规则不受新等级影响；AI/预览/实际结算使用同值。
- 通过条件：无升级反而削弱的非设计行为、无来源或伤兵复制、无旧档漂移、无已知预览差异。平衡指标是校准证据，不预先保证每个特质获得相同胜率提升。

## 10. 工作顺序

P0：6.1 sol 做执行点与数据流清单，搭规则版本和统一解析基础；本聊天审查数值和机制边界。

P1：优先接入参数完整、范围清楚的特质：守护、吸血、偷袭、耐力训练、践踏、盾墙、破甲、克制步兵/大型、顽固、统率。旧强名称按各类接入完成情况分批规范化。现有五项保持。

P2：补齐医护/再生记账、淬毒状态与AI，再做恐惧、工事/拒马/散兵/游击、坚韧/身法/工兵及潜伏/侦察的完整阶梯。整数命中类也在此阶段确定相关副效果。

P3：组合校准、技能和装备成本、面板/正文/说明完整同步；发布前完成旧档与回归验证。

所有阶段共用一个设计表。实现反馈为“当前公式在哪个场景失效、建议改哪一个参数、对L5/旧档的影响”，由本聊天更新设计；避免在UI、AI、伤害三处各自修出不同规则。
