# 2.10.8 世界书绑定与地图显示修复

## 已确认的问题与修复

- 副 API 原本只读取手动勾选的世界书，没有共享主 API 的激活结果。新增绑定模式，在扩展启动时监听宿主真实激活事件，只传当前角色和聊天本轮实际激活的条目。手动选择保留，绑定时不叠加。
- 对照 SillyTavern release 和 TauriTavern main 的 `world-info.js` / `script.js`：两端都在非 dry-run、结果非空时发 `WORLD_INFO_ACTIVATED`，消息含书名、UID 和正文。真实新生成先清空上轮激活结果，空结果不会带上旧绿灯；dry-run 不覆盖结果，TauriTavern agentResume 沿用原结果。切换聊天与编辑历史均使旧结果失效。
- 范围技能有施放者、主目标、副目标多个位置，旧箭头将对象枚举的首项和末项当作起终点，容易指向副目标；数字 ID 还会改变对象枚举顺序。现在按事件记录的参与者或攻击结算 ID 确定施放者和目标，范围副目标继续高亮，飘字按实际受击者位置显示，不读取单位后来的位置。
- 同一行动的 SVG 在状态重绘时会被清掉动画 class，并把实际格心坐标覆盖为初始坐标。现在用行动 key 区分轨迹，同一行动保留播放节点和坐标，新行动替换。
- 手动交接回合原本也执行自动回合前的保存/渲染，再将选择切到下一名单位，导致重复重绘。现在仅在确有自动行动需要推进时执行中间保存，手动交接直接选择新行动者，最后保存/重绘一次。
- 可达高亮与搜索小点共用 `::after`；搜索点的 4px 宽高将整格蓝色高亮压缩。搜索点改为独立元素，整格高亮继续使用伪元素。

## 验证与 review

本次只运行相关定向回归、类型检查与构建核验，不重复全套引擎测试、不调用付费模型。浏览器检查使用实际构建的原生扩展、合成 Tauri 宿主事件和账户接口，检查真实 CSS 尺寸、箭头端点、模式切换和回合交接。它不代表用户的真实 TauriTavern 安装已经实测。

定向回归分批执行，相关 12 个文件、41 个用例均通过：世界书激活/生命周期/设置/请求与主面板 20 项；战术地图/轨迹/原位 DOM/托管控件/反应回合 18 项；战果结算 2 项；内存保存与失败恢复 1 项。只重跑有新改动或失败需要核对的部分。

`node scripts/worldbook-map-smoke.mjs` 的 12 项浏览器检查全部通过，页面异常为 0。检查包括面板打开前捕获蓝灯/绿灯结果、模式来回切换保留勾选、范围技能箭头命中主目标格心、飘字位于实际受击格、同一轨迹跨重绘保留、桌面/390px 搜索格整格高亮、手动交接只保存一次、空激活结果清除旧条目，以及 Tauri `removeListener` 完整清理。结果与截图位于 `artifacts/worldbook-map-review/`。

`npm run typecheck` 与 `npm run build:extension` 通过。安装包按 2.10.8 同步版本并执行 `npm run verify:dist`，校验源码指纹及 82 个打包文件。

已完成最终差异 review，重点检查角色/聊天/分支隔离、旧手动配置迁移、dry-run 与 Tauri agentResume、事件注销、历史位置读取、地图节点复用、自动回合与反应击倒后的结算。review/回归中发现回合优化会跳过自动路径原本补写的结束日志，已改为在统一结束流程幂等补齐，反应击倒与战果结算回归通过；未发现剩余阻塞问题。
