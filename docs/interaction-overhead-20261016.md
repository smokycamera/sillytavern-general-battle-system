# 交互额外开销检查

2026-10-16。在本地已有的点选缓存、除主控托管及终章道具记录修改之上检查交互链路。本轮仅修改面板查询与绘制，没有调整引擎 AI 的搜索范围、候选取舍、抽样或战斗规则。

## 定位与处理

- 会战查看编队时，事件处理和重绘分别调用 `formationSelection`，每次又生成全部任务预览和完整 AI 建议。8 单位带技能场景的诊断中，8 次点选触发 16 次完整建议搜索；32 单位同类场景的建议搜索占绝大部分耗时。现在由面板按战场、编队和任务内容复用只读建议与预览；查看编队在点击内完成，不经过无关的异步物品分发，也不写档。
- 任务、目标和地图机动草案之前在保存前后各重绘一次。现在先显示草案，确认保存后仅更新状态；保存失败或档案切换仍恢复并重绘。仅保存草案时保留没有改变的战场查询，实际下令、技能修改、AI 行动、回合结算、正常事实保存及读档会清空缓存。
- 战术地图反复计算可见格、可达格、路径风险和敌情记忆。它们与此前的菜单查询共用面板状态缓存，行动改变后重新计算。
- 上一行动、地图轨迹、轨迹图层、关键变化等在同次重绘中重复构建公开历史事件；4000 条历史记录场景每次构建五遍。现在只在一次同步绘制范围内共享事件结果，嵌套查询沿用范围，正常和异常退出均释放，不跨异步保存缓存。
- 原位更新仍逐层比较未改变的显示子树，还为战场执行了整页替换专用的详情、焦点和选区扫描。现在相同子树通过原生节点比较后保留；实时表单值仍同步，以保证取消或保存失败后的控件回退。整页替换专用扫描只在其他工作区执行；页面可见性和导航属性只在值改变时写入。

## 浏览器对照

使用修改前保存的本地实际扩展包与本轮实际扩展包，同一引擎、同一固定存档，无头 Chrome、1440×1000、合成酒馆宿主。小战采用 30 单位、13×19 开阔分层地图、骑乘编队，每编队 20 人、每单位 5 个技能；长日志组添加 4000 条观测记录。会战为 8 或 32 个单位、每单位 5 个技能。

统计从点击派发到下一帧后任务的中位耗时。小战预热一轮后测六轮、每轮六次点选；会战先切换两个编队各一次，再测两轮、每轮两次切换。下表的会战结果衡量已经查看过的编队之间反复切换，不能解释为首次查询的耗时。

| 重复交互场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 30 单位小战，正常 CPU | 22.3 ms | 17.3 ms |
| 30 单位小战，4 倍 CPU 降速 | 46.3 ms | 42.1 ms |
| 30 单位小战、4000 条历史，正常 CPU | 48.4 ms | 29.1 ms |
| 30 单位小战、4000 条历史，4 倍 CPU 降速 | 192.8 ms | 80.1 ms |
| 8 单位会战，正常 CPU | 1892.9 ms | 13.2 ms |
| 32 单位会战，正常 CPU | 13280.0 ms | 14.3 ms |

各组点选前后保存的战斗逐字相同；无页面异常，并验证切换后实际选中了目标编队。原始结果为 `.diagnostics/interaction-20261016-before-results.json` 和 `.diagnostics/interaction-20261016-final-results.json`；诊断插桩结果为 `.diagnostics/interaction-20261016-profile-results.json`。这些是本机合成场景，不包含真实宿主保存、网络或手机端到端时间。

## 剩余成本与验证

首次查看一个此前没有缓存的编队，仍需计算一次系统建议。本次冷查询记录：8 单位约 1.15 秒，32 单位约 7.10 秒。因此会战首次查询仍可能明显停顿；这部分是完整同步 AI 搜索，若继续处理，应单独改为后台计算或调整建议展示时机，不能把上述缓存命中耗时用于承诺首次交互响应。

相关测试覆盖缓存与未缓存内容一致、草案切换、实际下令后失效、换战场、异常释放、表单回退、节点与焦点保留、相机滚动、详情开合、战斗托管、技能更换和世界书编辑。类型检查、原生构建及 64 个安装文件与源码的一致性校验通过。
