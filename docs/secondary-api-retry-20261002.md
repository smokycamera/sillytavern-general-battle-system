# 副 API 布置重试反馈与兜底（2026-10-02）

现象：开启“由 LLM 设计地图”后，第2步布置在本地生成失败，重试时反复报同一个地图生成错误。

## 原因

重试确实会把上次的报错带回第2步，但几乎没有作用：

1. **看不到上次的回答。** 第2步请求只有 system、正文和本步任务，上次的布置没有保存也没有回传。正文不变，模型多半写出同样的布置。
2. **只有报错原文，没有改法。** 本地报错是生成器的说法，可能带内部编号（如 `place2`）或英文方位（如 `north_east`），模型无法对应到自己写的哪一项。
3. **记忆容易被清空。** 切换浏览器标签页、最小化、手机锁屏或收起面板都会清空重试记忆，并中断正在等待的准备请求，下次重试什么都不带。
4. 第2步回答不是 JSON 时，报错写作“有效**决策** JSON”，像是第1步出了问题。

## 修改

- **附上上次回答和改法**：第2步失败后，下次的任务文字末尾写明“上次回答”（同一战场类型时）、“失败原因与改法”和更早的失败。报错中的内部编号换成回答里写的名称，方位换成九宫格代号，并按报错类型给出改法，例如：
  - 任务地点没有可站立的空地：objective 改写为空旷的地点或九宫格方位，或省略。
  - 地点放不下：换到更空旷的方位、type 改为 position 或 cover，或删去。
  - 开局位置放不下：双方各写2—3个相邻的空旷方位，删去单独部署。
- **每次开战自动尝试3次**：回答本身出错（本地生成失败、格式或选项无效）时自动再问，状态栏显示“第2次尝试”等；第2步失败时沿用已成功的第1步决策，只重发第2步。网络、超时、HTTP 和 Key 等错误不自动重试，直接报错。3次都失败才提示“已自动尝试3次”，再点开战会再试3次。
- **第6次仍失败时使用回答的有效部分**：同一段正文和设置下第2步连续失败5次后（即第二次开战的最后一次尝试），第6次若仍失败，本地逐项去掉落实不了的部分再生成：先去掉报错点名的地点或报错指向的项，否则按单独部署、任务地点、地点、桥、门、水系、开局位置、城市、场所风格的顺序。去掉的每一项和“连续6次布置未能生成地图，只采用回答中能生成的部分”都列在地图上方“查看布局依据”里。回答完全读不出来时只按第1步决策生成；全部去掉仍失败时改用本地生成的地图，第1步的决策照常生效。
- **隐藏页面不再清空记忆**：页面隐藏或收起面板只暂停自动战斗，已开始的准备请求照常完成，重试记忆保留。5分钟过期、取消读取、保存副 API 设置、正文或名单变化时照旧清空。
- 第2步的格式报错改为“模型未返回有效布置 JSON”。

## 验证

### 实测（DeepSeek-V4.1-Flash，`deepseek-flash`）

本地脚本按真实流程调用两步请求，本地生成照常执行。前三个场景在生成成功后再注入固定的本地失败，用来模拟生成器缺陷；回答改掉相关项后才能通过。

| 场景 | 修改前（只带报错原文） | 修改后 |
| --- | --- | --- |
| 攻城，目标为府衙（注入“正文任务地点没有合法目标格”） | 前4次仍写 objective 府衙，第5次才通过 | 3轮都在第2次通过：改为“府衙前广场” |
| 坡顶烽火台（注入“地标烽火台在指定区域部署容量不足”） | 6次都写 tower 烽火台，只换方位，全部失败 | 3轮分别在第2、2、3次通过：type 改为 position |
| 回答无法修正的本地故障（注入“结构数据损坏”） | — | 前5次报错，第6次按有效部分开战 |
| 护送进驿站、隔河石桥、室内书房，各2轮 | 全部首次通过 | 全部首次通过 |

改为每次开战自动尝试3次后再测一轮：攻城目标和烽火台都在第一次开战内通过（1次决策加2次布置，界面不出现报错）；无法修正的故障第一次开战报“已自动尝试3次”，第二次开战的最后一次按有效部分开战。

三个真实场景没有触发本地失败，所以没能复现用户遇到的那条具体报错。第1步决策单次6—100秒，所以同一次开战内的自动重试只重发第2步。

### 测试

- 新增：报错翻译与改法、逐项去掉的顺序、同一次开战内只重发第2步、3次后停止且网络错误不重试、第二次开战的第6次按有效部分生成、全部失败时改用本地地图、读不出的回答只按决策生成。
- 集成测试：第一次开战3次都失败后先收起面板再开战，第2步仍带回上次的失败；把隐藏处理改回旧写法时这项测试失败。
- 全量测试1757项中1750项通过，失败的7项是 `check-layered-test-baseline` 记录的已知基线；TypeScript 检查通过。
- 浏览器预览：本地构建候选包并替换宿主模型后端，第2步固定返回非 JSON。第一次开战时状态栏显示“正在布置地图（2/2，第2次尝试）”，第1步只请求1次、第2步3次，随后提示“已自动尝试3次”；第二次开战的第6次开战成功，“查看布局依据”列出两条说明，控制台没有错误。逐次手动重试时，收起再打开面板后的重试仍带回失败原因。

## 代码入口

- 自动尝试（`AUTO_TRIES`）、重试记忆、失败计数与第6次兜底（`LAYOUT_TRIES`）：`panel/src/llm-context.ts`。
- 重试文字、报错翻译与改法、逐项去掉：`panel/src/llm-layout.ts` 的 `layoutTask`、`layoutRetryNote`、`reduceLayout`。
- 页面隐藏只暂停自动战斗：`panel/src/main.ts` 的 `pauseAutomation`。
