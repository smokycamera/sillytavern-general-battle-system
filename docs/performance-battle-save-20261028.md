# 3.0.24 战斗与高楼层存读档性能

基线：正式版 3.0.23，`d7ebb30ec5d2ea62cc06687d20f450a3c2aad17d`。候选：3.0.24。2026-10-28 在同一台机器、Node v24.16.0 下将 TypeScript 打包为 Node ESM 后串行测量，避免 vite-node 热循环开销。以下是本机诊断数据，未测用户真实酒馆的端到端时间。

## 战斗

每名单位为 20 人编队、8 项技能，混合弓与长兵器；32 单位为三方，道具场景额外携带 4 种道具。使用当前 V39 规则、13×19 开阔地图，测一次单位 AI 决策，包含选位与技能/道具估值。每场景 3 个固定种子，表中取耗时中位数。

|场景|3.0.23|3.0.24|耗时减少|
|---|---:|---:|---:|
|4 单位，驻守意图，技能选择|1.446 秒|0.853 秒|41.0%|
|8 单位，自动选位与技能选择|8.916 秒|5.579 秒|37.4%|
|32 单位三方，驻守意图，技能与道具选择|24.328 秒|17.383 秒|28.5%|

9 对完整战斗快照 SHA-256 全部一致，包括战报、资源、伤损、行动与随机状态。前两种场景每次仍有 201、847 组独立伤损预览；32 单位场景由 4347 组减至 4301 组，减少的是重复查询，每组仍完整模拟原有 96 个种子。

实现要点：

- 只在已有的同步只读 AI 决策范围内复用完整预览，包括命中、伤损及解释文字。键保留完整单位、位置、资源、规则、表内容与攻击选项，结果独立复制；最多 4096 项、8 Mi 字符预算，单键超过 16 Ki 字符不缓存，决策结束释放。普通可编辑预览不启用这项复用。
- 同一组 96 种子复用私有单位外壳，逐种子恢复生命、状态、士气、伤兵/余量与全部可变分支，不再逐次展开整份技能、装备与生成资料。实际伤害仍走共用结算入口，随机数顺序不变。
- 合法且已经严格排序、合并的成员生命组继续验证，但省去重复规范化复制；没有佩戴装备时直接返回同样的空修正结果。

## 存读档

使用约 3.10 MB（3,100,442 字节）的合成档案，包含当前战斗和 30 份独立历史快照。模拟 100、1000、5000 楼聊天；每条正文 2000 个中文字符。各项运行 5 次，取中位数。

`NativeStore.load/commit` 使用内存模拟的 Tauri 元数据接口和恢复记录，测扩展的校验、复制、恢复记录及读写调用成本。没有将实际磁盘或网络时间混入数字。

|楼层|读档：原版 → 候选|减少|提交存档：原版 → 候选|减少|
|---|---:|---:|---:|---:|
|100|269.8 → 198.3 ms|26.5%|979.9 → 798.6 ms|18.5%|
|1000|244.6 → 193.6 ms|20.9%|966.7 → 770.5 ms|20.3%|
|5000|237.5 → 202.2 ms|14.9%|1025.2 → 834.0 ms|18.7%|

不同楼层使用同一大小的战阵档案，因此元数据接口的读档时间本来就不应随聊天正文长度线性增加；表中的波动不是楼层越高越快。3 对最终档案哈希全部一致，保存调用次数不变。

另外测量兼容 HTTP 路径的流式文件头解析，以及批量绑定 100 条来源消息：

|楼层|完整聊天字节数|文件头解析：原版 → 候选|100 条绑定：原版 → 候选|
|---|---:|---:|---:|
|100|3,714,006|66.2 → 64.3 ms|2.75 → 1.67 ms|
|1000|9,159,906|48.1 → 47.0 ms|4.00 → 1.32 ms|
|5000|33,367,906|99.5 → 45.0 ms|11.55 → 2.07 ms|

流式读取在前后均消费 3,145,728 字节后取消正文；没有进一步削减网络或后端读取字节。100、1000 楼文件头解析收益很小，5000 楼样本波动也较大，不能将这一行的降幅当成普遍保证。批量绑定则从逐标记全量扫描改为一次建立匹配表。

实现要点：

- 持久档案保留时使用已有的、保留引用关系和特殊键的数据复制器；仅作保存前后核验的读回结果省去整份额外副本。写入回调的结果仍先独立复制，宿主元数据、对外快照、延后快照及加载结果互相隔离。
- 没有缓存磁盘核验结论。保存前后仍独立读回、检查代次/修订/操作身份并计算原格式的 SHA-256。失败恢复、来源核验及其他扩展元数据继续沿用原契约。
- 文件头解析通过原生字节搜索跳过长字符串，处理跨块 UTF-8、奇偶反斜杠及转义引号，仍在完整解析和分隔符检查后返回。
- 来源绑定按整批建立索引后再验证和写入，保留已移动消息定位、重复身份拒绝和失败时整批不应用。

宿主本身仍通过原来的保存接口落盘。整段聊天保存、消息来源完整读回的兼容回退、宿主磁盘与网络开销仍可能随聊天长度增长。本次没有引入侧车存档、迁移存储位置或改变存档格式。

## 兼容性与验证

战斗规则仍为 V39，旧战斗保留保存的规则。没有重编译冻结技能、道具或历史快照，也没有修改提示词、动态上下文模板或世界书指令。

类型检查通过。宿主、运行时及相关战斗测试 31 个文件、293 项通过，随后新增的 2 项 V39 分层屏障/能量盾/伤兵/不屈逐种子对照单独通过，共 295 项。检查覆盖存读档回放到战斗结束、每项 96 种子统计对照、完整预览结果隔离、聊天切换、吞掉保存错误、半份存档恢复、外部更新冲突、MVU 共用保存、损坏档案拒绝，以及新的跨块文件头和批量来源绑定。没有扩大已知失败名单。

安装产物按仓库标准通过 `npm run build:extension` 生成，使用 `npm run verify:dist` 核对版本、源码指纹与文件哈希。浏览器检查使用现有 `npm run smoke:extension`，模拟宿主的元数据保存和完整保存契约；它不代表用户实际运行的酒馆。

## 复现

```powershell
$env:BENCH_CASE='4-hold-skills,8-auto-skills,32-hold-items'
$env:BENCH_TRIALS='3'
$env:BENCH_DIR='artifacts/performance-20261028/reproduce-ai'
node scripts/run-benchmark-ai-skills.mjs d7ebb30

$env:BENCH_DIR='artifacts/performance-20261028/reproduce-save'
node scripts/run-benchmark-save.mjs d7ebb30
```

原始最终记录保存在本地 `artifacts/performance-20261028/final-ai/{before,after}.json` 与 `artifacts/performance-20261028/final-save/{before,after}.json`。测量与校验脚本不读取用户存档、不请求模型服务，也不把耗时设为 CI 断言。候选在本地实现和验证；本记录不代表已推送或晋级 `test/main`。
