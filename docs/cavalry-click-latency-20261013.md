# 骑兵回合按钮与地块点击延迟

2026-10-13。性能与世界书实现提交 `5fd0516a0f6f0a77273fbe05d2b20da72da9421e` 已发布至 `test`，基于远端 `10378c8`。

## 原因与修复

手动点选会重新生成全部操作菜单，其中包括冲锋目标。旧版针对每个目标的多个相邻落点分别寻路，校验和伤害预览又重复查询同一路线；每次搜索的扩展还反复计算阵营观测。骑兵的移动预算更大，因此点击普通攻击、守备或空地也会付出冲锋查询成本。

现在一次同步点选到重绘期间复用观测、按行动单位和移动预算区分的有界 Dijkstra 结果，以及伤害预览的只读参数。普通移动、菜单合法性判断、移动高亮和冲锋落点查询可以共用搜索结果。普通移动与不含加速的冲锋预算分别缓存。嵌套查询保留调用者的缓存，正常或异常退出都释放本次缓存；执行动作和异步保存不处于该范围内。

保留最短路径与平局顺序，在得到最短路线后仍按原规则检查冲锋地形。普通模式重绘时不再准备不会显示的起落风险文字。伤害规则、抽样次数、随机数与存档格式未调整。

## 浏览器对照

改前使用远端 `10378c8` 的实际可安装 `dist/`；改后使用 `5fd0516` 对应的原生扩展包。无头 Chrome、本机 HTTP 合成酒馆宿主，13×19 开阔分层地图，8 或 30 个单位，双方全部骑乘，每队20人、4级长矛与轻甲、无技能。操作依次为切换移动、点选空地、切换攻击、点选敌军、切换守备、切换攻击；先热身两轮，再测8轮，每组48次点击。计时从派发点击到下一帧之后的任务，统计中位数；4倍 CPU 降速是浏览器模拟条件。

| 场景 | 改前 | 改后 | 降低 |
| --- | ---: | ---: | ---: |
| 8单位骑兵，正常CPU | 53.3 ms | 22.9 ms | 57% |
| 8单位骑兵，4倍CPU降速 | 305.3 ms | 109.3 ms | 64% |
| 30单位骑兵，正常CPU | 634.3 ms | 28.1 ms | 96% |

各组点击前后的已保存战斗逐字一致，浏览器没有页面异常。这是普通点选和模式切换的测量，不包含实际执行攻击后 AI 推进与存档的耗时。原始结果：`.diagnostics/tactical-browser-published-before.json`、`.diagnostics/tactical-browser-published-after.json`；本地测量脚本：`artifacts/tactical-clicks/browser.mjs`。
