# 开局与终局保存

2026-10-16。

## 行为

- 开战时保存开局检查点。手动攻击、移动、结束行动、AI 连续行动、跨轮推进、军令草案与战中技能调整只更新当前会话，不写酒馆存档、恢复日志或存档散列。
- 战斗结束、结算和收兵时保存累计结果。物品消耗、战损、经验与战报沿用原校验和入账入口，不逐步落盘。
- 重新载入页面或重新读取档案后，从保存的开局恢复。切换聊天不沿用上一聊天的会话进度。
- 玩家界面仅显示“开局已保存”或“保存中…”。删除重复的托管长说明，缩短任务与射程说明。

## 实现

原生服务以独立会话候选承接战中更新；持久化存储的 envelope、revision 与 payloadHash 保持在开局。界面查询和生成前的上下文投影读取最新会话候选。结束时将完整候选按原来的持久化校验、恢复日志、写入及读回流程提交。

会话候选仍校验事实版本、库存和物品消耗。连续两次使用物品按每步差额更新内存，结束时写入累计余量，避免再次扣减。聊天、存档代次或持久化头改变后，旧候选失效；宿主替换同一聊天且仍持有相同存档头的 metadata 对象时，保留当前会话。

旧面板控制器采用同样的内存接受与开局/终局写入规则。内存接受通过 receipt.memoryOnly 标记，不宣称已写入浏览器或宿主。

AI 激活与会战整轮结算使用独立 Worker 计算候选，应用前检查聊天、存档版本、战斗对象、轮次及行动者。保留既有候选、96 次伤害抽样、随机状态、召唤和战报；Worker 不可用时沿用同步路径。

## 验证

覆盖小战和会战控制、手动与连续 AI、反应失能、战中技能调整、MCP 动作、物品累计消耗、终局写入失败、切聊天时的过期后台结果、重读开局与同聊天 metadata 替换。单独验证旧面板控制器的开局/终局保存。

浏览器诊断使用实际原生构建、本机 Chrome 和模拟酒馆宿主；诊断脚本为本地 `.diagnostics/execution-response-browser.mjs`。记录点击到更新、操作完成时间、宿主保存调用数和持久化 metadata 是否改变。它不代表用户实际聊天的网络或服务端耗时。

每场景独立打开页面测量三次，下表为中位数。AI 组保留完整计算，页面等待期间可继续绘制。所有场景的宿主保存调用均为 0，持久化 metadata 逐字不变；战斗快照与逐步保存基线逐字相同。

| 场景 | 点击至操作完成 | 最长主线程任务 |
| --- | ---: | ---: |
| 8 单位手动攻击 | 131 ms | 89 ms |
| 30 单位、4000 条历史手动攻击 | 222 ms | 174 ms |
| 8 单位 AI 激活 | 2373 ms | 153 ms |
| 8 单位会战整轮 | 3148 ms | 179 ms |

原始结果：本地 `.diagnostics/opening-save-response-20261016.json`。这组将“整轮计算时间”与“主线程连续阻塞时间”分开记录，后台计算不等于无需等待结果。
