# 战阵技能与装备机制覆盖调研

日期：2026-09-26。代码基线：`smokycamera/tavern-battle@85bb90e`，0.2.0-rc.13。

下文缺口矩阵保留本次改动前的代码审计结果。用户随后批准了界面和第一批机制修改；实际完成范围见下节。未实现的后续建议不计入已完成功能。

## 用户批准后的实际完成范围

- 控制：明确提供眩晕、定身、沉默、缴械、惊惧、减速、击退、拉拽。原引擎已有相应状态，本次补上直观入口、中文简写和回归检查；目标可抵抗，净化可解除不利状态。天生武器不受缴械影响。
- 消耗品：治疗、回能、净化、强攻、屏障、投掷炸弹、车辆维修；按实际使用扣除库存，维修不能用于普通人形单位。
- 配件：两个通用配件栏，支持被动特质和有限次数的主动能力。夜视镜、护符、林行靴等使用相同配件栏，不增加头、手、脚等细分栏位；卸下会取消对应能力。
- 屏障：有限的伤害吸收量，在防护减伤之后消耗；不增加生命或人数上限。重复施放取较强保护，连续攻击共用剩余强度，剩余时间和强度随战斗保存。
- 范围：扇形、直线、环形、连锁，单次最多选择三支符合条件的单位；仍遵守有效目标、距离和观察限制。
- 持续区域：燃烧、毒雾、烟幕、治疗区域和一次触发的陷阱。可选择空地或阵位；每个区域对每个单位每轮至多生效一次，读档不重置当轮触发记录。火焰和毒雾也会伤害友军；空中单位不受这些地面区域影响。
- 武器只新增投掷冷兵器、单发重步枪、天生武器三类。撤回其他细分方案，保留原有大类，接受常见近义名称。
- 正文接口没有增加必填字段。仍填写既有的名称、类型与等级；范围、消耗、持续时间和抵抗由插件计算。

临时掩体、可破坏炮塔、陷阱拆除、任意反应技能、通用吸血、复活和控制权转移仍属后续扩展，没有作为本次已实现内容。多次攻击遇到屏障时的伤害预览使用固定样本估计；实际战斗逐次计算并保存结果。

## 改动前的调研结论

现有插件已覆盖许多常见攻防效果，优先补齐“效果怎么发动、选择谁、何时结束、通过什么物品携带”，比堆叠更多技能名更有价值。目标应是用有限、可组合的机制覆盖主要战斗情境；不能承诺一个固定目录涵盖任何世界观中的所有能力。

最值得先补的是非治疗消耗品、饰品/工具及装备授予能力、可消耗屏障、精确范围形状与持续区域。反应技、位移、信息控制、特殊弹药随后补齐；复活、变形、控制权转移最后处理。

## 对照的规则与启发

以下外部规则只用作机制比较，落地建议是结合本插件后的设计判断，并非建议照搬对方数值。

- D&D 2024 区分反应、专注、临时生命、范围形状、传送和复活。这说明行动时机、维持条件和独立状态应有明确模型。[官方规则术语](https://www.dndbeyond.com/sources/dnd/br-2024/rules-glossary)
- D&D 的装备与魔法物品分别提供弹药、投掷用品、药剂、卷轴、法杖、戒指和奇物等承载方式。对于战阵，重点是统一“物品提供什么动作/被动效果”。[官方装备规则](https://www.dndbeyond.com/sources/dnd/br-2024/equipment)、[官方魔法物品规则](https://www.dndbeyond.com/sources/dnd/br-2024/magic-items)
- XCOM 2 将装填、警戒、黑入以及职业能力放进战术行动体系。手册中的警戒和黑入提供了时机与控制权这两个维度；本插件已有部分警戒能力，应扩展而非另做一套。[官方移植商手册](https://www.feralinteractive.com/en/manuals/xcom2/latest/steam/)
- Wesnoth 的开发文档把邻接能力、武器吸血、命中治疗、先制和击杀转化分别定义。这可用于检查“效果作用于攻击者还是受击者”和触发条件。[官方能力定义文档](https://wiki.wesnoth.org/AbilitiesWML)

优先级表示实施顺序：P1 为第一批基础覆盖；P2 为依赖基础能力的扩展；P3 为需要特殊世界观/战役规则的能力。

| 通用触发与反应技 | 借机、警戒和部分命中附状态已有专用逻辑 | 格挡反击、友军遇袭援护、打断施法、受击反伤、击杀追击 | 触发事件+反应预算+适用条件；复用既有反应额度，明确先后顺序和递归上限 | P2 |

| 施法过程与维持 | 有SP消耗、冷却、每战次数 | 蓄力两回合、引导射线、持续专注、打断后返还部分资源 | 待执行状态、结算时点、中断条件、维持费用；读档后不得重新施法或再次扣费 | P2 |
| 主动机动 | 有移动、冲锋、飞行和单步推拉；推拉碰撞明确不产生伤害 | 闪现、换位、跃迁救援、连续冲刺、拖拽俘虏、击退撞墙 | 合法目的地规则及可选路径规则，明确借机、空地层、占位、携带对象和碰撞伤害 | P2 |
| 感知与目标选择控制 | 已有观测、潜伏、夜视和失准；没有通用致盲/标记/诱饵投送体系 | 失明导致不能指定可见目标、照明弹揭露、侦察标记、幻象诱饵、嘲讽 | 状态影响合法目标列表和AI选择；不能仅把“失明”翻译为命中−2；嘲讽必须在手动与自动行动中一致 | P2 |
| 元素、抗性、免疫和易伤 | 三伤害通道、部分特定免疫已有 | 火抗不抗冰、电击机械、亡灵受神圣克制、酸腐蚀装备 | 保留三通道用于装甲计算，另加元素/生物标签与抗性过滤；不要只增名称而不规定交互 | P2 |
| 复活、复苏与补员 | 治疗/濒死恢复、伤兵账本已有；尸体苏生蓝图禁用 | 战斗复活、复活次数、复活消耗尸体、永久伤亡与真实补员 | 用独立复活动作与身份/尸体账本；区分救伤兵、招募补员和死者复生；不能通过普通治疗增兵 | P3 |
| 魅惑、控制、变形 | 恐惧/眩晕/沉默已有，但不改变单位控制权或实体形态 | 黑入载具、临时策反、变羊、变身、附身、放逐 | 保存原控制方/形态、有效权限与恢复条件；计分、AI、装备合法性、退出战斗和读档都要同步 | P3 |

补充判断：特定装备/技能可以用多个效果组合模拟，但组合必须支持不同接收者和触发时机。单纯把 `damage + heal` 写在同一个效果数组里，不能自动视为吸血实现。[Wesnoth 吸血/命中治疗定义](https://wiki.wesnoth.org/AbilitiesWML)

## 怎样判断一种新机制已真正覆盖

每个机制至少回答下面八个维度，并在小战、会战分别建立例子：

1. **来源与拥有者**：已学技能、装备、消耗品、环境、召唤物；来源被卸下/移除后如何处理。
2. **目标**：自身、友军、敌军、空地、物体、濒死、尸体；隐藏目标是否允许。
3. **空间**：射程、形状、障碍、空地层、占位/容量、友伤、单人和多人编队。
4. **时机**：主行动、移动、反应、回合起止、进入区域、命中、实际受伤、击杀。
5. **费用**：SP、生命、物品数量、充能、弹药、冷却、每战次数；失败/被打断是否退还。
6. **冲突**：免疫、抵抗、同源/异源叠加、取强、覆盖、驱散、中断、永久与临时效果。
7. **持续与持久化**：来源死亡、目标死亡、跨战斗、存档读回、聊天切换、召唤物退出；不得重放扣费或重掷结果。
8. **可解释与自动决策**：预览命中/合法性、说明无效原因、AI估值、战报记录和叙事协议能否表达相同事实。

代表性验收场景：屏障被两段攻击耗尽；治疗不能复活但复活动作可按规则执行；烟幕改变可见目标；换下护符撤销技能；战中读档保留剩余弹药；吸血遇到未穿透目标回复0；火墙同一移动不重复无限触发；控制载具结束后归还原控制者；范围技能对英雄/编队/空中单位按同一份定义解释。

## 建议实施顺序

1. **第一批：扩展现有框架。** 非治疗消耗品、配件来源与装备授予能力、屏障池、效果接收者；建立向后兼容的数据版本和协议。
2. **第二批：扩大空间和时机。** 精确范围、持续区域、通用反应、光环、主动位移、信息控制、特殊弹药及部署设备。
3. **第三批：扩展战役规则。** 复活、控制/变形、模块化载具、装备耐久与修理；根据实际世界观选择。

每批都同时接通生成/编辑、合法动作列表、两种战斗模式、AI、预览、战报与读档。只增加下拉选项或技能名称，不算完成。

本次仅提交 UI 功能调整与调研。上述战斗规则、技能类型和美观策略均未实现。
