# 审查修复与副 API 准备调整

范围为用户提供的《通用战斗系统：问题与修改建议》大章节一到五（条目1–22），以及29、30、31、34。文档作为问题线索；修改以当前实现与复现结果为依据。

## 副 API

- 同一次模型请求保留场景、任务、双方指挥与可选VIP选择。
- 地图提示词改为简短字段约束。所有设施放在同一份实体列表，总计12项，不再要求同时维护多个重复列表。场所原型、路网、形状、高差、名称与空间关系仍可选择。
- 未指定的地标默认为局部尺寸；可省略版本标记、空关系、空数量约束及推断项的空引用。明确事实仍需有效来源引用。
- 超过5个叙事地标不再因旧地标上限被拒绝。布局生成按实际部署、地标数量及尺寸需求扩大；保留正文水体、设施状态和明确关系。
- 模型结果先经过实际地图、目标和部署校验；只在全部成功后进入开战。生成过的地图直接用于本次战斗。
- 再次点击时携带当前准备请求最近4条去重错误，每条最多280字符。仅在内存保存请求哈希和错误短句，5分钟失效；成功或明确取消即清除，聊天、配置或准备内容变化后不复用。
- 不保存完整提示词或失败回答，不因该功能自动循环请求模型。45秒独立截止时间释放操作锁，迟到回答无效。

## 对照记录

| 条目 | 本轮处理 |
| --- | --- |
| 1 | 编辑、规则转换及战果保存失败后使用权威档案恢复，不再回填旧名册；预览绑定上下文和事实版本，异步保存回执复核会话。 |
| 2 | 消息保存后的验证同时检查稳定ID和内容指纹；Helper批准重新读来源，编辑、换页、删除使旧提案失效。 |
| 3 | 兼容文件导入重新绑定稳定来源，同聊天校验导出时的来源指纹；跨聊天暂停自动批准并隔离旧索引。仅有索引、无可核对正文的文件拒绝自动绑定。 |
| 4 | 迟到生成回执不再写入已切换的聊天；原生会话增加分支变化检测，Helper镜像使用账号、角色、聊天、分支完整键，归属不明的旧镜像不自动载入。 |
| 5 | 首行动者与后续行动者共用开始回合流程；全部开场眩晕时可推进下一轮。技能菜单及执行检查失能，拒绝时不扣资源。 |
| 6 | 使用次数与共享冷却拆开；机制身份防止改名刷新次数。旧共享账本缺少历史归属时保守继承已用次数，消耗品维持原有实物账本；AI资源预测沿用相同账本。 |
| 7 | 保留高/低骰共用解析与均值语义；小分布精确计算，超预算的伤害预览使用有界模拟，不返回伪零值。 |
| 8 | 溃退单位照常经过持续伤害和时长衰减；本次行动中进入溃退也结算回合末效果。 |
| 9 | 非库存管理的旧单位字段编辑不再强制切换为库存管理并清空装备。 |
| 10 | 协议装备重编译携带伤害模型、冻结随机值及无随机标记。 |
| 11 | 替换学习技能保留物品和装备提供的能力；准备上限仍只处理学习技能。 |
| 12 | 更新接口拒绝正生命濒死等矛盾组合；同批互补字段合并后校验；改阵营清理我方主控/指挥引用，自动回合停留要求我方身份。 |
| 13 | 射程校准计入配方的正负修正与合法下限。 |
| 14 | 小战在副本上评估整条路径的借机和警戒，按剩余状态评估行动，冲锋与普通移动攻击使用一致的到达风险系数；会战移动射击计入脱离减员、阵亡与士气风险。 |
| 15 | 守城射手搜索墙顶射位及通往射位的登墙入口；公开占领进度出现敌方推进时优先回防目标。 |
| 16 | 落点计入残余火力风险，固守仍保留有限队友掩护收益；会战未来火力按目标剩余生命封顶。 |
| 17 | 共享搜索记录增加队伍分区，显示近3轮已排查地格。保留战争迷雾；未新增独立静默快进模式。 |
| 18 | 普通控制任务保留叙事指定的进攻阵营；中立控制不默认计为我方。 |
| 19 | 沼泽装饰不再覆盖深浅水，保留零桥深水边界。 |
| 20 | 旧门位放置支持绝对方位；毁坏状态传递至实际结构与瓦砾，并检查生成结果。 |
| 21 | 局部地标、尺寸预算及野外建筑放置减少容量失败；无水语义统一。仍限制一城一主河，未扩展多聚落、弯河或支流。 |
| 22 | 无指定归属的中立据点按双方实际部署和相同步兵移动成本选址，减少单侧提前占领。 |
| 29 | 多组、多发在独立目标副本上顺序预测伤势、减员、屏障和耗尽；缓存键包含伤损分布，不消耗实战随机源。 |
| 30 | 主概率明确为“至少命中一次”，详情列出判定组数、每组概率、条件/无条件均伤。连发返回整次行动汇总。 |
| 31 | 损坏的可选模型配置不阻断手动开战；增加原配置备份、保留连接重置和明确清空入口；模型请求截止时间不依赖传输取消。 |
| 34 | 主要行动按钮位于稳定操作区，提供全自动开关；起飞、降落和撤离先预览后确认。既有攻击、技能与移动预览继续使用实时资格检查。 |

## 验证范围

采用相关单元、宿主及界面集成测试，覆盖来源保存中变化、兼容导入重扫、编辑冲突后的后续保存、副API实际点击重试、超时锁释放、配置损坏后的手动开战、技能次数、开场失能、累计伤损、地图事实与AI基本进攻行为。运行TypeScript检查并生成原生扩展候选包；未执行全量审计或真实收费模型压测。

Flash一次成功率仍需在用户实际服务商、模型版本和正文上观察，本轮不提供未经实测的成功率数字。

提交到test时另由Test channel CI执行仓库规定的完整测试、宿主回归与打包检查，既有失败按仓库已记录基线核对。针对首次CI指出的技能账本断言、镜像键和冲锋行为，修复后的9个相关测试文件共109项通过，TypeScript检查通过；未扩大已知失败基线。
