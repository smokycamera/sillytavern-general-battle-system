# 技能选择、正负强化与连续通道防护

本次修改基于主分支 `86d719dc4931a77d99ddd0ee19638d81c0eaefb2`，承接 [PR #17 的2,800场审计](https://github.com/smokycamera/sillytavern-general-battle-system/pull/17)。之前的数据只作为基线；本目录的新实战数另行统计。

## 生效规则

|项目|当前规则|
|---|---|
|单项修正|整数 −10…+10，0表示无修正；相同方向不可重复。负修正不兑换额外正修正额度。|
|伤害、治疗、等效耐久强度|每点5%；同一来源的通用、强度与匹配通道合计倍率限制在0.5…2。不同实物/单位/技能仍依照原伤害管线结合。|
|穿透、防护|每点0.2档，通用与匹配通道合计限制在±2档；护甲与盾的防护修正共同受此上限约束。|
|精度、防御等离散项|保留原步长，负方向对称：默认每3点一档，非零余数向外取整；射程与持续每5点一档。|
|通道词条|动能/热能/奥术伤害、穿透、防护。只作用于匹配通道，不新增伤害段，不自动改变其他通道。|
|防护侧重|仍在现有通道之间转移预算；它与单通道词条是两种配置。|
|防护与强度|防护仅改变抗穿；强度改变等效耐久。移除“防护词条同时提高耐久倍率”的双重收益。|
|边界|防护不低于身体固有值，穿透不低于0，生命/技能持续不低于1，射程不低于最小射程。硬控制的正持续词条不延长失能，负持续可缩短至至少一次结算。|

穿透差值在 `−3→0、−2→12%、−1→30%、0→55%、+1→100%` 之间线性插值，两端截断。因此穿透2对防护1.5的通过系数为77.5%；1.5防护既可保存，也参与预览和实际伤害。通过系数还需与命中、强度、护甲耐久等共同结算，不是最终生命损失比例。

写法示例：

```text
步枪L5+3伤害-2精度+5热能穿透
重甲L5+5热能防护-3奥术防护
魔法单体热能L4-3伤害+1穿透
```

枪械的热能词条须在实际攻击为热能时才生效。手工指定的最终 `protectionOverride` / `powerModel` 数值继续按原有自定义规则优先，不把配方强化再次乘入手工数值。

这是有意调整正强化，而非仅放开负号：原先+1穿透/防护就跳一整档，现在为+0.2；+10仍为+2。原先正防护还提供额外耐久倍率，此次去除；旧装备保留词条与身份，结算使用新规则。

## 技能选择变化

旧默认AI用约2—5分评价控制，同时用真实生命伤害评价武器攻击，规模、装备和等级提高后，两者失去可比性。现在V4以一个可兑现行动的生命收益作为共同尺度：

- 眩晕比较失去的行动；缴械和沉默比较受限后的合法替代攻击或治疗，保留天生武器、普通法杖、副武器等实际选项。
- 定身与状态增减通过移动后可及目标、实际命中/伤害变化估值。小队估计可移动后行动；会战移动另占军令，不假定所有编队都能免费移动并攻击。
- 同一技能的复合控制一起评估成功组合，避免眩晕、缴械、沉默三次计算同一个被阻止的行动。命中后/损伤后门槛分别沿用对应预览概率，预计致命伤害会降低追加控制收益。
- 净化比较解除前后能恢复的行动与防御；屏障的价值受可预见来袭伤害限制；回能额外考虑是否解锁真正可用的伤害/治疗技能。原扣费、准备、冷却、次数限制继续生效。
- 惊惧沿用士气风险和“不溃”免疫。估值仅使用调用方已观测的单位，不读取敌方尚未执行的军令，不消费随机数。

估值是有界启发式：小队保留原位及最多三个接近敌方的合法落点；最多保留16种控制成功组合，第二次状态结算价值折半。它不保证多回合最优；复杂区域、推拉、目标占领、持续伤害和队友协同仍有进一步建模空间。此次没有把射程、技能费用或控制时长统一抬高来强制提高施法率。

## 兼容与交付

配方技能升级到 `skill-v4.3`。旧技能从原配方重建一次，保留实例ID、准备项、剩余冷却、已用次数和资源；重复读取不会重复强化。自定义和固定技能遵循原有跳过迁移条件。正文解析、装备表单、库存、档案校验与 `unit_set` 同步支持负数和三通道词条；小数穿透/防护可在手工数值中设置。

校验包含整数锚点、连续单调性、正负边界、通道隔离、盾甲叠加、物理技能实际通道、旧档升级幂等、事务回滚和真实伤害抽样。全套测试及兼容/打包校验结果见 `verification.json`。真实酒馆宿主的交互烟测需要可用的浏览器环境，此环境的浏览器下载未成功；不将其标为通过。

## 对战数据与解释

- 2,000场：原世界观矩阵的同初始快照、同随机状态复测，涵盖同世界观/跨世界观、装备、训练等级、地形、小队和会战。
- 240场：原技能诊断矩阵中默认AI策略的同初始快照复测；不混入强制技能优先策略。
- 640场：16种新情境 × 2模式 × 5种子 × 2换边 × 修改前后。320对初始快照除技能公式版本标记外逐项相同。
- 160场：眩晕、缴械、沉默及复合控制的2对2支援情境，补充纯控制单挑的局限，80对初始快照同样一致。
- 324场：三通道 × 伤害/穿透/防护 × −10/0/+10 × 两模式 × 三种子 × 换边的单通道修正实战。

合计3,364场新实战，候选版2,964场、主分支对照400场。伤害抽样和复现验证不计入上述场数。完整统计在 [statistics.md](statistics.md)，分模式数值和描述性区间在 [summary.json](summary.json)，每场结果在 [battles.jsonl](battles.jsonl)。日志包含初始快照、随机状态和整场记录，压缩包及校验和随交付提供。

装备明显落后的控制者即使正确施法，也未必逆转胜负；沉默不针对普通法杖攻击、缴械不针对天生武器，是预期差异。某些回能或控制对照的胜率没有上升，不能把更多施法等同于普遍战术改善。小样本换边记录彼此相关，报告中的Wilson区间仅作描述。

原先的同火力纯控制单挑诊断仍然可以全程选择普攻：控制的抵抗概率、费用与放弃攻击的机会成本使它未必划算。2对2支援中眩晕、缴械和复合控制出现有效使用窗口；沉默、回能的部分小样本胜率仍下降，不能宣称所有技能构筑已达成最终平衡。

同P武器并不等于同预算军队：人数、身体、车辆平台、展开、盾牌与技能都影响战力。高训练对抗的回合上限平局属于截尾数据；本次不以消除全部平局或把所有组合改成50%胜率为目标，也未引入尚未定义的招募价格体系。

## 复现

先恢复PR #17提供的原始 `worldview-2000` 与 `skill-policy-480` 数据至 `engine/sim/out/`，然后运行：

```bash
npx vite-node scripts/sim-signed-skill-regression.ts --worker=0 --workers=4
npx vite-node scripts/sim-signed-skill-regression.ts --worker=1 --workers=4
npx vite-node scripts/sim-signed-skill-regression.ts --worker=2 --workers=4
npx vite-node scripts/sim-signed-skill-regression.ts --worker=3 --workers=4
npx vite-node scripts/sim-support-scenarios.ts --out=engine/sim/out/support-candidate-v2
npx vite-node scripts/sim-control-team-scenarios.ts --out=engine/sim/out/control-teams-candidate
npx vite-node scripts/sim-signed-channels.ts
```

将同一份 `sim-support-scenarios.ts` 与 `sim-control-team-scenarios.ts` 放入基线提交的独立工作树，使用该工作树的引擎，分别输出至候选仓库 `engine/sim/out/support-baseline-v2` 与 `engine/sim/out/control-teams-baseline`。最终执行：

```bash
python scripts/analyze-signed-skill-regression.py
npx vite-node scripts/verify-signed-skill-replay.ts
```

分析程序要求完整、唯一的2,240+400+400+324行记录和匹配日志；缺失或重复时拒绝生成完整报告。
