# 2.9.5 来信判断与战报修正

实测日期：2026-10-22。信件原话由用户提供：“缴枪不杀！！！”。收件方实际人设未提供，因此使用固定的谨慎守桥队长示例：兵力与装备处于劣势，优先保全部下，但不轻信口头承诺。此示例不能代表用户原战局的服从概率。

请求模型固定为官方 `deepseek-v4-flash`，两次返回均为 `deepseek-flash`。关闭思考，开局简报直接使用固定资料，没有额外生成人设。修前、修后各执行一次本来就需要进行的第2大回合指挥请求，来信合并在请求中；共2次真实 HTTP 请求，后续验证使用本地测试，不再追加模型调用。

| 版本 | 同一次回复中的工具 | 实际保存的反应 |
| --- | --- | --- |
| 修前 | diplomacy、commander_intents | 向我方提出投降；笔记为空，但信已标为已读。 |
| 修后 | commander_plan、diplomacy、commander_intents | 写入来信判断和新计划，提出双方撤军；笔记与外交决定均保留，夹带的战斗意图不执行。 |

修后实际笔记包括：“对手来消息『缴枪不杀』，仅为口头承诺，不可信；需对等保证才考虑投降。”总计划改为边退边谈，外交原话为：“我方不强求守桥。若双方各自撤军、互不追击，我方愿即刻退出桥头，避免无谓伤亡。”

两次回复存在模型采样差异，不能把投降与撤军的变化解释为稳定的战术改进。实测确认的是：正常回合调用能携带信件，修后同一次回复能产生并保留可见判断，不必为来信另加一次调用。

修前用量为2389输入／158输出 tokens；修后为2422输入／337输出 tokens。凭据只在本机运行时读取，未写入源码或报告。原始请求与回复保留在本机忽略目录 `artifacts/letter-reaction/`。

程序检查要求新来信先产生非空判断笔记，再接受行动或外交决定；没有判断时在原有请求预算内要求补全，不伪造指挥官意见。修复同一回复中外交优先导致笔记被跳过的问题。界面显示来信与送达状态，采纳／不采纳的理由仍来自实际模型笔记。

战报按用户指定的“我方对xx消息：xxxxx”保留原话，并加入AI提出投降／双方撤军、对方同意／拒绝及原话。逐轮、增量和终章共用消息识别与原文保留逻辑，兼容旧日志；旧归档有叙述事件时在输出时补全，不改写原报告。战斗进行中不泄露其他两方的私下交涉。
