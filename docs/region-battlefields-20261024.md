# 区域城市、自适应地图与可进入建筑

版本：3.0.1，分支`codex/region-battlefields`，发布目标`test`。数值战斗规则保持V32，已有战斗继续读取保存的实际地图，不重建。

## 行为

- 副API继续使用A1–D4的4×4布局草图。`city.at`可用分区数组描述一座城市、城堡或营寨；相邻分区合并，分离的分区通过最短的可用分区路径连接，避开另行指定的水域。保留凹形轮廓，内部接缝不筑墙。`front`城区须连接地图边缘；`ring`沿整体外缘筑墙；`double`生成内外墙及夹道，门状态和结构等级继续独立使用。
- 实际地图取消固定尺寸白名单。区域内的墙、建筑内部与单位占据容量共同决定起始尺寸，必要时在开战前扩大候选；尺寸增长不改变4×4草图各区的相对位置。单位卡数量限制不变，战斗过程中不改格编号。
- `water.at`数组表示面状水域，单个编号继续表示河流。区域水面覆盖普通低地，保护城市、命名建筑、实体工事和高地；先为明确水域预留底图，避免程序补出的树林、崎岖地和房屋把海面切成碎片。`mixed`沿陆地边缘生成浅滩，`shallow`可指定浅水分区；未指定的远处水格为深水。面状水域不自动建桥或补渡河浅滩；明确指定的桥必须跨过真实水格、连接两岸。
- 舰队按自身能力在水中部署，区域浅滩可作为登陆开局位置；普通河流仍保留原来的渡口部署规则。没有水域的明确计划尽早返回错误，不反复放大无水地图。
- 室外命名的`building`拥有外墙、门和内部地板，默认内部为3×3；同地点明确绑定的单位较多时，按整组占据容量扩大内部及对应分区。门、墙、掩体、视线、局部破坏与通行继续使用已有机制，建筑周边保留绕行空间。普通未命名房屋继续作为街区实体障碍。
- 检查完整占领区，移除被深水覆盖的无效占领格；城内仍有可走地面时在原城内修复核心。命名的攻城目标须在守方城内，不能通过默认回退把旗点改到城外。
- 地图回答最多修正3次，同一次开战进入已有的明确降级或本地回退流程；前两次是占领区错误、第三次才出现航行错误时，也在该次完成回退。错误反馈说明具体的占领区、水域与城内目标约束。
- 实际格坐标超过Z列时继续为AA、AB等。地图标尺、坐标输入、战报移动压缩与旧事件轨迹解析共用该格式。固守姿态保存新地图的实际高度，旧姿态记录继续按原尺寸解释。

## 真实调用与3.0.1修正

随后按用户要求，以相同正文、15张单位卡和固定地图种子做5轮真实Flash调用。共11次请求（5次决策、6次地图），首次布置通过4/5，重试后5/5完成生成、部署、开战与快照恢复，没有降级地图。平均每轮29.3秒。所有城内水格为0，所有占领目标格在城内且可走。该通过率只描述这5轮开战流程，不等于所有地图的正文还原率。

实测发现4轮我方舰队分区偏移，第3轮敌方舰队也偏移，另有2轮默认城墙朝向按全场方位误判。3.0.1在程序中修正：

- 航行单位的水上部署不受守军默认城内/上墙规则覆盖；攻方整片预选区域不再抹掉独立舰队的指定水域。仍按实际水格、障碍和占据容量检查。
- 默认正面按主力部署相对实际城区的方向确定，只选择存在外缘的墙面。单独侧翼小队不改变主力正面。
- 正面仅约束未指定位置时的默认接近地带。明确分区、命名接近地点与多方向来敌可在各自城外位置部署，西侧潜入和南侧部队不再统一挪到正面；有容量时保留指定分区，站开距离按该分区的实际空间确定。
- 城区与海岸距离继续由模型决定，未增加强制贴岸规则。本次修正未改动已确认的提示词或世界书。

重放原始5轮回答后，5/5均完成开战、恢复、一次AI行动与再次恢复；10支舰队全部保留原回答指定分区，5张图默认正面均朝北，城内无水且目标仍在城内。重放没有修改原始回答、没有新增API请求；原始真实调用结果保留，不将重放统计当作新的模型成功率。

证据目录：`artifacts/venice-map-audit/region-live-20261024/`（原始真实调用）与`region-replay-20261024/`（修正后离线重放）。

发布前复核覆盖舰队城外部署、明确分区保留、四方向相对朝向、侧翼及多方向城外开局；保留普通守军城内、攻方城外和原有占据/潜入关系。新增对应3个集成用例，未扩大已知失败允许名单。按用户要求发布到test，不查询或等待CI。
