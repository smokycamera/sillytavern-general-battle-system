# 承载与重量修正（V29，2026-10-23）

新建战斗默认V29，随2.10.0进入test。CI状态以发布记录为准。V28及更早战斗保留原规则。2.10.1起，战外自动把可确认的旧默认负载更新为新表；手工负载保留。

## 战外自动更新（2.10.1）

读档与战斗结算后的保存共用同一更新规则：库存实物和单位当前配装一起处理，容量采用下表；进行中战斗等结算后再更新档案，原战斗快照、战报与备份不改。

只更新仍等于原配方默认值的负载。例如旧火炮默认6、存档也是6，更新为12；存档为9则保留9。比较仅容许浮点误差，没有额外的“明显偏移”百分比。新写入的手工负载有独立标记，恰好等于默认值也保留；历史手工值若恰好等于默认且没有标记，无法追溯区分，将按默认值处理。缺配方、配方未知或未记录原负载时保留。

更新只复制负载及容量版本，不重编装备伤害、防护、品质、等级或随机浮动，不改变单位基础生命与库存归属。重量修正仍按该件装备原配方计算。重复读档不再次递增版本；保存失败不发布候选，原生待确认保存可按原流程重试。

## 实际容量

容量是重量、体积和操作负担的抽象数值。负载不超过容量80%时无惩罚；超过后沿用连续移动、先攻和超载命中／闪避规则。

## 重量修正

武器、护甲、盾支持重量−10至+10，每个方向只写一次，不限制修正方向数量。正值更重，负值更轻：`实际负载＝基础负载×1.1^重量点数`。每+1乘1.1，每−1除以1.1。重量独立于装备L、强度和伤害修正；无甲、天生武器等基础负载为0的装备仍为0。

| 重量修正 | 负载倍率 | 基础负载12的火炮 |
| --- | ---: | ---: |
| −10 | 0.38554 | 4.63 |
| −5 | 0.62092 | 7.45 |
| −1 | 0.90909 | 10.91 |
| 0 | 1 | 12 |
| +1 | 1.1 | 13.2 |
| +5 | 1.61051 | 19.33 |
| +10 | 2.59374 | 31.12 |

示例：`直射火炮L5+3伤害+2精度-3重量`。表单与库存显示实际负载；原始精度保存，玩家显示最多两位小数。已编译实物不会随持有者升级或换身体重算。一次性、充能、佩戴道具和单位本体不新增重量方向。

## 借鉴与取舍

Pathfinder的Bulk规则将重量、体积和携行难度抽象为负载，并区分身体承载能力与装备等级；这里借鉴这种抽象，不照搬其容量、体型或超载公式。[Pathfinder Player Core：Equipment／Bulk](https://2e.aonprd.com/Rules.aspx?ID=2143)。

美军迫击炮资料列出炮管、两脚架、底板等分件；用现有班组人数分摊负载可表达集体操作，不必新增口径、炮架或载具分档。[M252A1系统与分件](https://www.cpeae.army.mil/Project-Offices/PM-CAS/Organizations/Precision-Fires-Mortars/Products/81MM-M252A1/)。本次所有游戏容量、负载和重量修正系数均为本系统的平衡选择，不是现实公斤换算公式。
