# v1.3.19：批量删除与冻结实例 RNG

## 选择与边界

目标是「同类型、同L、同品质、同体型、其他修正相同的属性，+2 位于 +1 的峰与 +3 的谷之间」，不是让所有 +2 武器在任何战况下一定打出更高伤害。命中、暴击、伤害骰、防护和最终生命取整仍可使实际结果交叉或打平。单位训练 L 与装备技术 L 继续独立；本次不改 V11 压制曲线、SP、技能定义或内置世界书。

比较三个以零为中心、支撑区间 [-0.4,+0.4] 的候选，全部满足相邻档隔离：

| 候选 | 浮动标准差（修正点） | 精确端点概率 | 取舍 |
| --- | ---: | ---: | --- |
| 连续均匀 | 0.23094 | 0 | 简单，但产生许多难辨的小数品质 |
| 两次均匀平均（三角分布） | 0.16330 | 0 | 更集中于普通水平，使本来就小的实例差异更难感知 |
| **五档等概率离散** | **0.28284** | **每端20%** | **选用：有限、可展示、常见峰谷，强度均值不变** |

表中标准差由分布解析计算，不伪称三套候选都运行过完整战斗。完整实战对照只针对旧主分支与所选方案。

新实例适用属性保存整数 roll ∈ {-2,-1,0,1,2}，实际修正偏移为 roll/5。每个轴由版本、实例 seed 与属性名独立播种：增减一个轴不会使其他轴改点。查属性、攻击、预览、读档不会重新抽取。

例：

| 标称修正 | 可能的有效修正 | 仅此伤害修正的倍率 |
| --- | --- | --- |
| +1 | +0.6 / +0.8 / +1.0 / +1.2 / +1.4 | 1.03–1.07 |
| +2 | +1.6 / +1.8 / +2.0 / +2.2 / +2.4 | 1.08–1.12 |
| +3 | +2.6 / +2.8 / +3.0 / +3.2 / +3.4 | 1.13–1.17 |

相邻支撑区间之间空出0.2修正点。不能把这些小数理解为装备 L 升降：它只影响指定属性的修正项。

- 伤害、生命与吸能/盾覆盖强度：原倍率中心 ±0.02，五档步长0.01；这是乘数的**百分点**，不是最终伤害固定±2%。
- 穿透、防护：原评级中心 ±0.08，五档步长0.04。
- 原合计倍率下限0.5、上限2，以及穿透/防护修正评级±2的封顶点保持原值；已饱和中心不再随机穿越边界。
- 单位随机生命/伤害；配方武器随机伤害/穿透；配方护甲、盾牌随机防护/强度。技能不额外抽一层；物理招式沿用持有武器，单位伤害轴同时作用于普通攻击与伤害技能。
- 不随机命中加值、防御加值、射程、移速档、攻击次数、负重、人数、SP或消耗品数量。空防护不会凭空变成正防护，显式覆盖的防护值照旧优先。
- 新武器不再叠加旧±3%骰子预算抖动，避免双重随机。浮动作用在保留小数的伤害倍率上，不再先被重建整数骰吞掉。
- 角色生命最终为整数，因此低生命时可能显示相同最大生命；装备不同属性互有高低也是正常的。本功能没有「所有属性一起变好」的质量总分。

## 冻结数据与兼容性

新记录使用可选 `variance.version = enhancement-bands-v1`，放在装备 recipe 与单位 genAudit 内。没有这个字段的旧实例保持旧值，读档不自动补字段，也不重掷。`noVariance` 构造仍为中性基准。

改造沿用原 seed 和各轴 roll，名字、归属、装备/卸下、再次部署、读档、XP升级不重掷。旧装备改造不会静默升级成新随机模型。生成上下文 `variance:false` 专门保留历史配方的旧抖动路径；两条复现 V7 报告/巨人旧武器投影的测试显式使用它，原数值断言未放松。

详情新增一行「固定浮动」，仅展开时显示。物理攻击预览与实战共享同一乘数；本次没有把命中后伤害改回混入未命中的期望伤害。

## 批量删除

入口放在配装标题区「技能选择」左侧。窄屏标题与三个按钮分行，避免挤出屏幕；进入多选后只显示全选/删除（数量）/取消。

全选只包含当前可见、数量大于0且未装备的物品；已装备项禁选，不自动卸装。改变查看单位或聊天、开始战斗、已选物品消失/被装备会清理相关选择与预览。删除按整组数量确认，一次展示所有选中项，只有一次最终确认。

底层 `discard-many` 先校验整批唯一ID、现存数量、装备状态、全局事实版本和战斗锁，再将整批数量置零。沿用原库存零数量墓碑与操作账本，一次操作ID、一次revision、一次持久化；失败不会部分删除，重复提交同一操作幂等。保存中禁用重复确认，失败保留同一预览可重试，旧聊天迟到的保存结果不污染新聊天。

## 实测

对照基线为 `c51aada22024a7c12c6a7a09d1f180861e867730`，两棵独立源码树运行同一 `audit-instance-variance.ts`，每棵600场，总计 **1,200场、600对**。覆盖L1–10、50套同级/相邻/远距压制与技能、屏障、盾牌、人数、车辆等模板，平原/森林/夜间城镇，小规模与会战，双方镜像换位。实例seed和战斗seed配对；不改变生产AI政策。

| 指标 | 旧主分支 | 新五档RNG |
| --- | ---: | ---: |
| 完整战斗 | 600 | 600 |
| 平均回合 | 6.7567 | 6.7333 |
| 中位回合 | 5 | 5 |
| 小规模平均回合 | 7.3133 | 7.2467 |
| 会战平均回合 | 6.2000 | 6.2200 |
| 出现单体满血击杀的战斗 | 109 | 108 |
| 错误/未结束 | 0 | 0 |

600对里18对胜负/平局结果改变（3%）；平均回合下降约0.35%。这说明本样本整体节奏接近，但不是「随机数没有效果」，也不是所有情景都保证不变。模板有设计上的强弱队，不能把A队胜率当作普通玩家阵营胜率。

完整新增回归包括区间顺序、负修正/封顶、10,000种seed的离散分桶、L1–10武器小数生效、冻结/拒绝损坏数据、升级、护甲/盾、普通攻击和魔法各2,048次独立攻击的预览统计一致性，以及批删原子性、保存失败/重复点击/切换聊天等。

基线全量：1,319项，1,312通过、7失败。修改后全量：**1,359项，1,352通过、7失败，新增40项全部通过，无新增失败**。原7项是5项旧战斗精确回放和2项旧生命上限断言，本PR未修改这些失败测试或伪造绿灯。专项5文件60项全部通过。类型检查、构建、`verify:dist`通过。

本地 Chromium 离线浏览器验收通过320/390/690/1280px、仅可见物品全选、已装备保护、一次确认/一次宿主写入、失败重试、读档保持删除、固定浮动详情。容器禁止localhost导航，故本地采用离线页面+模拟宿主/存储；这不等同于真实安装的ST/TT人工验收。脚本默认走localhost正常浏览器路径，供CI复测。
