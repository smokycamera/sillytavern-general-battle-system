# 可选 JEV 指挥模式

当前发布版本为 **0.2.0-rc.11**，内置 JEV **0.2.3**。原有自动 AI 保留为默认；新安装与旧存档不会自动切换到 JEV。

## 更新与连接

在酒馆扩展管理中更新本插件并刷新页面。在“设置 → JEV 指挥”选择连接方式：

- **TypeSafe / JEV API（新安装默认）**：地址 `https://api.typesafe.ai/v1`，填写 TypeSafe API Key，点击“拉取模型”，在列表中选择模型，再保存连接。默认模型 ID 为 `jev-latest`。模型列表请求 `/models`，评分与开战选择请求 `/systemone`。
- **OpenAI 兼容接口**：填写第三方 API 基础地址与其 API Key，拉取并选择模型。决策使用所选模型的 `/chat/completions`，服务需要支持 JSON 输出。仅模型列表可拉取不代表决策协议一定兼容。
- **本地桥接（旧版）**：已有连接自动保留此模式，地址与 JEV_SERVICE_TOKEN 沿用旧配置；模型仍由桥接服务的 `.env` 配置。桥接服务需支持 JEV 0.2.3 接口。

地址可以填写基础路径、完整 `/models`、`/systemone` 或 `/chat/completions` 地址；自定义路径前缀会保留。远程 API 使用 HTTPS。rc.10 的请求通道默认“自动”；使用宿主或自建转发时，上游不需要支持浏览器跨域。仅“浏览器直连”仍要求上游允许 CORS。不支持模型列表的服务可以手动填写模型 ID，点击“仅保存连接”。“保存连接并测试”在远程 API 模式只检查模型列表，不发起付费决策请求。rc.11 新增“测试模型推理（调用 API）”：发送简短示例验证实际 POST 与答案格式，不读取聊天或战场，可能产生 API 费用。测试结果留在设置页；可随时暂停。

API Key 只保存在当前浏览器会话；重新开启浏览器后可能需要重填。地址、协议、模型 ID 保留在当前浏览器，不写入聊天存档。已有旧桥接配置不会被自动覆盖；切换官方直连时请同时修改协议、地址和密钥。

官方接口依据：[模型列表](https://docs.typesafe.ai/models)、[决策接口](https://docs.typesafe.ai/api)。

在准备界面或战场工具栏选择“JEV 指挥”。现有单次自动行动、敌方自动行动、全自动战斗与会战结算入口沿用。可随时暂停、收起面板或切回“原有自动 AI”；切换不会重掷正在进行的战斗。V1 旧规则继续使用原 AI。

## 跨域连接（rc.10）

rc.9 在面板 iframe 中直接请求远程 API；服务不支持 CORS 时，模型列表、连接测试和实际决策都会失败。rc.10 将这些请求与旧桥接请求统一交给连接通道；rc.11 在同一通道内加入规划请求自动重试。

| 环境 / 协议 | 推荐请求通道 | 需要的设置 |
|---|---|---|
| SillyTavern / TypeSafe 或 OpenAI | 自动 / 酒馆宿主转发 | 在宿主 `config.yaml` 设置 `enableCorsProxy: true`，重启酒馆 |
| TauriTavern / OpenAI 兼容 | 自动 / 酒馆宿主转发 | 使用宿主已有 custom 后端，无需通用 CORS 代理 |
| TauriTavern / TypeSafe，服务不支持 CORS | 自建转发 | 在同一设备启动下面的转发程序，填写转发地址 |
| 已支持 CORS 的 API / 独立面板 | 浏览器直连 | 上游允许当前页面的 Origin 和 Authorization 请求头 |
| 旧本地 JEV bridge | 自动 | 保持原直连；也可显式选择转发 |

TauriTavern 当前没有可转发任意 TypeSafe 请求的 `/proxy/` 接口；单纯换成父窗口 `fetch` 也不能消除浏览器跨域限制。插件不会虚构此能力，也不会关闭 WebView 安全策略。其 OpenAI 后端通过每次请求传递自定义 API 地址和 Key，不更改酒馆主模型连接设置。

### 本机转发启动方法

在安装有 **Node.js 22 或更新版本**的设备上，进入本插件目录运行：

```sh
node scripts/jev-cors-relay.mjs
```

从 GitHub 克隆的仓库也可用 `npm run jev:relay`；此程序仅使用 Node 内置模块，无需 `npm install`。Android 上可在 Termux 中运行；转发进程需要保持运行。电脑上的 `127.0.0.1` 与手机上的不是同一台设备。

然后在插件填写：

- 连接方式：`TypeSafe / JEV API`。
- API 地址：`https://api.typesafe.ai/v1`，完整 `/systemone` 地址也可以。
- API Key：原来的服务商密钥。
- 请求通道：`自建转发`。
- 转发地址：`http://127.0.0.1:4318`。
- 点击“拉取模型”，选择后“保存连接并测试”。

转发默认仅监听 `127.0.0.1:4318`，目标固定为 TypeSafe 官方 API。允许的页面来源默认包括 `http://localhost:8000`、`http://127.0.0.1:8000`、`tauri://localhost`、`http://tauri.localhost` 和 `https://tauri.localhost`。如酒馆端口或域名不同，请配置其**准确来源**，例如 bash / Termux：

```sh
JEV_RELAY_ORIGINS='http://127.0.0.1:8080,https://your-tavern.example' node scripts/jev-cors-relay.mjs
```

其他 API 的上游基础路径必须与插件匹配，例如：

```sh
JEV_RELAY_UPSTREAM='https://your-api.example/v1' node scripts/jev-cors-relay.mjs
```

PowerShell 对应写法：先执行 `$env:JEV_RELAY_UPSTREAM='https://your-api.example/v1'`，再运行上述 `node` 命令。`JEV_RELAY_PORT` 可修改监听端口。旧 bridge 上游应填写原桥接基础地址，不附加 `/v1`。

程序只接受配置上游的模型、决策和桥接端点；拒绝其他来源与任意目标，不跟随上游重定向，不转发酒馆 Cookie 或 CSRF。它不写入 API Key、请求正文或返回正文日志。自建转发会接收你填写的 API Key，应使用自己控制的服务。若通过自己的 HTTPS 反向代理跨设备访问，请将代理的上游 Host 设置为本机地址，并保留 Origin；不要开放给不可信来源。

浏览器直连失败仍可能是网络、TLS 或 CSP，单凭“Failed to fetch”不能确诊 CORS。宿主代理未开启、CSRF 过期、API 401/403、超时、无效 JSON 将分别提示；代理返回的正文不会原样显示，以免回显密钥。SillyTavern 使用 Basic Auth 或额外反向代理认证时，若服务商 Authorization 与宿主认证冲突，可改用上述自建转发。

## 同一次请求选择敌方与场景

设置页提供以下项目：

| 设置 | 行为 |
|---|---|
| 我方指挥水平 | 手动指定我方五档能力，现有自动策略作为我方风格偏好 |
| 敌方指挥：根据上下文 | 根据当前敌方的明确设定选择新手、常规、熟练、专家、大师及 14 维风格 |
| 敌方能力／缺省档位、风格／缺省偏好 | 手动模式的实际配置，或自动模式信息不足时的默认配置 |
| 战场与任务：开战时根据上下文 | 选择平原、城镇、攻城、森林、山地，昼夜，标准／室内地图及胜利任务 |
| 战斗形式：按上下文与编制 | 选择逐单位的小战地图或编队会战，也可手动固定 |

开战时将上述自动项目合并为 **一个 JEV choice 批次**。只需已有 JEV 密钥，**不需要额外配置 TEXT 文本模型**。本轮增加的是已有引擎选项的选择和落地；地图格子、地形生成、合法部署与胜负仍由酒馆引擎负责，未加入模型自由绘图。

胜利任务包括歼灭、攻城夺点、我方护送、拦截敌方。护送／拦截／夺点及室内场景自动采用支持这些规则的小战地图；会战采用现有歼灭结算。编制不支持会战时采用小战，室内地图容量不足时采用标准地图。手动会战与手动特殊任务冲突会提示调整，不悄悄改写任务。护送对象沿用主控或首个我方单位；拦截使用首个敌方单位。

修改准备界面的地形、光照、地图、任务或攻守方，会切换为手动场景。需要恢复自动选择时，将“战场与任务”设回“开战时根据上下文”。旧档明确指定的室内地图或任务默认保留手动选择。

## 上下文与战斗中更新

默认读取最近 **6 条已完成的 assistant 消息**，共享“最近消息数”和已配置的消息角色；每条最多使用末尾 6000 字符。窗口为 0 时不读取、不请求。原生接口保留消息边界；历史独立面板只能使用适配器提供的最近文本。

没有明确证据时保留原设置，不凭人物姓名或伤害数值推断大师能力。能力与风格选择要求置信度至少 0.6；场景接受合法候选，模型选择 unknown 时保留默认值。敌方配置与场景随本场战斗保存，重复消息窗口不会重新判定；信息不足而采用默认配置后，新正文到达时可补充识别。

场景、地图和胜负规则在开战时冻结。已有上下文指挥配置仅在**新消息明确描述指挥官更换，或其能力／性格状态变化**且变化置信度至少 0.8 时更新。一般伤亡、行动或情绪描写不会让敌方每回合换性格；更换指挥者清除前任偏好，原指挥者状态变化保留未提及的维度。

“正文目标提取”是独立功能，默认关闭。TypeSafe 直连不支持自由文本目标提取；OpenAI 兼容模式使用同一所选模型；本地桥接仍需 `TEXT_API_URL`、`TEXT_API_KEY`、`TEXT_MODEL`。它只补充目标与环境提示，关闭不影响上述 JEV 开战判定。

## 保存、取消与回退

小战推进一个激活，会战保留玩家明确军令并补齐其余军令，再交给原引擎结算。计划、回执、指挥配置与战斗快照一起保存。开战判定等待期间可暂停；聊天切换、消息改变或存档代次变化会丢弃未提交结果，取消不会创建半场战斗。

rc.11 对规划评分、开战上下文选择和正文提取采用同样的重试规则：首次请求失败后，间隔 **1 秒**自动重试，最多 **10 次重试（共 11 次尝试）**。重试期间显示次数，耗尽后才显示失败和具体原因。上下文选择失败沿用准备设置；评分失败回退原有 AI，下一次规划最多等待 **1 秒**即可重新探测，不再进入 30 秒冷却。协议、Key、代理设置等固定错误仍需修正，重复请求不能消除 CORS 限制。

1 秒是失败后的等待间隔，并非模型响应时限。每次请求最多等待 30 秒，决策总预算已覆盖完整重试周期；可随时暂停。每个自动激活／会战轮次最多 10 个逻辑模型请求，上下文判定与正文提取计入同一上限；每个请求的重试单独计数。达到逻辑请求上限时保留本地规划，不再误报服务不可用。普通动作仍在本地选择。

如果 1～2 秒就报错，应查看最终诊断中的 HTTP 状态、宿主代理/CORS 提示或返回格式错误，并使用“测试模型推理”复查。模型列表可达不代表 POST 推理权限和协议可用。错误提示不回显 API Key、远端响应正文或聊天内容。

保存失败沿用既有 journal 回滚／核实流程，重试不重新请求模型或掷骰。刷新恢复已保存配置与计划，全自动不会自行打开。密钥不进入 dist、计划、战报或聊天存档；API Key／服务令牌仅存浏览器会话。不自动向聊天发送 JEV 决策。

## 核心维护边界

`vendor/jev-core/source.json` 记录核心来源提交和文件校验。通过 `node scripts/vendor-jev-core.mjs <核心仓库路径>` 同步已提交源码，构建前检查哈希；不手改副本。许可证沿用本仓库 LICENSE 原文。

JEV 0.2.3 仅增加通用“宿主提供问题与候选值”的选择接口、校验和服务网关。酒馆的敌方提示、场景名单、阈值、手动优先、地图约束与存档全部留在本插件。核心没有新增酒馆模式分支或重写调度器。

rc.7 已有的无接触搜索、移动目标绑定、全组距离选敌、有限历史和置信度加权继续保留。模型接收本阵营最近 24 条 JEV 操作与回执，并非整场完整战报；普通行动仍在本地执行。

本轮验证见 [rc.11 重试与诊断验收](jev-retry-validation.md)，前一轮连接验证见 [rc.10 跨域验收](jev-cors-validation.md)。开战上下文验证见 [rc.8 定向验收](jev-context-validation-20260922.md)，上一轮广泛战斗验证见 [rc.7 指挥验收](jev-command-validation-20260922.md)。本轮未重复全量战斗测试或对用户实际聊天运行测试。
