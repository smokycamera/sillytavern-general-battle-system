# 上下文配置与 JEV 状态

JEV 指挥尚未完成，本版已撤下战场、准备页和设置页的 JEV 连接、测试、扫描及切换入口。设置只保留不可选择的 `jev指挥功能(未完成，勿选)` 提示。旧聊天即使存有 JEV 模式，也使用内置自动战斗；旧连接记录保留供恢复。

当前可用的是“设置 → 上下文与开战配置 → 普通 LLM 读取上下文”。填写 OpenAI 兼容服务的 API URL、API Key，拉取并选择模型，也可直接填写模型 ID。无需填写转发地址或选择请求途径。网络请求自动使用宿主支持的通道；服务本身仍须可达并兼容 OpenAI 接口。

从 1.0.6 起，原版 SillyTavern 和 TauriTavern 都自动使用各自内置的模型后端，拉取模型与开战前读取上下文均不依赖 ST 的 `enableCorsProxy` 开关。更新扩展后刷新页面即可，无需修改酒馆配置。插件始终使用这里填写的 URL 和 Key，不改动酒馆聊天连接；Key 留空时也不会把酒馆原有的 Key 发给该地址。

连接失败时保留可操作的诊断：会话校验失效请刷新酒馆；缺少模型后端接口请更新宿主；网络失败请检查运行酒馆的设备或服务器能否访问该 API。上游未提供模型列表时可手填模型 ID，再尝试开战前读取上下文。原版 ST 的部分错误响应不保留上游状态码，此时需结合酒馆服务端日志排查。反馈请附 ST/TT 与扩展版本、脱敏后的报错，勿附 API Key。

配置即时写入独立的本机存储，URL、Key、拉取的模型列表、模型选择和读取层数不属于聊天或角色卡，不随其切换、清空或删除而改变。旧版 OpenAI 连接可自动复制过来；不把 TypeSafe 地址当成普通 LLM 接口。主动清除浏览器站点数据或更换设备不属于聊天删除，会失去该设备的本机配置。

开战前读取最近 1–100 层已完成的用户/AI 消息；一层是一条消息，每条截取末尾最多 6000 字符，不读取思考内容。模型从支持的具体选项中选择双方指挥能力、风格、小战/会战、地形、昼夜、地图和胜利任务。优先遵循明确设定；信息不足时结合身份、行为、任务与场景自行作出合理判断，不提供 unknown 选项，也不会因置信度低于 0.6 而覆盖模型选择。只有没有可读取正文时沿用准备设置；请求失败或返回不支持的选项时不开始战斗，可重试或改为手动。取消、切换聊天、变更连接或准备数据后，迟到的答案不能开始战斗。

选择出的双方指挥配置只作用于内置自动行动的候选排序，并随本场快照保存。能力改变估值误差，风格提供有界偏好，不改命中骰、伤害、单位属性或手动命令；未开启 LLM 或没有可读取正文时沿用内置自动决策。战斗期间不会再次调用模型或更改地图。

开启“由 LLM 设计地图”时，开战准备分两步请求：

1. **开战决策**：选择上述配置、VIP，以及战场类型（野外、城墙攻防、巷战、围攻院落、室内、堑壕）和战场大小。选会战时到此结束。
2. **布置战场**：在上北下南的九宫格上写城市、水系、最多8个地点、双方开局方位、单独行动的单位和任务地点。回答不需要 ID、段落引用或关系词，坐标、占地、道路、高差与具体落位由本地生成。

两步共用相同的 system 与正文消息，只有最后的任务不同，支持前缀缓存的服务商可以复用第1步的正文部分。关闭地图设计时只请求1次。

攻守位置由本地规则保证，不依赖模型措辞：攻城开局时攻方只在城外正面，守方在城内或城头；城外野战双方都在背景城镇之外，巷战双方都在街区内。护城河或与城市同侧的河流沿城外开阔一侧布置，不穿过城区。方位写成“北方、城南、north_east、左上”等也能识别；无法落实的方位就近调整，调整说明列在地图的“查看布局依据”里。详见[副 API 两步准备与攻守部署修复](secondary-api-two-step-20261002.md)。

同一准备内容失败后再次点击开战，会携带出错那一步最近最多4条去重后的错误原因，每条最多280字符：地图生成失败只告知第2步，不干扰第1步的决策。仅在内存保留请求指纹和错误短句，5分钟后失效；成功、明确取消、换聊天、改连接或准备内容时清除或隔离，不保存完整提示词及失败回答。不会因此自动增加模型调用。每步请求有独立的120秒截止时间，不依赖服务是否响应取消，超时后释放操作锁，迟到回答不生效。

手动或 MCP 提交的地图 JSON 仍使用原有的场景意图格式，逐项严格校验；新增可选的 `deployments` 按九宫格写开局位置，同样受上述攻守规则约束。

配置损坏时可继续手动开战，在设置的“配置恢复”中备份原始配置、重置选项并保留连接，或明确清空配置和Key。

同目录其他带日期的 JEV 验证文件属于历史记录，不代表当前界面提供这些入口。
