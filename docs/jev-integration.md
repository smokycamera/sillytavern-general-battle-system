# 可选 JEV 指挥模式

当前发布版本为 **0.2.0-rc.6**，基于 GitHub c6da07a（0.2.0-rc.5）。原有自动 AI 完整保留，旧存档和新安装默认不调用 JEV。

## 使用

启动配套 `smokycamera/jev-general-tactic-system` 服务，在其 `.env` 设置 TYPESAFE_API_KEY、JEV_SERVICE_TOKEN、JEV_ALLOWED_ORIGINS。完成 npm ci、npm run build 后运行 npm start。

酒馆“设置 → JEV 指挥”填写服务地址（默认 http://127.0.0.1:4317）和 **JEV_SERVICE_TOKEN**，点击“保存连接并测试”。这里不填写模型 API 密钥。服务令牌只存当前浏览器会话，不保存到聊天。

在战场工具栏选择“JEV 指挥”，原有的单次自动行动、敌方自动行动、全自动战斗和会战结算入口就会使用 JEV。随时可暂停、收起面板，或切回“原有自动 AI”。切换模式不会重掷当前战斗。V1 旧规则继续使用原 AI。

指挥水平提供五档，现有“自动策略”作为我方风格偏好。正文提取默认关闭；需另配 JEV 服务的文本模型后，可选择自动或手动扫描最近完成正文，默认最近六条 assistant 消息。自动模式在下次决策检查消息变化。正文仅补充目标与环境提示。

## 保存与回退

适配器分别读取双方可见单位。小战推进一个激活，会战保留玩家明确军令并补齐其余军令，再交给原引擎结算。计划、回执和战斗快照一起保存；等待中取消、聊天切换、存档代次变化会丢弃候选。

保存失败沿用原生 journal 回滚／核实流程，重试不重新请求模型或掷骰。刷新恢复计划，全自动不会自行打开。手动修改战场使原计划失效。服务不可用时回退原有 AI，暂停模型探测 30 秒；每个自动激活／会战轮次最多 10 次模型请求，普通动作主要在本地选择。

不会自动向聊天发送 JEV 决策或正文消息。模型密钥不进入 dist、计划、战报或存档。

## 核心版本

`vendor/jev-core/source.json` 记录核心的仓库、提交号和文件校验。`node scripts/vendor-jev-core.mjs <核心仓库路径>` 仅接受核心源码已提交的副本；构建前执行 `node scripts/check-jev-vendor.mjs` 校验。前端无远程脚本依赖。

## 验证范围

新增适配器、取消、过期、回退、计划恢复、显式军令保留测试；原生浏览器冒烟增加模式选择、模型等待中暂停、持久回执和切回旧 AI。原有引擎与历史场景兼容检查保持通过。

本轮实测包含模型接口联通和合成酒馆宿主，没有操作用户实际聊天。特殊组合利用率、长局表现及平衡仍需实战评估，暂不承诺 JEV 胜率高于原 AI。未映射的专属动作由原 AI 完成剩余行动；未配置文本模型时不执行正文语义提取。

## 核心维护边界

本次内置 JEV 0.2.1，沿用本仓库的 LICENSE 原文。同步脚本会验证核心的来源提交、文件和许可证哈希；核心源码副本不得手工修改。修改通用能力先提交到 JEV，再通过同步脚本更新。

支援动作是否可以穿插执行由酒馆的 TaskExecutor 决定，JEV 调度器不识别酒馆技能名称或 support 特例。小战/会战数据映射、原 AI 回退、客户端连接、聊天存档和界面仍在酒馆代码中。此次未混入 RTS/FPS 实时调度重写。
