# 保存待处理卡死与提示白话化（2026-10-03）

现象：

1. 玩家停在“上一笔保存尚待核实”的提示，三个按钮“核实并重试保存 / 放弃未落盘待确认内容 / 导出已确认档案”都走不出去：点放弃显示 `Error: 待确认内容已部分落盘，不能当作未保存操作丢弃`，点重试的原因也是这一句，刷新页面后仍停在同一处。
2. 提示和按钮用“核实、落盘、待确认内容、读回、来源消息标记”等说法，玩家看不懂；“待确认内容”还和面板里等玩家确认的正文事件同名；报错前面带英文 `Error:`；状态区的多行说明挤成一行。

## 原因

扫描 AI 回复或确认正文事件时，一次保存要写两样东西：聊天附加记录里的战阵存档，以及对应聊天消息上的来源标记（用来防止同一条消息重复入账）。保存后会从酒馆重新读一遍，两样都对上才算成功，否则进入待处理。

卡死发生在“存档已经写进酒馆，但消息标记没对上”的时候。可能的来路：

- 保存时这条回复正在被酒馆收尾或被别的插件改写，写下去的是新正文，标记里记的仍是旧正文；
- 保存没确认成功后，玩家重新生成、编辑或删除了这条回复，酒馆随后的自动保存把内存里的半份存档一起写了进去；
- 酒馆没有保存消息上的附加字段。

这时三条路互相指向对方：

- 重试：先要把标记重新贴到原消息上，消息已经变了，于是转去放弃；
- 放弃：发现存档已经写进酒馆，怕把已保存的进度当成没保存，拒绝放弃；
- 刷新：读档时同样发现半份存档，又回到待处理。

旧测试“候选已部分落盘时不因来源变化自动丢弃或重新入账”断言的正是这个停住的状态。

## 修改

### 存档恢复

- **撤销这次改动**：存档已写进酒馆而消息标记没保存时，不再拒绝，而是把上一版存档作为新的一版写回酒馆（版本号继续往前加，旧记录不会再和酒馆里的存档对上），读回核对一致后才删掉浏览器里的恢复记录。
  - 写回没成功：保留原恢复记录，面板继续显示上一版存档，稍后可以再点一次。
  - 酒馆里已经有别的新进度：不覆盖，提示重新读取。
  - 首次建档（例如采用旧脚本存档）写到一半：撤销会删掉这半份存档，回到“采用旧档 / 从空档开始”的选择。
  - 存档其实已经完整保存：仍保留进度，并提示“这次改动其实已经保存成功，已保留”。
- **重试保存**：消息已被修改、重新生成或删除时，自动按上面的方式撤销半份存档，再重新扫描当前这条消息，只生成需要人工确认的事件；旧回复和新回复里的事实都不会自动入账（与 rc.5 对“保存前回复被改写”的处理一致）。消息没变时照常重新保存。
- **保存途中回复被改写**：保存后发现标记对不上，立即再贴一次标记；回复确实变了就当场撤销半份存档并重扫一次，玩家不会看到待处理提示。宿主确实存不上标记时，最多多保存一次，然后进入待处理。
- 交回旧版脚本的保存仍不能撤销，只能重试完成。

### 提示文字

待处理提示：

> 战阵最近一次改动（例如扫描 AI 回复、确认事件或战斗行动）还没有确认保存成功。为免弄乱存档，已暂停其他操作。
> 原因：……
> · 重试保存：再保存一次这次改动。
> · 撤销这次改动：放弃这次改动，回到上一次保存成功的存档。
> · 导出存档备份：下载上一次保存成功的存档。

| 原按钮 | 新按钮 |
| --- | --- |
| 核实并重试保存 | 重试保存 |
| 放弃未落盘待确认内容 | 撤销这次改动 |
| 导出已确认档案 | 导出存档备份 |
| （无） | 重新读取存档（酒馆里已有其他新进度时使用） |

- 按钮失败时保留整段说明，只更新“原因”一行；以前会把说明整个换成一句带 `Error:` 的报错。
- 所有状态提示去掉 `Error:` 前缀；状态区按换行显示。
- 面板顶部的锁定原因、设置页“保存与恢复”里的按钮同步改名。

保存相关报错改写（节选）：

| 原文 | 现在 |
| --- | --- |
| 待确认内容已部分落盘，不能当作未保存操作丢弃 | （不再出现，改为撤销写回） |
| 档案已保存，但来源消息标记或回退副本尚未落盘 | 存档已写入，但对应聊天消息的标记还没保存成功 |
| 来源已变化；已核实旧待确认内容未落盘，请重新扫描 | 这次改动对应的聊天消息已被修改、重新生成或删除，改动没有生效；请重新扫描这条消息 |
| 酒馆保存接口返回后，持久档案仍停留在上一版本 | 酒馆显示保存完成，但读回的仍是旧存档，这次改动没有写进去 |
| 读回的档案身份或版本与本次待确认内容不同 | 读回的存档和这次改动对不上，可能已被其他操作改动 |
| 酒馆已存在其他进度，请重新读取后核对 | 酒馆里的战阵存档已被其他操作更新，请重新读取存档后再看 |
| 上一笔操作的保存结果仍待核实 | 上一次保存还没确认成功，请先选择“重试保存”或“撤销这次改动” |
| 酒馆数据校验失败 | 酒馆里的战阵存档没有通过完整性检查，可能已损坏 |
