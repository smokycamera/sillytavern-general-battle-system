# 正文自创道具：unit_set 交道具、写不出的单独略过、道具位置的武器词条、佩戴防护（2026-10-12）

基线：`1af8b45`（test，V15 道具系统）。不新增规则版本：佩戴防护只对新写出的佩戴道具起作用，已有道具与进行中的战斗结算不变（见验证）。世界书只改条目 0 的 unit_set 便捷属性一行和示例里的一个字段（已同意）；`lorebook system explain.md` 同步说明。

按 2026-10-12 的讨论：items 只增不减；写不出效果的道具单独略过；不增加元素词（寒冷、雷电等照旧不认）；道具位置上的武器词条自动换成对应道具写法。另两条按之前的建议一起做了：“佩戴”写在特质前、修正写在等级前的写法容错，以及佩戴道具可以加防护。

## 现象

正文给出一组自创道具，再用 `unit_set id="u1" items="…"` 分给两名队员：

| 道具 | 写法 | 改动前 |
| --- | --- | --- |
| 法力合剂、炽火魔杖、石肤卷轴、沸血烈剂、硫磺晶尘、龙髓药油 | 各自的道具写法 | 能识别 |
| 爆裂火球石 | `爆破装置L5` | 静默变成一件能反复用的爆破武器 |
| 碎魔臂甲 | `佩戴破甲L5` | 报错：“佩戴”写在特质前不认 |
| 抗火护符 | `佩戴热能防护L5+4` | 报错：修正方向写在等级前；佩戴道具也不能加防护 |
| 冰风暴卷轴 | `魔法范围寒冷L5` | 报错：没有“寒冷”这种伤害 |
| unit_set 的 items | 分给 u1、u2 | 报错：unit_set 没有 items |

只要有一处报错，整条回复判为待补全，写对的 7 件也没有入账。

用真实模型复现（DeepSeek flash，奇幻战利品、现代空投补给、修仙宗门赐宝三个场景，现有四人小队，每个场景 6 次），改动前 18 次回复里有事件块的 14 次只入账 3 次：7 次整条卡住（佩戴道具写防护 4 次、写法问题 2 次、模型输出乱码 1 次），4 次佩戴修正超出预算，到入账时才报错、整批失败。入账的 23 种道具全在公共库存，没有一件到队员手上。

## 原因

1. unit_set 没有 items：正文没法把道具交给已有单位。V15 方案把它留到了第二期。
2. 一件道具写不出，整条回复作废。佩戴预算还要到入账编译时才检查，同样整批失败。
3. 佩戴道具的修正方向只有伤害、精度、防御、速度、士气、单通道伤害，“抗火”“防弹”写不出来。
4. 常见的写偏不认：“佩戴”写在特质前、修正写在等级前（`佩戴热能防护L5+4`、`物理单体射击+6穿透L5`）、效果词写在等级后（`buff治疗L3+振奋`）。
5. 武器词条写在道具位置：items 里直接拒绝，give 里静默变成武器。

## 修改

### 1. unit_set 的 items：把道具交给单位（`panel/src/item-handover.ts`）

写法同 spawn 的 items：`<unit_set id="u1" items="治疗药水:buff治疗L3×2,炽火魔杖:充能魔法单体热能L5"/>`。只增不减，收回用 take。每一项依次取：

1. 同一回复 give 的同名道具：直接交过去，不另入库。
2. 单位原本带着的同名道具算在内：已经够数就不再添，正文每次重复同一份清单不会越加越多。
3. 我方库存里没主的同名道具。
4. 还差的新建。

写了效果的只拿效果相同的那件；同一回复 give 的同名道具效果不同时，两件各自入库并提示。佩戴、充能道具交出时装上，编队一件就是整张卡的配发（写了多件只交 1 件并提示）。敌方与中立单位不动我方原有库存，只拿同一回复 give 的或新建。只交道具的 unit_set 不改档案、不升档案版本。unit_set 用新编号新建单位时带的 items 交给这个新单位。

道具在入账最后交出：这时同一回复 give 的已入库，新建单位也已建档。审批里列“交给法师：法力合剂（装上）、抗火护符（装上）…”；事件说明写“交给道具 …”，不再显示一串 JSON。

### 2. 写不出的单独略过

- give 的 spec、spawn 与 unit_set 的 items 某一项写不出效果，只略过这一项，审批提示“未采用道具「…」（原因）”，其余事件照常入账。spawn 的 items 本来就这样，现在 give 和 unit_set 一样。
- 解析时就把道具编译一次（`assertItemCompiles`），建不了档的在这一步略过，不再拖到入账时整批失败。
- 一条回复只剩写不出的道具时，作为待补全显示原因，不悄悄消失。
- 佩戴修正超出等级预算（`佩戴L5+8防御`）时，从最大的一项起逐点降到预算内，道具保留，提示“超出L5的佩戴预算，按「佩戴L5+5防御」”。这和“专精等级超出 L1–10 夹到边界并提示”一样。特质本身就超出预算的仍然略过。面板手工表单不降档，照常提示预算。
- “识别可解析部分”不再留下什么都不改的 `<unit_set id="u1"/>`（它本身也是错误）。

### 3. 道具位置上的武器词条（`weaponItem`）

在道具位置写武器词条，就换成“用这件武器打一次”的道具，并提示“「爆破装置L5」是武器写法，按道具「物理范围投射L5」”：

| 武器词条 | 道具 |
| --- | --- |
| 爆破装置、直射火炮、曲射火炮 | 物理范围投射 |
| 投掷冷兵器、轻型投射、弓弩、火枪、步枪、单发重步枪、机炮、能量武器 | 物理单体投射（道具自带动能，持有者不需要远程武器） |
| 法杖、魔杖 | 魔法单体，默认充能 |
| 剑、斧、长兵器、钝器、天生武器、召唤武器 | 没有对应道具，在道具位置上略过 |

后面的修正和效果词照技能写法理解，`淬毒飞刀:投掷冷兵器L5+中毒` 得到 `物理单体投射+中毒L5`；道具没有的修正（防御）略去并说明。

道具位置包括：

- spawn 与 unit_set 的 items；
- 带“充能/一次性”的 spec（`充能魔杖L5`）；
- give 写 type 为道具的，或同一回复 unit_set 的 items 正要把它交给单位的；
- give 写爆破装置的（用掉就没的爆炸物）；
- 改造道具时写武器规格的（形态不变）。

其余 give 写武器照旧是武器，如 `霜之哀伤:剑L7`。type 写 weapon、带附魔等武器专属属性、或同一回复换到 weapon、weapon2 上的，也照旧是武器。

### 4. 佩戴道具的防护

佩戴修正方向加上防护与单通道防护（`佩戴L5+4热能防护`），照样占佩戴预算。在抗穿计算里（`anchoredProtection`）与护甲、盾的防护修正相加：同方向只取最高的一件，合计仍限 ±10 点（±2 档），没穿护甲也有效。+4 热能防护使热能抗穿高 0.8 档。佩戴道具只存在于 V15 战斗，旧战斗里没有这样的道具，结算不变。

### 5. 写法容错（只换写法、不改规则，审批里说明）

| 正文 | 理解为 |
| --- | --- |
| `佩戴破甲L5` | 佩戴道具 `破甲L5` |
| `佩戴热能防护L5+4` | `佩戴L5+4热能防护` |
| `物理单体射击+6穿透L5` | `物理单体射击L5+6穿透`（只挪带点数的修正，`+减速` 这类效果词不动） |
| `buff治疗L3+振奋` | `buff治疗+振奋L3`（严格写法读不出修正时也走正文容错） |

### 6. 世界书与说明

- 条目 0 便捷属性：加 items，“items把道具交给该单位，写法同spawn的items，只增不减，收回用take”；“全部便捷属性格式示例”加 `items="治疗药水:buff治疗L3×2"`。条目 0 从 2282 字变为 2354 字。
- `lorebook system explain.md`：unit_set 字段表加 items；佩戴形态加防护例子；道具一节加佩戴修正方向、items 交道具规则、武器词条对照、略过与容错。

### 没有改

- 元素词：寒冷、冰霜、雷电等照旧不认，写了的那件略过；世界书教的冰系写法仍是“热能+减速”。
- items 里写近战武器（`青霜飞剑:剑L5`）照旧略过，不当成备用武器交给单位。
