# 执行规范

适用于交给 GPT 或其他执行方的所有规格任务。规格书与本文冲突时，以规格书为准。

## 1. 分工

- 设计决定由规格书给出。执行方负责四件事：实现、测量、在指定旋钮内调整、如实报告。
- 不重新设计。不新增机制、开关、配置项、兼容层或预留字段。
- 规格没写到的情况，按最接近的现有规则处理，并在结果文档的"未覆盖情况"一节列出。
- 规格内部自相矛盾时，停下来，把矛盾和两种可选处理写进结果文档，等决定后再继续，不自行选择。

## 2. 代码：不写防御性代码

- **只在信任边界校验。** 边界包括：正文 AI 的输入解析、存档或快照读取、玩家表单。内部函数之间的参数一律信任，不重复校验。
- **不为不会出现的状态写代码。** 不写多余的分支、默认值或报错。类型上保证存在的字段，不加 `?.`，也不加 `?? 默认值`。
- **不吞错误。** 不用 try/catch 吞掉内部错误。除非规格明确要求，不写"失败时回退到旧逻辑"。
- **一个概念只有一个函数。** 例如 `shieldUsable`。不另写"安全版""兼容版"。
- **被替换的旧代码直接删除。** 不保留注释掉的代码，也不留切换开关。旧战斗需要的冻结路径，按规格指定的版本判断保留。
- **报错文字只用于玩家的输入错误。** 写成一句玩家看了就知道怎么改的话。
- **注释只写规格编号加一句原因**，例如 `// R2 拒止：敌人进入触及范围时先刺一次`。
- **不顺手重构**规格之外的代码。

## 3. 测试：只测规格列出的

- **只写"必测"。** 单元测试只覆盖规格"必测"里列出的用例。每条用例写成一个断言或一个小测试；同类样例用表驱动，写成一个测试。
- **不做组合穷举。** 例如不写"每个特质 × 每级 × 每种模式"，也不写"逐级见证"这类大矩阵。
- **不测常量和大对象。** 不断言一张表等于它自己，也不对大对象做快照测试。
- **不补旧测试。** 不为规格之外的旧代码补测试。
- **同一行为只在一层测。** 不在引擎、面板、集成三层重复测同一行为，只在能测到它的最低一层测。
- **大规模对战是测量脚本，不是单元测试。** 放在 `artifacts/<版本>/`，不进测试套件。
- **新增测试文件只用规格指定的文件。** 只有修复回归时，才能另加一个回归测试。

## 4. 运行次数

- 开发过程中只跑相关的测试文件。全量测试在每次推送前跑一次；有失败的话，修复后再跑一次。
- 每个测量窗口：
  - 初值跑一次、最终复测跑一次，都用全样本；
  - 中间每调一个步长跑一次，用缩小的样本（规格写了就按规格，没写就用 1/4）；
  - 旋钮范围走完就停，不另外加跑。
- 代码没变，就不重跑已经跑过的测量；不为了"再确认一遍"重跑整套审计。
- 只保存结果表和复现命令，不保存每次运行的完整原始数据。

## 4.1 工具与证据

- `artifacts/` 整个目录不在 git 里，测量脚本和旧证据都只在 `D:\gbs`。几个审计脚本（`scripts/*commander*`）也只在 `D:\gbs`。
- 按规格列出的清单，把需要的文件复制到自己 worktree 的同一路径，只用，不提交。
- 不运行会改写旧证据的命令（例如审计脚本的 `--phase` 系列）。新数据写到规格指定的 `artifacts/<版本>/<run-id>/`。

## 5. 文档

- **每个版本只写一份结果文档，用规格书指定的文件名。** 不写过程记录、复核记录、交接记录或见证文档。
- **结果文档不超过 200 行，优先用表格。** 每项一行：状态、关键数字、证据位置。
- **不把工作量当成果写。** 测试条数、覆盖率、运行次数都不算成果。
- **不写防御性声明。** 例如"仅供参考""不代表全局""有限样本不能证明"。
- **未达标就直接写未达标。** 附上条件、数据和复现命令。

## 6. 向用户报告

- 先写结论，再写细节。
- 每项只用三种状态之一：已完成并验证、已实现但未达标、未完成。
- 不用"情况复杂""需要平衡""建议进一步观察"收尾。

## 7. 停止条件

| 情况 | 处理 |
|---|---|
| 旋钮范围用完仍不达标 | 记为"已实现但未达标"，继续做下一项，不自行加机制 |
| 规格内部矛盾 | 按 §1 处理：写明矛盾和两种可选方案，等决定 |
| 发现规格外的缺陷 | 在结果文档"规格外发现"一节写一行（现象、复现方式），不顺手修 |
| 测量耗时超过规格估计的 3 倍（规格没给估计时，以该窗口第一次运行的耗时为准） | 先缩到规格允许的最小样本，再报告耗时 |
