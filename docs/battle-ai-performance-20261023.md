# 战斗 AI 性能优化（2026-10-23）

基于 test `215a71c`（2.10.2），本次发布为2.10.3。优化本地战术评估，不调用模型API，不更改提示词、动态上下文、世界书或战斗规则。

## 修改

- `skill-tactics.ts`：同一次同步只读决策内，不对每次潜在行动估值重复序列化全部单位、技能和物品。决策范围结束、进入下一范围后失效；范围外保留实时状态变动检查。
- 相同上下文内复用完整目标状态相等的估值，条目及单条长度有界。治疗估值直接跳过无治疗效果的技能。
- `damage.ts`：伤害预览键按攻击者、守方、攻击参数拆分，共用内容完全相同的描述。保留完整JSON比较、原共享缓存和96次固定种子抽样，内存受限时回退完整文本。
- 普通武器的抽样基础参数不因成员伤口分布变化而重算；仍区分人数、状态、盾耐久、条件及屏障，实际伤损始终使用实时成员生命。火炮保留完整编队状态参与判定。

## 有限基准

Node v24.16.0，先以esbuild打包，再独立串行执行前后版本。场景使用V29、混合弓兵和长兵器、每单位20名成员、每人8项技能、同一固定种子，测一次单位行动；不含浏览器渲染、宿主保存和模型响应。

| 场景 | 原版 | 优化后 | 结果 |
|---|---:|---:|---|
| 4单位、LLM原地驻守意图下的技能选择 | 14,434.68 ms | 2,324.20 ms | 约减少83.9%，前后各199次独立预览，完整快照哈希相同 |
| 32单位、三方、每人8技能压力场景 | 超过数分钟后停止 | 28,408.85 ms | 原版未完成，不宣称精确加速比或该场景快照等价 |

4单位前后快照SHA-256：`e5f25bf118f140043aeba64e4aab3114556f802aac86f19f342294602994e11c`。

32单位结果说明密集技能场景仍需后续优化，不能把此次改动表述成所有战斗均无延迟。开发运行器vite-node也会放大热点开销，前期中止的开发运行器结果不用于加速比。

复现有限对比（PowerShell）：

```powershell
$env:BENCH_CASE='4-hold-skills'
node scripts/run-benchmark-ai-skills.mjs 215a71c
```

输出在 `artifacts/ai-skills/`。可选场景还包括8/32单位常规AI、32单位三方驻守、明确buff与道具意图；不默认把完整矩阵当作CI耗时门禁。`BENCH_TRIALS`默认1，计时仅作诊断。

验证结果：6个文件共88项定向测试通过，覆盖伤害96种子统计等价、伤口与护盾变化、大技能清单缓存、状态失效、技能估值、资源决策及指挥意图（包含原三轮回放哈希）。类型检查通过，原生构建生成74个文件。安装包校验检查版本、哈希和源码指纹。全量测试及远端CI未运行或查询。
