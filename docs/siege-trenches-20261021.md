# 建筑围攻、堑壕与任务选点（2.7.2）

基线为 `test` 的 `2e640d3`（2.7.1）。本次延续 [室内布局研究](indoor-layouts-20261020.md) 的实际空间、固定种子和真实 API 验证方法。地图变化仅用于新开战，读取已有战斗继续使用保存的地图、目标及战斗规则。

## 结构变化

| 场景 | 新组织 | 实际构造 |
| --- | --- | --- |
| 建筑围攻 | 单院、前后院、双翼夹院、曲折院落、内外院、破损院落 | 先确定独立院墙轮廓，生成可进入的主屋、院内分区与联络门，再放家具。外门与内门分开统计，保留独立状态和绝对方向。 |
| 堑壕 | 相对前沿、纵深防线、梯次斜线、突出部、分散支撑点、前伸支壕 | 两方壕系独立生成，每方前沿、后方与交通壕实际连通，中间保留无人地。支撑点之间通过后方相通；前伸支壕向无人地延伸。 |

不强制镜像、等距或对称房间。两翼长短、院墙退让、门位、壕线转折、支撑点和交通壕分别变化。继续使用现有墙、门、工事、掩体、瓦砾及结构破坏规则，没有增加地形战斗加成。

房间、院落及联络通道可以绑定完整实际区域。堑壕地点绑定真实前沿、后方或交通壕的一段，而非孤立地标。院内守军不会因院外掩体标记被拉出院墙；指定方向有本方壕位时优先使用。已毁主屋不再误摧毁整个外围墙门。新围攻和堑壕记录生成版本8；其他场景保持原生成版本。

## 固定种子比较

每类60个相同种子、相同尺寸，调用实际 `generatedLayeredField`。结构指纹保留完好墙、门、建筑、塔和工事，去掉低家具并合并水平／垂直镜像；指纹数和整体组织种类分别统计。

| 场景 | 尺寸 | 修改前完整几何／骨架 | 修改后完整几何／骨架 |
| --- | --- | ---: | ---: |
| 建筑围攻 | 11×17 | 56／1 | 60／59 |
| 堑壕 | 7×13 | 60／58 | 60／60 |

两类各六种整体组织都在本地抽样中出现。堑壕此前已有较多局部折线组合，因此不能只以指纹增加两种概括变化；本次重点是前沿与后方、支撑点和支壕的整体关系。另对野外、城墙攻防、城内巷战、室内各30张做同种子对照，120／120完整几何一致。任务选点的后续修复会改变新任务的位置，不重建这些基础地图。


## 护送、拦截与夺点

用户追加要求后，以六种院落、八种室内、六种堑壕及野外、城市攻防、巷战，两种种子、三种任务做138组检查。最初116组通过，22组失败：14组因关闭的门让中立夺点找不到共同区域，8组室内出口落在边缘隔墙。修正后138／138通过合法性、门路可达性、边缘出口及快照恢复检查。

- 默认护送／拦截出口沿实际部署的相反边缘选择合法落点，避开隔墙和不可达格。VIP 在城头时先按已有下地规则寻找地面接近路径，不把墙顶当作地面出口。
- 九宫格出口保持在指定方向的合法边缘；命名房间、院落或接应地点保留实际位置，在其区域内选择目标，避免把既有地点移到地图边上。
- 中立夺点按各参战阵营的实际部署与相同步兵移动成本选址，纳入第三方；评估可开启的门路时不修改真实门状态，不绕过完整墙体。
- 指定中立地点保留完整实际区域，旗帜位于合法代表格。中立夺点不附加固定 `attackingSide`，第三方仍可独占、被其他阵营打断并重新占领取胜。攻城夺点继续保留攻守规则。
- 地图用“出口”标出护送目的地，夺点保留旗帜，单格和多格目标均有实际区域标记；图例区分普通撤退箭头与护送出口。

支持三方夺点的既有记录见 [三方小战实现结果](small-three-way-result-20261018.md)。相关判胜规则此次未重写。

复现：`npx vite-node scripts/audit-objective-positions.ts`。结果为本地 `objectives-before.json`、`objectives-after.json`。

## 官方 DeepSeek 实测

只调用官方 `https://api.deepseek.com` 的 `deepseek-v4-flash` 兼容名。沿用用户已确认的 Flash 后续版本路由，所有响应实际模型均为 `deepseek-flash`，未切换 Pro。[官方模型说明](https://api-docs.deepseek.com/zh-cn/)

密钥只在运行时从用户指定文件读取，不保存到源码、报告、请求记录或安装包。正文为合成中文场景。测试直接使用产品 `LlmContextController` 的第一步决策、第二步布局、解析、真实生成、部署、开战及快照恢复；事实检查读取实际地图，不让模型自评分。

| 批次 | 真实场次 | 结果 |
| --- | ---: | --- |
| 十二种布局各两次 | 24 | 24场首次生成、开战及恢复成功；初轮定义的事实检查18场通过，发现紧凑翼房过碎、守军被院外地标拉走、内门误算外门等问题。 |
| 修正后回答重放 | 24份既有回答 | 24份通过扩展后的事实检查，包括各方从本方壕内开局；这是离线重放，没有新增请求。 |
| 布局修正后新请求 | 6 | 六场全部首次成功、事实检查通过，覆盖前后院、双翼、内外院、相对壕、突出部和支撑点。 |
| 追加护送／三方夺点 | 6 | 三场护送全部首次成功、事实检查通过；中立夺点暴露第一步缺少 control 选项，模型只能选 siege，其中一场室内无法开战。 |
| 补齐 control 后的新三方夺点请求 | 3 | 院落、室内、堑壕全部首次成功，正确选 control、绑定目标、不指定攻守方，三方可沿门路接近。 |

不将修正前失败从报告中删除，也不将离线重放计为新增实测成功。共39场真实准备、80次 HTTP 请求；有限样本不保证任意正文都能逐细节复刻。

复现命令（须显式提供密钥文件）：

```sh
npx vite-node scripts/audit-deepseek-maps.ts --key-file=密钥文件 --group=objectives --repeats=1
```

`--replay=已有报告` 离线重放，不读取密钥、不产生请求。原始回答与实际地图保存在本地 `artifacts/indoor-layout-research/` 的 `live-positions.json`、`replay-positions.json`、`live-positions-confirm.json`、`live-objectives.json` 和 `live-objectives-control-confirm.json`。

## 提示词与验证记录

后续用户要求一并修正地标显示与库存事件。地标列表保留名称按钮与定位，移除逐格坐标；库存按原叠的拆分来源而非同名物品查找，依稳定顺序从任一持有者扣除，支持四件全部给出后扣一件、两人各两件、一件加三件、跨回复及读档后继续扣取。原件耗尽仍保留短编号和后代来源；不同冻结属性及独立同名库存不混扣，超量失败不写入任何部分。
