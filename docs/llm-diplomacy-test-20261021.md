# 投降与双方撤军：实现及 Flash 实测

产品版本：2.9.2。测试日期：2026-10-21。

## 已实现行为

- 副 API 指挥官可以提出投降或双方撤军，也可答复另一个 AI 阵营的提议。所有协议只有两个参与阵营，无结盟、无独立发信、无三方协议。
- 发给玩家的提议会暂停自动推进，弹窗显示对方原话，玩家可同意、拒绝并填写回复。提议与答复记入战报；相关方后续指挥请求保留原话，拒绝后继续交战。
- 仅剩两方交战时，接受投降判接受方胜利，接受双方撤军判平局，保留实际伤亡。
- 三方战场中，接受投降只让投降 AI 方强制溃退，包括“不溃”单位，本场不再重整。两个 AI 阵营协议撤军时，这两个 AI 阵营溃退；AI 与我方协议撤军时，只让 AI 方溃退，我方所有单位保持原状态、由玩家自行撤离。未参与协议的第三方继续行动，溃退方在实际离场前仍可被追击。
- 后台预取可以准备外交决定，只有轮到发起阵营实际行动时才提交。提议、答复及强制撤退状态随战斗快照保存，重复答复不能重复结算。
- 提示词使用用户确认的简写工具 `diplomacy` 和 `mode/target/id/text` 字段，示例原话可自行替换或省略，原文备份见 [备份说明](prompt-backups/README.md)。

## 四组真实调用

使用桌面 `deepseek.txt` 的官方渠道配置。请求模型固定为 `deepseek-v4-flash`，9 次请求实际返回模型均为 `deepseek-flash`，全部 HTTP 200。没有切换 Pro 或其他模型。人设生成沿用 API 默认思考行为，战斗指挥使用非思考参数。

每组真实生成一次指挥官人设，再通过现有每阵营每大回合意图接口取得第一个决定。记录模型实际选择，不把“必须投降”写进测试指令，不用模型自评作为通过依据。这些是单个决策点的功能观察，不是完整战斗或概率统计。

| 场景 | 请求数 | 模型实际选择 | 引擎实际执行 |
| --- | ---: | --- | --- |
| 被玩家收买、手下精兵强将的指挥官 | 2 | 未投降。制定表面推进、避免深入和歼灭玩家军的计划；精锐队推进，指挥官固守 | 合法意图可推进指挥官行动，战斗继续 |
| 懦弱商人，四支护卫中两支覆没 | 3 | 主动向玩家提出双方撤军 | 模拟玩家同意后，立即结算为平局，实际伤亡保留 |
| 想体验被俘的成年女法师，第三方为好色哥布林 | 2 | 未提出投降。人设保留被俘幻想，同时优先自保；首个意图为后撤，并以哥布林为优先目标 | 合法战术意图执行，战斗继续 |
| 同一设定的女法师，第三方改为残暴嗜血哥布林 | 2 | 未提出投降。人设强调目睹残暴后避免向其投降；首个意图为推进，并以哥布林为优先目标 | 合法战术意图执行，战斗继续 |

商人实际交涉原话：

> 诸位军爷，小人只是行商，货可以留，命只有一条。双方各自撤军，各走各路，如何？

本轮输入共 36,636 tokens，输出共 8,623 tokens，包含人设生成及其思考开销。

四组接口、合法结果执行、快照恢复和我方不被协议强制溃退检查均通过。**本批模型响应仅主动触发了双方撤军，没有触发三方投降的接受链路；不能据此宣称真实模型已经走过该分支，也不能声称女法师必定因人设而投降。** 三方投降、AI 与 AI 撤军、拒绝及原话传递等行为由下述定向测试覆盖。
