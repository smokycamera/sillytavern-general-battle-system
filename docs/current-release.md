# 当前版本与工作区入口

当前发布版本：**2.6.8**。版本的唯一数值来源是根目录 `package.json`；本文、README、锁文件及安装清单应与它一致。

## 当前实现与安装

- 当前源码：`engine/src/`、`panel/src/`、`host/src/`、`runtime/src/`、`extension/src/`。
- 酒馆直接安装入口：根目录 `manifest.json` 和 `dist/`。`npm run verify:dist` 同时检查版本、文件哈希与源码指纹。
- `test` 为集成验证分支，`main` 为正式分支，使用同一份通过验证的构建晋级。流程见 [发布渠道](release-channels.md)。
- 产品版本与战斗规则版本分开管理。历史规则保留给存档和回放，不能据此判断当前产品版本。

## 2.6.8 的变化

- 修复同批 `give` 转移装备并用 `unit_set` 配装时，单位字段先执行而取不到原件，导致重复建档、重算属性或仅写名称无法入账的问题。
- 接收单位指向该件实物的配装在转移后执行，优先使用转来的原件；支持名称和实物编号，保留属性修正与冻结数值，旧装备卸下留库。
- 标签前后顺序不影响结果；同批新建单位、敌方接收和保存读回照常处理，不延后无关装备修改，出错仍整批回滚。

## 2.6.7 的变化

- `reforge` 新增一次性道具整叠改造，保留实物编号、数量、归属和来源；库存面板增加“改造道具”和“增加数量”入口，先预览再保存。
- 新增物品事件由 `give` 改为 `add`，支持武器、护甲、盾牌及所有道具。`add id="实物编号" qty="件数"` 补充同规格库存；唯一实物逐件保存，属性沿用冻结值。
- `give` 改为转移已有物品。可用 `to="u1,u2"` 同时交给多个单位，`qty` 为每个单位各得件数；原库存扣除总量，拆分保留属性，总量不足整批回滚。省略接收单位移回公共库存，已装备的先卸下。
- 接收单位可省略 `to=` 并放在标签属性任意位置；新增物品兼容 `id="单位编号"`。动态物品清单、内置世界书及对应说明按用户确认的内容更新。
- 正文事件兼容中英文引号、逗号、分号、冒号及全角标签符号；动态物品提示词精简为五行命令字段，世界书移除符号要求、默认数量和重复机制说明。
- 提示词的后续修改须先展示具体改文并获得用户确认，已写入仓库工作约定。

## 2.6.6 的变化

- 支持观察宿主保存状态时，流式回复的自动入账先准备候选档案与来源标记，共用宿主回复后的保存；独立读回核验后才确认成功。无能力、不同事件顺序或宿主未保存时继续使用原有保存与补写。
- 允许 MVU 追加变量更新块或状态栏占位符；消息身份、swipe 与战阵事件仍须一致。保留双方独立字段，不替换其他插件的变量或保存函数。
- 停止累积物品完整改造副本和单位逐次状态历史；旧档载入时清理已有历史，保留当前属性、装备、经验、伤亡和战报。操作去重只保留短摘要；刚转制的撤销备份在后续单位改动后释放。
- 详细机制和验证范围见 [保存合并与历史精简](mvu-save-history-20261020.md)。

## 2.6.5 的变化

- 修复非致命击倒编队后切回致命补刀，单位已阵亡却残留可救伤兵，导致“可救伤兵记录损坏或超出编制上限”并退出战斗界面的问题。
- 小战、会战与小战结束时的阵亡结算统一清零已阵亡单位的可救伤兵和伤兵累计余量，确保战斗快照及战果档案可以保存、恢复。
- 单纯切换规则仍保留已经濒死的单位及其伤兵，不补记阵亡；进行中的战斗继续使用保存的规则版本。
- 简化武器伤害说明，均值后不再追加“生命”；道具属性修正不再追加“格、步、点、抗穿”，百分比含义继续保留。

## 2.6.4 的变化

- 修复城墙、城门塌毁后，阵亡、濒死或已撤退单位残留平台站位，导致“平台站位数据不合法”、后台自动行动失败和战斗界面退出的问题。
- 读取旧存档时兼容上述塌毁平台的遗留记录，保留单位生命、伤亡状态、位置、战斗规则和战报；仍然拒绝真正损坏的站位数据。
- 城墙与城门上的存活单位继续按原规则落地并结算坠落损失，不重复处理已退出行动的单位。

## 2.6.3 的变化

- 单位资料、战场筹码、成员生命、行动预览、伤害明细和战报汇总中的数值最多显示两位小数，整数不补零。
- 数值按字段格式化，不修改角色与物品名称，不修改结算、存档和编辑输入的原始精度。

## 2.6.2 的变化

- 逐轮战报恢复普通武器和技能对七类结构的破坏记录，保留实际耐久变化与摧毁结果。
- 保留控制、治疗、屏障、推拉、驱散、资源与区域的实际效果，以及状态、临时能力、屏障和区域消失的过程。
- 战报省略效果持续时间、免疫原因、同类效果未追加、剩余物品件数和召唤行动时间；召唤保留名称与落点。
- 补齐未穿透、屏障吸收、实体盾碎裂、能量盾实际消耗、第三方最终状态和占点过程。
- 结尾城防只汇总受损、已毁及操作过的城门，省略完整墙段；过程中的每次破坏照常记录。
- 统一版本入口，隔离历史资料，清理重复构建与旧工作树。

既有归档保留保存时的文本，以上战报格式应用于后续生成的内容。
