# 当前版本与工作区入口

当前发布版本：**2.7.2**。版本的唯一数值来源是根目录 `package.json`；本文、README、锁文件及安装清单应与它一致。

## 当前实现与安装

- 当前源码：`engine/src/`、`panel/src/`、`host/src/`、`runtime/src/`、`extension/src/`。
- 酒馆直接安装入口：根目录 `manifest.json` 和 `dist/`。`npm run verify:dist` 同时检查版本、文件哈希与源码指纹。
- `test` 为集成验证分支，`main` 为正式分支，使用同一份通过验证的构建晋级。流程见 [发布渠道](release-channels.md)。
- 产品版本与战斗规则版本分开管理。历史规则保留给存档和回放，不能据此判断当前产品版本。

## 2.7.2 的变化

- 建筑围攻增加单院、前后院、双翼夹院、曲折院落、内外院、破损院落六种组织。先构造院墙轮廓、主屋与院内分区，再生成门和家具，不强制对称或双方等距。
- 房间、院落、联络通道绑定实际区域；守军的院内部署不会被院外地标拉出院墙。外门支持绝对方位，内门和外门分别放置、状态独立；主屋已毁不再连带摧毁外围墙门。
- 堑壕增加相对前沿、纵深防线、梯次斜线、突出部、分散支撑点、前伸支壕六种组织。每方前沿、后方与交通壕实际连通，留有无人地；开局优先占据指定方向内可用的本方壕位。
- 副 API 仅应用用户确认的 compound、trenches 字段说明及建筑围攻 city 行改文，以及后续确认的两方／三方夺点任务说明和第一步 control 选项，其他模板和示例保留，原文见 [提示词备份](prompt-backups/README.md)。旧回答可逐字段回退；只对新围攻和堑壕记录生成版本8，战斗规则版本不变。
- 护送与拦截默认出口选择实际可达的合法边缘，避开隔墙，支持平台 VIP 先下地；指定地点仍在其实际区域内选点。中立夺点通过现有可开门路评估可达性，不实际打开门，纳入第三方部署，保留三方独占、争夺和获胜规则。面板用“出口”区分护送目的地，单格或多格夺点均标出实际占领区域。
- 地标列表只显示可点击名称，移除整段逐格坐标。`give` 分配同叠物品后，`take` 可沿原编号扣除任一持有者的拆分份额，支持同批分配整叠再扣取、不同数量分配、跨回复与读档；超量仍整批回滚。
- 补齐 `unit_set` 的 `enchant`、`stabilized`、`protection` 便捷配置及新建单位的附魔传递，同批转移换装后应用到原件。修改当前装备保留身份、冻结种子及未指定属性；`enchant=none` 恢复武器默认伤害通道。
- 内置世界书的共用配置按用户最终修正改为四行“体型／载具武器稳定器／护甲侧重防护／武器属性”，保留其他正文与示例，完整原文已备份。
- DeepSeek 官方 Flash 实测、固定种子审计及验证细节见 [建筑围攻与堑壕报告](siege-trenches-20261021.md)。

## 2.7.1 的变化

- 修复同批 `take` 扣除已装备物品、已佩戴道具、角色随身及公共库存时，佩戴道具卸装漏传实物编号导致整批报错的问题。精确卸下所扣的那件，其他佩戴保留；任一步失败整批不应用。
- 同批 `reforge` 与 `unit_set` 换装先锁定原实物，重铸与转移完成后再穿戴。支持原件已装备、在本单位背包或公共库存，以及按旧名、新名或短编号引用；保留原件编号、改造属性与冻结种子，避免改出两件同名装备。
- 装备栏技能选择增加逐项删除与撤销，保存后才生效；取消不改档案。按技能实例删除，保留其他技能的数值、装备、精力及冷却次数；战斗中仍可更换上场选择，删除在战果提交后进行。
- 顶部当前装备与已装备卡片固定按主武器、副武器、护甲、盾牌、佩戴饰品排序。
- 提示词、动态上下文模板和世界书指令未修改，战斗规则版本不变。

## 2.7.0 的变化

- 副 API 的 `units` 支持按地点名称绑定单位，`unit` 可写一个短ID或短ID数组，让多个单位一起进入同一房间或驻守同一地点，不再限于单独行动。
- `place` 引用本次地点、桥或城门，`relation` 支持 `inside` 内部、`guards` 驻守附近、`near` 靠近；省略时房间采用内部，其他地点采用驻守。复用引擎已有的地点关系部署，房间以完整实际区域绑定。
- 地点绑定优先于九宫格 `at`；地点无效、重名或未能保留时说明原因，使用备用方位或本方部署。旧版方位回答与攻城岗位继续兼容，最多32个单位，包括第三方。
- 同地点的多名单位按整组计算占据容量；地点太小时沿用附近扩展与说明，避免逐人计算导致整组无法部署并在重试中丢失绑定。
- 提示词仅替换用户确认并修正的 `units` 说明，支持成组放置，其他提示词和示例保持。旧战斗不重建，战斗规则版本不变。

## 2.6.10 的变化

- 修复含旧版 `give item="…"` 同步历史或待审记录的存档打开队伍栏时抛错、整页空白的问题。
- 旧记录继续按新增物品显示，原 `id` 保留为接收单位；尚待确认的旧批次也沿用原含义。读取与切换页面不重新执行记录，不重复入账，原文、来源去重、单位与已有库存保留。
- 当前 `give` 转移已有物品的语义保持，战斗规则版本不变。

## 2.6.9 的变化

- 室内新增穿堂连室、主厅侧室、环形回廊、交叉通道、双翼联通、货架通道、走廊小室和破损连室八种空间骨架；住宅、客栈、寺院、仓库、工坊、办公设施、牢房和废弃建筑用途独立选择。
- 先生成实际房间，再连接房门、放置家具和高货架。本地生成也使用同一套布局，不强制镜像、双方等距或对称分房；房间分段、门位和家具独立变化。
- 副 API 可选 `interior:{use,pattern}`，旧回答仍可用。`room` 地点绑定完整房间区域，方向以房间整体位置匹配，较大的主厅保留足够空间；家具高度不会误写成地面高度。
- 只对新室内地图记录生成版本7，其他场景继续原有生成器。旧战斗地图不重建，战斗规则版本不变。
- 提示词仅应用用户确认的室内字段和示例改文，并按用户要求移除“正文未确定的项省略，由程序变化”；原源码与原室内提示词保存于 [提示词备份](prompt-backups/README.md)。
- 设计依据、真实 Flash 测试及其他地图的只读审阅见 [室内布局与地图审阅](indoor-layouts-20261020.md)。

## 2.6.8 的变化

- 修复同批 `give` 转移装备并用 `unit_set` 配装时，单位字段先执行而取不到原件，导致重复建档、重算属性或仅写名称无法入账的问题。
- 接收单位指向该件实物的配装在转移后执行，优先使用转来的原件；支持名称、实物编号及同批 `reforge` 改名后的名称，保留改造结果、属性修正与冻结数值，旧装备卸下留库。
- 标签前后顺序不影响结果；同批新建单位、敌方接收和保存读回照常处理，不延后无关装备修改，出错仍整批回滚。

## 2.6.7 的变化

- `reforge` 新增一次性道具整叠改造，保留实物编号、数量、归属和来源；库存面板增加“改造道具”和“增加数量”入口，先预览再保存。
- 新增物品事件由 `give` 改为 `add`，支持武器、护甲、盾牌及所有道具。`add id="实物编号" qty="件数"` 补充同规格库存；唯一实物逐件保存，属性沿用冻结值。
- `give` 改为转移已有物品。可用 `to="u1,u2"` 同时交给多个单位，`qty` 为每个单位各得件数；原库存扣除总量，拆分保留属性，总量不足整批回滚。省略接收单位移回公共库存，已装备的先卸下。
- 接收单位可省略 `to=` 并放在标签属性任意位置；新增物品兼容 `id="单位编号"`。动态物品清单、内置世界书及对应说明按用户确认的内容更新。
- 正文事件兼容中英文引号、逗号、分号、冒号及全角标签符号；动态物品提示词精简为五行命令字段，世界书移除符号要求、默认数量和重复机制说明。
- 提示词的后续修改须先展示具体改文并获得用户确认，已写入仓库工作约定。

## 2.6.6 的变化

- 支持观察宿主保存状态时，流式回复的自动入账先准备候选档案与来源标记，共用宿主回复后的保存；独立读回核验后才确认成功。无能力、不同事件顺序或宿主未保存时继续使用原有保存与补写。
- 允许 MVU 追加变量更新块或状态栏占位符；消息身份、swipe 与战阵事件仍须一致。保留双方独立字段，不替换其他插件的变量或保存函数。
- 停止累积物品完整改造副本和单位逐次状态历史；旧档载入时清理已有历史，保留当前属性、装备、经验、伤亡和战报。操作去重只保留短摘要；刚转制的撤销备份在后续单位改动后释放。
- 详细机制和验证范围见 [保存合并与历史精简](mvu-save-history-20261020.md)。

## 2.6.5 的变化

- 修复非致命击倒编队后切回致命补刀，单位已阵亡却残留可救伤兵，导致“可救伤兵记录损坏或超出编制上限”并退出战斗界面的问题。
- 小战、会战与小战结束时的阵亡结算统一清零已阵亡单位的可救伤兵和伤兵累计余量，确保战斗快照及战果档案可以保存、恢复。
- 单纯切换规则仍保留已经濒死的单位及其伤兵，不补记阵亡；进行中的战斗继续使用保存的规则版本。
- 简化武器伤害说明，均值后不再追加“生命”；道具属性修正不再追加“格、步、点、抗穿”，百分比含义继续保留。

## 2.6.4 的变化

- 修复城墙、城门塌毁后，阵亡、濒死或已撤退单位残留平台站位，导致“平台站位数据不合法”、后台自动行动失败和战斗界面退出的问题。
- 读取旧存档时兼容上述塌毁平台的遗留记录，保留单位生命、伤亡状态、位置、战斗规则和战报；仍然拒绝真正损坏的站位数据。
- 城墙与城门上的存活单位继续按原规则落地并结算坠落损失，不重复处理已退出行动的单位。

## 2.6.3 的变化

- 单位资料、战场筹码、成员生命、行动预览、伤害明细和战报汇总中的数值最多显示两位小数，整数不补零。
- 数值按字段格式化，不修改角色与物品名称，不修改结算、存档和编辑输入的原始精度。

## 2.6.2 的变化

- 逐轮战报恢复普通武器和技能对七类结构的破坏记录，保留实际耐久变化与摧毁结果。
- 保留控制、治疗、屏障、推拉、驱散、资源与区域的实际效果，以及状态、临时能力、屏障和区域消失的过程。
- 战报省略效果持续时间、免疫原因、同类效果未追加、剩余物品件数和召唤行动时间；召唤保留名称与落点。
- 补齐未穿透、屏障吸收、实体盾碎裂、能量盾实际消耗、第三方最终状态和占点过程。
- 结尾城防只汇总受损、已毁及操作过的城门，省略完整墙段；过程中的每次破坏照常记录。
- 统一版本入口，隔离历史资料，清理重复构建与旧工作树。

既有归档保留保存时的文本，以上战报格式应用于后续生成的内容。
