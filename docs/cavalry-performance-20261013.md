# 战斗与骑兵性能优化

2026-10-13，基线 `326fc53`。骑兵 AI 单次行动反复预览编队伤害并重复搜索冲锋路线，在主线程上形成长任务。

## 改动

- 冲锋路线改为一次有界 Dijkstra，取得所有预算内落点；同一次只读 AI 决策内按行动单位对象复用。保持最短路径、平局顺序、占位、禁冲锋地形与降落费用的原规则，仍在最短路线生成后校验冲锋地形。进入执行或重新决策前释放缓存，异常退出也释放。
- 可见单位在单次冲锋查询前取得，搜索扩展不再逐格读取并复制观测数组。
- 伤害抽样只读取“是否曾命中”和守方最终状态，省略编队攻击包汇总报表；命中的抽样结算也省略战报文字。保留96次抽样、全部攻击包、随机调用顺序与实际伤害结算。

## 性能与结果

运行 `node node_modules/vite-node/vite-node.mjs scripts/benchmark-cavalry.ts`。可在命令末尾提供 JSON 输出路径，或设置 `BENCH_OUT`。

场景：13×19开阔地图，4对4，20人编队，等级4、长矛轻甲，无技能；只测首个单位的 AI 激活。每种场景先热身一次，再运行三个固定种子，分别比较完整战斗快照的 SHA-256。前后使用同一 Node 运行环境，无 CPU 采样或方法计时包装。

|场景|改前中位耗时|改后中位耗时|降低|
|---|---:|---:|---:|
|分层地图步兵|210 ms|168 ms|20%|
|分层地图骑兵|646 ms|426 ms|34%|
|旧地图步兵|208 ms|150 ms|28%|
|旧地图骑兵|1543 ms|435 ms|72%|

12组快照全部相同。实际抽样计算次数也相同：分层步兵33、骑兵88，旧地图步兵33、骑兵89。改善来自减少冗余工作。

另一次带插桩的查询计数中，分层骑兵 `visibleCombatants` 从23729次降到530次，旧地图骑兵从126184次降到1212次。该运行的耗时不与上述无插桩中位数混用。

本数据用于比较此场景，不设为 CI 耗时硬阈值。AI 激活仍在主线程同步执行，规模更大、技能更多的战斗仍可能出现长任务。

## 验证

- `barrier-preview-cache.test.ts`、`hit-preview.test.ts`、`spatial.test.ts`、`grid-battle.test.ts`、`cavalry-ai.test.ts`：48项通过，其中新增一项连续骑兵激活与每次从独立快照恢复后行动的结果一致性检查，覆盖占位与状态变化后的缓存释放。
- TypeScript 类型检查通过。
- 原生扩展构建与安装包源代码一致性检查通过。
- `unified-replay.test.ts` 的5项历史回放失败，在未修改的基线代码复跑时出现相同失败及相同实际回合数，属于现有问题：human-four T1、giant-four T10、giant-four T6、giant-unbreakable T1、human4-vehicle2 T10。其余3项通过。

诊断原始数据保留在本地 `.diagnostics/cavalry-before.json` 与 `.diagnostics/cavalry-after.json`。
