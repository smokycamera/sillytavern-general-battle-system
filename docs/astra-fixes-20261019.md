# 历史记录、保存开销与长兵器警戒

根据 astra.txt 的三项反馈调整：

- 已同步和已忽略的剧情记录保留最近12条完整明细。更早记录转成来源键及去重凭据，避免重复入账；待确认、待补全、失败和过期记录不自动清理。下次正常写入时生效。
- 单位档案历史倒序显示最近12条，完整单位历史仍在存档中。战报不自动删除。
- 发送战报和读取提示词设置时只复制对应字段。载入及保存阶段的状态判断使用存档头和布尔查询，不再为存在性判断复制整份存档或恢复记录。恢复日志利用 IndexedDB 自带的结构化复制；内部不可变存档头不再重复复制。存档独立读回、哈希核验及聊天隔离仍然执行。
- 小战长兵器、重型长兵器主动警戒后，拒止命中额外+2；战报标记“警戒拒止反应”。仍与自动拒止、借机共用一次反应。加速行动设置的警戒使用其伤害倍率，AI路径风险计算使用同样的拒止命中加值。范围内移动的普通警戒攻击保持原规则。

性能范围：这次减少插件自身的历史明细体积及重复复制，没有改变宿主聊天文件格式。宿主完整消息保存与元数据写入仍可能随聊天长度变慢；未测量用户真实聊天的端到端耗时。

验证：6项针对性历史/拒止回归；保存事务和高楼层自动确认回归；TypeScript类型检查；原生扩展构建。
