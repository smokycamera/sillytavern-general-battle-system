# 3.0.6 城市封闭与墙头连接

3.0.7修订：用户澄清“相连”指生成时已经挨在一起的墙格，并明确要求去掉连桥。本次移除下文3.0.6新增的桥生成、专用显示与保护逻辑；相邻墙格沿墙头直接移动的现有行为保留，并用生成城市中的相邻墙格验证实际预览、移动与快照恢复。闭合修复、已确认提示词和战斗性能改动保留。

触边分区的双重城墙原来自动采用front：代码只要看见任一所选分区位于4×4分区外缘，就认定城区延伸出图，移除后墙。这是原先为大城局部防线保留的推断，不能代表城堡或整座城市也应开放。

本次取消该自动推断。明确的front继续开放，double及ring按完整城区轮廓围合，地图边格留给城外接近空间。旧式单一方位输入明确指定双重墙时也按围城处理。解析器保留显式layers，因此front加layers=2仍可表示双重正面防线。进行中的战斗保留原结构和规则，不重建地图。

内外门楼之间原来隔着一格地面夹道，墙头寻路无法跨过它。现在在对应门楼之间生成有平台的连桥，上层可移动、桥下可走地面，连桥受损毁后上层路线断开。分区与旧式城市输入共用该连接；命名地标不得覆盖连桥，显示按邻接墙头确定桥面方向。

副API提示词仅增加用户逐字确认的一句：“城市、城堡、营寨、院落和水域等区域，根据大小、位置和形状选择占据的分区及数量。”完整修改前源码已逐字节备份，见[prompt-backups](prompt-backups/README.md)。

战斗性能改动复用提交2fbb313，固定场景数据及96次抽样、快照一致性见[性能记录](battle-latency-20261024.md)。发布执行本地定向检查、类型检查、扩展构建及verify:dist；按用户要求不查询或等待CI，test构建直接晋级main。
