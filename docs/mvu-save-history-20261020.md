# 回复保存合并与档案历史精简

2.6.6 试用改动，基于正式版 2.6.5。不改变战斗规则版本和进行中战斗的结算。

## 回复保存

原生扩展只读取宿主 `/script.js` 导出的实时 `isChatSaving` 状态，不替换宿主或其他插件的保存函数。SillyTavern 与 TauriTavern 都有这个导出；导入失败、导出缺失或检测超时则保留原保存方式。

流式回复先结束生成、再发出 `MESSAGE_RECEIVED` 时，扩展在该事件返回前完成候选准备：检查原持久版本，写浏览器恢复日志，给回复补来源标记，将候选存档写入当前聊天附加数据。事件回调只等准备完成，磁盘确认在事件链外进行，避免宿主和扩展互相等待。

随后给宿主 600 毫秒的保存启动窗口；观察到保存后最多等 30 秒，读回核验候选存档和消息标记。即使保存太快、没观察到状态，也先读回，已经落盘就不再另写。宿主没带上候选时，仅在持久版本仍是原版本的条件下补写。其他进度、聊天切换和保存失败继续沿用原有冲突与恢复处理。非流式等不同事件顺序、手动扫描与手动批准继续独立保存。

MVU 可能追加变量更新块、状态栏占位符，并替换同聊天的附加数据对象。共用保存的来源核验允许战阵标签外正文变化，仍严格检查角色、swipe、发送时间、生成完成状态、唯一来源标记和战阵事件摘录。战阵事件被改动时撤销旧候选并产生人工确认，不自动执行改动后的事件。MVU 的楼层变量、聊天变量及其他附加字段不被替换。

## 历史精简

- 单位只保存当前档案、版本、精确装备/技能、经验与伤亡；不再追加每次编辑、补员和战果的状态历史。
- 物品保留当前实物身份和规格，不保存历次改造的完整属性副本；界面移除旧历史列表，备注照常保留。
- 物品操作的防重复回执保留操作编号与固定长度摘要，不保存完整请求参数。旧回执自动转换，早期重复操作仍能识别。
- 刚转制单位保留一次立即撤销所需的原档，之后发生单位改动即释放旧副本。
- 载入旧原生存档时单次写回精简结果；未完成保存与已交接脚本版的档案先按原恢复/交接流程处理。后续保存和导入也执行精简。
- 战报正文、开局、恢复战斗所需快照和去重身份保留。战报开局及迁移副本中的单位/物品编辑历史也会移除；只更新原来仍有效的重战状态守卫，不解锁已过期战报。

## 验证范围

新增回归覆盖 SillyTavern/TauriTavern 保存契约、MVU 前后监听顺序、异步状态栏写回、宿主不保存时补写、战阵事件变化、聊天切换、旧档载入清理及清理幂等。旧的单位与物品事务用例继续验证实物身份、数值和配装，改为要求不累积编辑历史。

`npm run smoke:mvu` 用真实构建产物和 Chromium 验证两种宿主契约，以及随消息更新和渲染事件异步写回两种 MVU 行为。宿主与 MVU 的事件/存储行为为模拟，不代表连接用户的实际酒馆或完整 MVU 安装。

本地 Chromium 四组 MVU 行为验证通过：正常自动入账各共用一次宿主完整保存，宿主不保存的下一条回复各补写一次；双方变量与来源标记均落盘。原有原生扩展浏览器流程 55 项通过，包含旧 pending 恢复、文件导入、交接、战报和移动端交互。

独立的 `verify:compatibility` 历史脚本在原始 2.6.5 与本版本均有相同失败：`verify-recovered-scenarios.ts` 的首个冻结数值预期为 5、当前为 6；`verify-native-compatibility.ts` 的冻结旧版回退快照字段不一致。本次不修改这些冻结夹具或扩大失败基线。当前原生旧档载入、改造历史清理、继续保存和重战守卫由新增回归及现有原生测试覆盖。
