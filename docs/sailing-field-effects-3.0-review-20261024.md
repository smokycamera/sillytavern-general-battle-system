# 3.0.0 两栖、航行与战场效果显示

## 实现与行为

- 保留 `water-crossing` 编号和原数值，只将规范名称“航渡”改为“两栖”。航渡、浮渡、泅渡继续解析，旧技能机制编号和历史快照不重编。
- 新增不可分级 `sailing`（航行），包括自带、祝福、技能、装备来源。小战的占位、移动消耗、寻路、闪现落点和攀登共用水域限制；同时具有两栖也不能上岸。现有水域移动消耗不改。
- 部署位置在陆地时，按曼哈顿格距寻找最近可用深水或浅水格；相同距离按格编号稳定选择，避开已占满的格子与敌军。先保留已有合法占位，校验在单位副本上完成；冻结开局和正常读档保留实际水格。
- 指定地图无可用水格时给出带单位名的错误，返回副 API 的原回答重试中，并明确要求增加、保留水域。第三次仍无法部署时，在同次开战中使用带水域的本地地图。大量航行单位的本地回退可以使用全场低地浅水，保留地物和高地；不更改已保存地图。
- 陷阱、火墙、毒雾、烟幕和治疗区域使用独立图案、图标、覆盖格和剩余轮数。格子详情显示等级、期限及平台信息；技能和道具共用实际保存的区域记录。
- 技能或道具授予工事后，按 `entrenchedAt` 绘制原单位的据守位置。离开显示“空置”，来源到期或被解除后移除；不创建额外耐久或替其他单位授予防护。会战按实际阵位显示。
- 自己放置的区域可在视线外识别；敌方隐藏陷阱不显示，敌方其他区域仍受现有可见性约束。到期和已经触发移除的陷阱不保留假标记。

## Review

本次进行了本地代码 review，检查了来源生命周期、部署原子性、排序和容量、城防平台、导航共用入口、读档边界、地图回退、显示可见性以及构建版本一致性。

已在 review 中修正：

- 室内底图尚未生成水域时不能提前部署航行单位。
- 城内守方的原部署区全在陆地时，仍须从原区域找到最近水格。
- 需要改位的航行单位不能先占掉其他单位已经指定的合法水格。
- 无水错误不能沿用“可以删去河流”的通用建议，也不能要求玩家重复点击开战才走到最终回退。
- 普通单位的移动路径不为新特质反复构造完整派生特质列表；查询航行来源时仍立即识别来源到期和装备变化。
- 多个区域重叠时优先显示工事文字，完整区域信息保留在格子详情。
