# rc.11 规划重试与诊断验收

基于 main `5927cdb50476ae8b6411b78152bd9e8580d2ebda`（rc.10）。

## 定位结果

- 旧评分请求任何一次异常都会立即丢弃 JEV 候选、显示通用失败，并进入 30 秒冷却。这能解释临时错误后反复回退，但不能单独确认用户设备的首个错误来源。
- 用户补充首次请求约 1～2 秒即失败，不能据此归因于 10 秒超时。旧提示隐藏了 HTTP 拒绝、CORS、宿主代理、协议和返回格式差异；没有用户设备网络日志或真实 Key，本次不宣称已确认其中哪一种。
- “保存连接并测试”只请求 GET 模型列表，不验证 POST 推理。新增真实推理测试可以在用户设备重现与区分这一差异。
- 另外，原单请求 10 秒与决策总计 12 秒预算会截断慢请求。对原 controller 运行新增回归，11 秒返回的有效评分未进入模型选择；修改后保留其置信度并完成规划。
- 10 个逻辑调用上限原来与连接失败共用回退分支，现改为保持本地评分，不再误报服务不可用。

## 修改

- 首次尝试之后最多自动重试 10 次，每次失败后等待 1 秒；耗尽之前仅显示重试进度。开战选择、评分、正文提取采用同一机制。
- 单次响应上限 30 秒，外层核心预算涵盖完整重试。卡住或忽略取消的传输也有明确时限，迟到响应不会被采用。
- 最终失败后只保留 1 秒探测间隔；后续规划会等待剩余间隔然后真正重新请求，不会立刻重复显示旧失败。
- 暂停、取消与聊天失效检查覆盖请求和等待阶段。仅模型读取重试，战斗执行、掷骰和保存均位于候选事务之后。
- 最终提示显示本地生成的 HTTP/代理/CORS/格式原因，不回显远端响应正文或 JSON 解析片段。API Key 仍仅保存在会话中。
- 新增“测试模型推理（调用 API）”，发送固定微型上下文，不读取用户战场/聊天，支持三种协议及同样重试；UI 明示 API 调用可能计费。
- 未修改 vendored JEV 核心或宿主网络权限。TypeSafe 格式与[官方 API 文档](https://docs.typesafe.ai/api)核对一致。

## 验证

- `npm run test:extension`：16 个文件、141 项测试通过。覆盖快速 HTTP 拒绝、十次重试耗尽、最后一次恢复、1 秒间隔与下一次恢复、具体错误与敏感正文隔离、11 秒评分、十次超时后恢复、取消和聊天失效，以及原有存档/自动推进行为。
- 传输、上下文和重试测试纳入 `npm run test:extension`。
- TypeScript 类型检查、扩展构建与 JEV 核心来源校验均执行；安装 dist 与清单同步为 rc.11。
- 没有真实 API Key、用户设备 WebView 和宿主运行环境，因此未验证用户现场 POST 请求。秒失败的实际 HTTP/网络原因仍需由新版推理测试确认，不能将重试等同于修复第三方拒绝或宿主 CORS 配置。
