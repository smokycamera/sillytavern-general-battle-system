# 战阵 UI 评审与待批准方案

日期：2026-09-26。基于 GitHub `main` 的 `85bb90e`（0.2.0-rc.13）和本次装备筛选修改。

## 已实现的功能调整

- 装备页仅显示当前单位的已装备物品、当前单位携带的未装备物品，以及公共无主物品。
- 排序为：当前单位已装备 → 当前单位携带 → 无主物品；每组内保留原顺序。
- 当前配装摘要移至单位选择器下方、批量操作和新建表单上方。
- 可以稳定选择“无主物品”，刷新视图时不会自动跳回首个我方单位。
- “发送全选／全不选”只改变当前显示物品，保留隐藏单位物品的发送状态。
- 未装备的自有物品可经“更多操作 → 放回公共库存”转移；仍须预览和确认，战内禁止。
- 切换单位时，关闭已隐藏物品的改造表单及待确认预览，避免继续编辑另一个单位的装备。

“当前单位物品”包含随身药剂和备用装备。否则卸下后的实物会从自己的界面消失，也无法管理战前携行品。

## 实际查看方式

先尝试 Windows Computer Use，窗口截图分别报 `FrameArrived timed out` 和 `window capture timed out`；按恢复流程刷新句柄并重试后，改用浏览器 Computer Use 成功完成评审。

查看的是本次构建的原生插件，运行于本地合成酒馆宿主；档案为“巡林队长／后备守卫／敌方哨兵”，没有读取或改写真实聊天。检查了默认约 854×620 视口及 390×844 窄屏、配装页上下部、切换单位、无主物品模式、队伍详情、新建装备表单、深浅主题。窄屏属于浏览器模拟，不是手机实机验收。

## 下面全部是待批准方案，尚未实施

保留现有深青灰底、低饱和金色点缀和战术面板风格。优先改善阅读与操作，不增加装饰性动画。

| 编号 | 实际观察 | 建议改法 | 验收标准 |
| --- | --- | --- | --- |
| U1 | 外层版本栏、内层品牌栏、导航、标题和长摘要逐层占高；默认视口首屏看不到物品卡片 | 原生模式压缩内层品牌区；配装摘要默认显示武器、防护、负载等少量关键值，规则解释可展开 | 默认视口能看到第一张已装备卡片；390px 下单位选择器和至少一个装备主要操作进入首屏 |
| U2 | 武器伤害、穿透、剑术说明、两套射程和负载连成段落，摘要与卡片重复 | 将伤害、穿透、射程、负载作为固定短字段；仅展示当前战斗模式射程，另一个放详情；特殊规则可展开 | 不读整段说明就能比较两件武器；完整规则仍可找到，不用省略号永久隐藏 |
| U3 | 物品名、数量、发送给 AI 复选框、归属标签同处一行；复选框和文字发生断行 | 卡片分为标题行、属性行、操作行；发送开关保持图文同组，归属/槽位单独排列 | 长中文名与大数量不会挤散复选框；390px 无横向溢出 |
| U4 | 装备、分配、改造、删除按钮权重相近；已装备卡片仍出现空的“更多操作”；自有物品出现重复分配操作 | 每张卡片只突出装备/卸下/使用这个主要动作；次要操作归入菜单；无实际内容的菜单不显示；不提供无意义的重复分配 | 卡片主操作一眼可见；删除保留明确文案与原有确认预览；菜单无空展开 |
| U5 | 桌面双列卡片受较长武器说明影响，同排短护甲卡片留白明显 | 将已装备、随身库存、公共库存作有标题的分组；关键属性对齐；长规则折叠后再确定统一卡片节奏 | 不靠阅读所有归属标签也能辨认分组；切换单位后分组与数量同步 |
| U6 | 暗色小号辅助文字、禁用操作辨识度弱；浅色面板外壳仍是深色 | 统一外壳和内容区的深浅主题变量；调整辅助文字、边框、选中态及禁用态对比 | 两套主题都人工检查并测量对比；正文以 4.5:1、明显大字和控件边界以 3:1 为设计验收目标 |
| U7 | 新增物品表单插入列表前，纵向推走装备；单位详情也包含长段规则 | 桌面考虑侧边编辑区，窄屏使用独立编辑页或底部面板；底部固定“预览结果”；基本字段先展示，高级配置折叠 | 编辑时一直知道当前单位和物品；取消后返回原滚动位置；不修改既有事务/预览语义 |
| U8 | 队伍页同时出现参战队伍、主控近况、编制与储存器，概念和入口分散 | 统一“当前参战”和“全部档案”的术语与入口；摘要采用相同属性展示组件 | 同一单位的生命、装备和状态在各页用词一致；历史档案不会被误认为本场参战 |

推荐先批准 U1–U6：主要是布局、排版和组件状态，收益明确。U7–U8 涉及更大的交互调整，建议单独确认。以上编号全部保留待批准状态。

- `npm run test:extension`：154 项通过。

- `npm run smoke:extension`：前段原生流程通过，JEV 阶段失败。合成服务只模拟 `/api/bridge/context`，当前客户端请求 `/api/bridge/select-context` 得到 404；未经修改的 `85bb90e` 安装包在同一测试中同样失败。此次没有修改 JEV 产品行为，也未宣称完整浏览器烟测通过。

实际 Computer Use 还确认了：巡林队长显示 5 件物品；切到后备守卫后显示 4 件且不包含队长的装备/药剂；无主模式显示 2 件公共物品。
