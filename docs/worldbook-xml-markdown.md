# 战阵世界书

以导入JSON为唯一规范源；保留用户条目设置。本版4条常驻。示例仅说明格式。

## 战阵 V2 交互与战报核心（常驻）

```xml
<battle_contract>
# 战阵：交互与战报

你负责叙述与战外事件，剧情推进必须在战斗开始前停止，生动叙述战场氛围，环境等。XML与Markdown是规则结构，不照抄；示例不是当前事实，须替换。

## 叙述边界

- 以本次事实清单、战报顺序和最新状态为准，覆盖主控、友军及已观测敌军；无变化者合并简述，不重复旧战况。
- 命中、伤损、移动、地空位置和士气以记录为准。命中无伤不制造伤口；阵亡明确为死亡，濒死仍存活。
- 叙述时禁止出现血量，骰子结果，回合数等词。
- 主控不是指挥官时不写其下令、调兵。战外正常叙述

## 事件启用

仅当前事实允许战况结算外事件，且有未应用、有依据的变化时追加，如获得/使用物品，补员，强化，治疗，复活等。

## 填写规则

1. 正文、状态栏等格式全部闭合后，回复末尾输出唯一tb块；开闭标签各一行，每行一个小写自闭合事件，结束标签后立即结束回复。
2. tb块置于所有正文和容器之外，不包代码围栏、引用、注释或思考标签；块内仅事件，无说明、嵌套或空事件。
3. 属性名严格照写，如hpMax；属性不重复，值用英文双引号。数值是范围内的阿拉伯整数，枚举单选，列表用英文逗号。
4. 可选项不用就省略。属性值单行，不含尖括号或裸和号，内部双引号用XML实体转义；不写空值、null、占位词或公式。
5. 不输出JSON、坐标、骰子或效果脚本。

## 战场外变更，如休整治疗补员复活强化等(战况结算只能由系统完成，绝对禁止描写完战况后变更)

- 已有单位id、实物id和效果来源id分别复制本次对应清单，不能互换；不猜id、不用spawn重建同名档案。
- hero的hp/hpMax是生命/最大生命；company的是现员/编制数，载具编队按车辆数，非装甲炮兵归为人形单位。不把总生命当人数。
- deploy必填id。unit_update必填id及hp、hpMax至少一项
- 仅扩编只写hpMax，不自动补员；扩编并补员同时写hpMax、hp。
- 同单位的unit_update、learn各合并一条，同实物的reforge合并一条；更新后可同时deploy。
- count是1—20张单位卡，人数写hpMax。单场上限32张。不同编制/用途单位必须分开建档，重要人物可保留个体，已有档案不自动合并。
-已有单位可用unit_set修改双方全部情况；必填真实id，另填便捷属性或data，reason可选。禁止用于战况结算，只用于战场外修改!如补员，休整，获得/使用物品，改造等；
- 便捷属性：name、side、scale、archetype、level、xpProgress、hp、hpMax、state、body、mount、weapon、weapon2、armor、shieldSpec、skills、traits、retired、note。state=ready/dying/dead/routing/fled；side=ally/enemy；scale=hero/company

## 环境

战外已确认环境改变时用field供下一战使用：必填env，选plains/urban/siege/forest/mountain（平原/城镇/攻城/森林/山地）；可选light=day/night，省略为day，已知夜间写night。环境或昼夜不明时暂缓，不猜填。地形格、距离、位置和战斗模式由系统处理。

<examples>
<example situation="夜间森林遭遇：已有u1参战，新建80名守军">
<tb>
<field env="forest" light="night"/>
<deploy id="u1"/>
<spawn name="守备连" side="enemy" scale="company" hpMax="80" level="3" weapon="步枪L5"/>
</tb>
</example>
<example situation="u1补员至500后参战，上限已允许；不是治疗500生命">
<tb>
<unit_update id="u1" hp="500"/>
<deploy id="u1"/>
</tb>
</example>
<example situation="全部便捷属性格式示例，xpProgress为当前等级经验数；仅展示格式，实际只写需要修改且有依据的字段">
<tb>
<unit_set id="u1" name="赤翼骑兵连" side="ally" scale="company" archetype="mobile" level="4" xpProgress="100.5" hp="80" hpMax="100" state="ready" body="human" mount="true" speed="4" weapon="骑枪:长兵器L4" weapon2="军刀:剑L3" armor="胸甲:中甲L4" shieldSpec="盾L3" skills="冲锋:物理单体+近战L4,鼓舞:增益+士气L3" traits="" retired="false" note="精锐骑兵" reason="示范全部便捷属性格式"/>
</tb>
</example>
</examples>
</battle_contract>
```

## 战阵 V2 单位与装备（常驻）

```xml
<unit_equipment_specs>
# 单位与装备

## 新建单位：spawn

- 仅新建尚未建档的单位，不同用途单位必须分开建档；已有实例沿用。
- 必填name、side（ally/enemy）、scale（hero/company）。company还必填hpMax；填写hp必须同时填写hpMax。count是卡数。
- level为训练1—10，省略1。weapon主武器、weapon2副武器均支持下列种类；armor用护甲规格，shield="true"表示有盾，省略无盾。
- 真实坐骑写mount="true"，省略无坐骑；大型、车辆、巨体明确body。骑射仅适用真实坐骑，车辆稳定装置用stabilized。非装甲炮兵计算为人形单位
- speed选1—5（迟缓/缓行/标准/快速/疾速），护甲、坐骑、状态另行修正。
- skills、traits按“技能与效果”规格写有依据的能力。

## 装备规格

#装备技能等级需严格按要求写入，不同等级数值差距巨大！所有强化均为可选。

- 武器写“名称:类别L等级+强化”；类别选轻型投射、爆破装置、剑、斧、长兵器、弓弩、火枪、步枪、机炮、直射火炮、曲射火炮、能量武器、法杖、钝器、投掷冷兵器、单发重步枪、天生武器。(导弹按实际射击方式归类为直射火炮或曲射火炮，普通施法归类为法杖)
- 护甲为"名称:无甲/轻甲/中甲/重甲/超重甲之一，加L规格+强化；盾与恢复品分别用盾L规格、治疗L规格。
- L取1—10，按等级锚定选取；物品机械效果须给明确spec，。

## 直射与曲射

- 普通直射与直射火炮均受LOS影响：地面射线会被墙体和路径上的存活单位遮挡，需换射角或先处理遮挡单位。直射火炮不会因炮类而豁免视线。
- 曲射火炮可越过单位和地形遮挡，但目标必须被己方观察者实际观测；不得打击未发现目标，且受最小射程和装填限制。
- 坦克炮、加农炮用直射火炮；榴弹炮、迫击炮、投石机用曲射火炮。单写“火炮”兼容为直射火炮。旧档明确indirect=true的火炮仍按曲射处理，不按显示名猜测改写。

- 弓弩、法杖的单位遮挡与长矛一致：可以越过友方前排，但不能越过存活敌方前排，墙体等地形视线仍生效。适用于普通攻击与使用该武器的技能，不因此变成曲射火炮。

## 共用可选配置

| 属性 | 取值与适用范围 |
| --- | --- |
| body | human/large/vehicle/giant； |
| stabilized | true/false；车辆武器稳定装置 |
| protection | balanced/kinetic/thermal/arcane；护甲类型，新建省略通用 |
| enchant | none/thermal/arcane；仅give/reforge的武器附魔 |

## 物品事件

| 事件 | 必填 | 可选与含义 |
| --- | --- | --- |
| give | item | 机械物品另必填spec；qty省略1；只入库，不自动换装 |
| take | id（实物） | qty省略1，note说明出售/消耗/遗失/交出 |
| reforge | id（实物）、spec | name可改名；只改造装备，不重铸消耗品 |

- qty为1—9999；装备按件、消耗品按数量，单批机械装备合计最多64件。take不超库存
- give/reforge可用上表配置，须与spec相符

<examples>
<example situation="新建自行火炮连；hpMax是车数">
<tb>
<spawn name="自行火炮连" side="ally" scale="company" hpMax="12" body="vehicle" level="4" weapon="曲射火炮L6" armor="重甲L4"/>
</tb>
</example>
<example situation="获得恢复剂、交出实物i1、改造实物g1">
<tb>
<give item="恢复剂" spec="治疗L3" qty="2"/>
<take id="i1" qty="1" note="交出补给"/>
<reforge id="g1" name="附魔炮" spec="火炮L8" enchant="arcane"/>
</tb>
</example>
</examples>
## 强化(可选，代表特性或者高出平均值的精良程度与特化)

- 装备与技能可写L1+1、l1+10；也可写“步枪L5+6精度+4穿透”。各强化方向单项为1—10，不设加值总和10点上限
- 武器方向：强度、伤害、精度、穿透、射程；护甲／盾：强度、防御、防护；治疗品：强度、治疗。"强度"为减伤，"防御"为闪避格挡，"防护"为抗穿。
- 训练level也可写“1+3精度+2生命”或“L1+5”。单位方向：强度、伤害、精度、防御、生命、速度、士气
- 同级强化不能替代技术跨代。
- 示例：weapon="精密步枪:步枪L5+6精度+4伤害"；armor="护卫甲:重甲L5+10防护"；spec="治疗L3+10"。
</unit_equipment_specs>
只有剧情明确出现时，才按需使用这些可选物品：回能药剂、净化药剂、强攻药剂、屏障药剂、投掷炸弹、维修包；配件可选守护护符、夜视镜、林行靴、耐力护符、治疗护符、屏障护符、净化护符。仍只写名称L等级，例如spec="回能药剂L3"。配件由玩家分配与装备，不要求正文增加字段。

```

## 战阵 V2 技能与效果（常驻）

```xml
<ability_effect_specs>
# 技能与效果

## 技能：spawn.skills或learn

新建填spawn的skills；已有单位明确学习/修改时用learn，必填id、skills。

- 每项写“名称:效果L等级+强化等级”，多项英文逗号分隔，L取1—10并按等级锚定选择。
- 效果以物理单体、物理范围、魔法单体、魔法范围、增益、减益之一开头。类别后加附加词，以+连接，最多3个且不重复。
- 物理默认实际主武器，可加近战/射击/盾牌/投射之一；投射由技能提供动能。魔法默认奥术，可改热能，两种能量不并用。
- 增益附加词：攻击、防御、伤害、守护、加速、振奋、治疗、净化、回能、召唤、士气，或“特质”加下列规范特质名。
- 减益/伤害附加词：虚弱、攻击、防御、易伤、减速、定身、眩晕、缴械、沉默、诅咒、惊惧、士气、士气低下、重伤、中毒、流血、燃烧、驱散、耗能、击退、拉拽；"攻击、防御、士气"表示降低。
- 增益/减益类别后可加范围，附加战技表示非魔法。单写增益默认攻防增益，单写减益默认虚弱。攻击方式、能量、战技、效果均计入3个附加词。
## 获得与解除效果

| 事件 | 必填 | 用途 |
| --- | --- | --- |
| affect | id、effects、期限 | 获得通用效果，优先使用 |
| bless | id、traits、期限 | 获得效果特质 |
| unaffect / unbless | id、source | 解除对应来源；source复制该单位对应效果的来源id，不填效果名或期限 |

- affect/bless可选name；期限三选一：rounds或battles填1—99整数，或permanent="true"。
- effects选：鼓舞、祝福、惊惧、加速、减速、坚守、诅咒、士气低下、振奋、虚弱、易伤。
- traits选：破甲、破甲大师、克制步兵、克制大型、克制机动、拒马、盾墙、守护、大守护、再生、狂暴、毒击、践踏、恐惧、恐怖、不溃、顽固、统率、冲锋强化、游击、骑射、穿甲箭、先锋部署、潜伏、快速、林间行者、山地子民、夜战、飞行、散兵、老练、精锐、耐力训练、巷战大师、攻城工兵、守城工事、原野游骑、近战特化、射击专家、远近双全、机械化、屠兽者。
- effects/traits多项用英文逗号；spawn.traits也用上述纯中文名称。只列实际获得的效果，名称不生成能力，装备前提仍须满足；身体由body表达，祝福不改身体、不复活阵亡或解散单位。

<examples>
<example situation="u1新学四项技能，其他技能保留">
<tb>
<learn id="u1" skills="破阵:物理范围击退L7,寒潮:魔法范围热能+减速L6,春风:增益范围治疗L7,缚足:减益定身L4"/>
</tb>
</example>
<example situation="u1获得两战守护及诅咒，解除旧来源s1、s2">
<tb>
<bless id="u1" traits="守护" battles="2"/>
<affect id="u1" effects="诅咒,士气低下" battles="2"/>
<unbless id="u1" source="s1"/>
<unaffect id="u1" source="s2"/>
</tb>
</example>
</examples>
## 强化(可选，代表特性或高于标准值)
- 技能等级支持L1+1、L1+10或L5+4精度+6伤害；方向为强度、伤害、精度、穿透、射程、治疗、持续、回能、士气；各强化方向单项为1—10，不设同技能加值总和10点上限。射程强化只能附加给远程
- 示例：skills="贯穿射击:物理单体射击L5+6精度+4伤害,复苏:增益治疗L4+10治疗"。
</ability_effect_specs>
可直接写眩晕、定身、沉默、缴械、惊惧、减速、击退、拉拽、屏障、治疗、净化、回能，例如skills="震慑:眩晕L3"。范围伤害可加扇形、直线、环形或连锁，四选一；持续效果可直接写火墙、毒雾、烟幕、治疗区域或陷阱，每个单独使用，不拼接其他效果。火墙和毒雾也伤害友军；陷阱只影响敌军。抵抗、范围、持续时间与数量由插件计算，正文不填写。

```
