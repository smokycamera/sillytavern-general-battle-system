# V6 统一生命、技能与战斗节奏（v1.2.0）

本版落实已验证的统一方案。新建单位和新战斗采用 V6；V2–V5 战斗快照仍按原规则恢复。手机定位、HTTP 局域网兼容与页面恢复修复保留。

## 默认数值

| 项目 | V6 |
|---|---|
| 训练 T1–10 基础生命 | 20 / 36 / 52 / 68 / 84 / 100 / 116 / 132 / 148 / 164，即 `16T+4` |
| 身体生命倍率 | 人形 1、大型 2、载具 6、巨兽 6 |
| 身体近战力量倍率 | 人形 1、大型 1.4、载具 1、巨兽 3；不加强远程武器 |
| 原型生命修正 | 乘身体倍率后加：步兵 +4、远程 0、机动 +2；然后应用单位生命强化 |
| P1–10 创伤预算 | 8 / 16 / 24 / 28 / 32 / 36 / 42 / 48 / 56 / 64 |
| 单体独立伤害技能 | 预算 ×1.5；武器/盾牌技法保留 ×2.2；多效果继续折扣 |
| 范围技能 | 预算 ×1.05；每张目标编队卡内分配给暴露成员，不重复乘出整份伤害 |
| 独立范围技能成员覆盖 | 4 / 4 / 4 / 4 / 4 / 4 / 8 / 16 / 24 / 32 |
| 榴弹额外溅射名额 | 0 / 0 / 2 / 2 / 4 / 4 / 6 / 12 / 16 / 24 |
| 基础交战展开 | 远程 20、近战 16，困难地形各减 4；参考人数仍为 50 |
| 生命硬上限 | 个体、单个成员均为 2000；编制人数和全队总生命不受此限制 |
| 武器伤害溢出 | 默认开启；武器直击余伤在同一目标编队内传递 |

百人编队在开阔地分别最多参与 40 份远程、32 份近战攻击；20 人编队为 20、16。同侧同阵位共享展开，拆成 40+35+25 不增加总参与量。炮组人数、重型平台及车辆的既有换算继续生效，不能理解为所有编队伤害统一翻倍。

穿透、防护、盾牌、暴击、训练伤害 `1+0.12(T−1)`、技能费用与冷却沿用原规则。巨兽基础攻防更偏近战攻击；护甲不会额外变成生命倍率。

## ±10 修正与技能口径

每个允许的方向都是 −10～+10 的整数，超出范围报错。同一来源的伤害/生命/治疗相关值按“本项 + 强度 + 实际匹配通道”每点 5% 换算，总倍率限制为 0.5～2。强度自身为 0.5～1.5。通道修正不创造额外通道；单位、装备、技能是不同来源，不能把各来源的乘积误称为全局两倍上限。

| 方向/效果 | 规则 |
|---|---|
| 精度、防御、抵抗 DC | 每 3 点一档，不足一档向外取整；DC 有既定边界 |
| 穿透、防护 | 通用与匹配通道合并，每点 0.2 档；合计限于 ±2 档 |
| 常规射程、速度、持续、回能 | 各自每 5 点一档；保持各机制下限和费用约束 |
| 生命 | 同一成员与个体使用同公式；最高默认巨兽步兵 988，生命 +10 与强度 +10 为 1976，不再被 1000 截断 |
| 武技强化 | 2.2× 与本来源最大 2× 可得到 4.4×；存档校验与执行一致 |
| 状态效力 | V6 为 0.25～1.5；弱化多效果技能不会生成无法保存的低于下限的效力 |
| 硬控制 | 正持续不会延长眩晕、定身、缴械、沉默；负持续可以缩短，至少一次 |
| 直接治疗 | 单体为创伤预算，范围为 65%，再分摊多效果并应用强化；P1/P2 同步为 8/16 |
| 屏障 | 保留 `8+5P` 等各配方预算与多效果分摊；强度影响容量，持续影响期限 |
| 持续区域 | 火墙、毒雾、治疗区域、陷阱每次基础值仍为 `4+3P`；同区域同目标每轮最多一次，伤害最多暴露四名成员；烟幕强度影响持续 |
| 区域附加治疗 | 与新生命曲线统一后再分摊、强化；`skill-zone-v2` 从原配方生成一次，读档不重复强化 |
| 召唤 | 继承本场版本；群体人数 `4+2P`，分摊同级单体的生命和武器预算；射程保留每点一格的专用规则 |
| 持续伤害、再生 | 保留自身骰子/比例和抗性；不用直接攻击预算重复放大，也不附送武器溢出 |
| 新消耗品 | 治疗/维修按新生命表的 25% 及品质、强化生成；屏障按对应公式。强攻效力、回能数值、炸弹伤害接受其强度修正；净化数量仍按原 1/2 项规则 |
| 已有消耗品、配件、明确自定义效果 | 保留已保存实例；不按角色训练升级或重新读取时重算 |

正文、手动编辑、`unit_set`、成员上限、技能学习与存档读取都使用相同版本的边界。逐级成长用同一名义生命差值，消除 ±1 等小修正取整后个体/成员不同步的问题；升级只提高上限，不治疗、不扩编、不重掷装备。

## 旧档升级与回退

在设置中选择“预览统一数值升级”；用旧档案开新战斗时也会先显示这份预览。确认前列出每个档案的生命上限变化，确认后保存完整原档备份。正在进行的旧战斗必须先收兵归档，才能升级；旧战报的重战仍按其原始快照和规则运行。

默认模板生命转换时保留已损失的生命点数；存活者在较低新上限下最低保留 1 生命，零生命不复活。编队现员、可救伤兵、身份、装备实例、资源和技能冷却账本保留。明显自定义的生命上限保留；历史版本没有保存“是否手工填写”标志，与旧默认或其旧上限截断值恰好相同的上限按默认模板处理，变化会在预览中显示。战外到新战斗的精力/冷却重置仍遵循既有部署规则。

旧巨兽武器在 V6 中按原配方、原种子投影新的近战力量；不改写库存实物。已知关闭随机的实例保留原设置，历史实例通过原骰子匹配识别；若取整使两种模式无法区分，采用常规原种子模式，可能与关闭随机的原型相差少量取整值；不认识的手工骰子与明确自定义武器保留。新装备记录 `balanceVersion: unified-v1`，避免重复应用力量。新规则技能使用 `skill-v6.0`，从原配方重建一次，不靠改名刷新冷却。

插件文件回退点为 `282fe4bed124bf62d4267a36686fdf6a28c8f3e3`（v1.1.2），见 [回退说明](version-rollback.md)。旧程序不认识 V6 标记；降级应同时使用升级前存档，不能删除版本字段冒充旧档。

## 验证与已知边界

原方案以固定 V5 引擎 `dc8b19d07bf8b57eb22d181308ea0b93a68ceb76` 做过 3088 场有效对照。本次没有把它们冒称为新提交重新跑过的全部对局；正式实现补充数值入口、正负强化、迁移、读取与发布检查。

`engine/tests/fixtures/unified-balance-replays.json` 保存 4 场真实 V5 快照及 4 场候选原型快照。测试比较回合数、行动次数、胜方、最终人员/生命/状态以及完整日志哈希；候选只适配版本标记，没有重算初始数值或改写预期战果。另覆盖 T1–10 四类身体、逐级小数取整、所有标准技能蓝图/效果方向的正负修正、独立范围预览采样、召唤分摊、旧档升级与备份恢复。

本次正式实现验证：1054 项单元/集成测试全部通过，5 项中继测试通过；类型检查、冻结生成/战斗基线与旧原生存档兼容检查通过。

保留的设计边界：纯爆发法师小队仍可能约 2～3 回合结束；低阶不溃重甲巨兽仍可能很长；完全打不穿仍可僵持。独立范围预算只在一张目标编队卡内守恒，多卡地图覆盖仍按既有几何和目标数量规则。本版改善常见战斗节奏，不保证任意配置都相同回合结束。
