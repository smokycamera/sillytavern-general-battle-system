# 3.0.3 移动、城区轮廓与组合技能审查

## 改动与兼容边界

- 新战斗采用V33：中甲／重甲／超重甲的额外穿戴移动倍率改为0.98／0.95／0.90，保留先攻、活动疲劳和实际负载处罚。V32及以前保存的规则不变。非战斗载入、档案实体化与快捷建人入口也同步使用新穿戴规则，避免资料页显示与入场移动量不一致。新档speed2、不受负担影响的重甲单位每次激活可进入相邻崎岖地，连续三次移动及存读档验证通过；没有在当前新地图中复现原先“两回合一格”的症状。
- V33环形以施放者为中心，选定的合法敌人参与结算且优先进入目标数上限；小战实际命中并附加惊惧，会战目标选择与存读档均验证。旧规则保留原有圆心行为。
- 括号外L作用于未单独标L的部分；独立等级保留在机制编号、配方和实际效果中。用户示例“物理范围L4+近战+环形+惊惧L2”的共享等级为4、惊惧为2。混合治疗L2、屏障L3、防御L4、守护L6在共享L5下，入场重建后仍保留各自等级。
- 城区不再逐分区预留完整小城，清理底图遗留的城外随机房屋。命名建筑和实际容量仍可能触发全图扩大，因此不承诺所有城市都很小。
- 正面墙可在地图中部连接，保留开放后方；双重墙的层数不再必然意味着四面围合。保存的君士坦丁堡第一份回答已离线重放，从封闭25×31方堡变为开放21×27双重防线；南北海面仍未还原。

## Z形与住宅区

原连接器从首个地块出发，逐个连接之后输入的地块。对已经连通的A1、B1、B2、B3、C3，如果先输入A1再输入C3，连接器会在尚未看到B1等地块时添加C1、C2。这是程序bug。现在先读入全部选定分区，再对真正断开的连通块补最短干地连接；起点与搜索顺序固定。全部120种输入顺序得到同一个五地块轮廓，水域阻断与输入顺序也有对应验证。

建筑围攻明确提供`city.at`时，围墙沿选定分区并集外缘构建，保留凹口；为城外接近空间保留一圈地图边格。内部用实际连通面积递归分割房间与院落，并在隔墙上开门。切分前检查两边连通，入口、内部房门与目标周边保留通路。原`compound.pattern`在此路径上仅提供内部方向及房院倾向，不把外形套回矩形。未提供`city.at`时仍使用原六种骨架。

同一五地块Z形、同一courtyard参数连续24个种子生成，均为11×17，共20种不同的房间／门位结构；24/24内部连通且轮廓在指定分区内。前六个连续种子的示意图为本地`artifacts/z-outline-20261024/z-variations.png`，完整摘要为同目录`summary.json`。8个种子另经过8人实际开战与快照恢复，命名房间与院外广场验证各自保留在墙内／墙外。此轮不新增API调用。

这些检查证明指定轮廓可以变化内部结构，不等于所有历史建筑都已准确还原。旧历史文本没有指定院落范围时仍可能走旧骨架；威尼斯海岛水道、骑士堡的建筑比例、塔楼住宅形制、窗户与楼层几何仍有[历史审计](historic-map-audit-20261024.md)记录的偏差。
