# v1.4.0：地图生成 v3 与副 API 地图/VIP 选择

## 使用

设置 → 上下文与开战配置 → 普通 LLM 读取上下文。

- 「由 LLM 选择战场规模」保持原设置。
- 「由 LLM 设计地图」：默认关闭；开启后结合已完成正文、单位名单和单位备注，在同一次开战请求中选择九个地图参数。
- 「由 LLM 选择护送／拦截 VIP」：默认关闭；可独立于地图设计开启。护送选择我方，拦截选择敌方。

三个开关独立保存在本机全局配置，不绑定聊天/角色。手动模式下禁用。开关改变会取消尚未完成的开战配置；不会重生成已经开战或读档的地图。新增选项不增加请求次数，但会增加请求与返回的 token 数。

## 本地地图

所有新建格子地图使用 v3 生成器，不依赖副 API。平原、森林、山地、城市、攻城、室内采用六类布局骨架：分散片区、条带巷道、交叉通路、环绕空地、偏置据点、破碎地形。骨架与朝向、覆盖密度、长短墙段、地形片区、宽窄通路和局部地标组合，而不是只加随机散点。

保留非对称设计、独立地图随机源、同种子复现、日夜不改地形、自然野外不凭空建墙。两条不会共用格子的安全通路可以跨越中线，路上允许森林/山地等可通行地形，不再强制铺成固定左右两条纯空地。宽路只扩展主路肩部，避免小图被清空。

标准图保留双方前三排部署容量；室内按本场真实名单保留必要部署；明确部署额外避让。攻城防线和目标跟随守方；地形生成后只局部开缺口连接孤立区域。开放地面保持超过 25%。部署和任务出口的安全优先于模型密度要求。

当前仍只使用既有 open / cover / rough / forest / hill / wall 六种真实地形规则。没有增加水域、桥梁、多层高度、可破坏建筑等未实现机制。军团会战没有格子地图，因此不应用地图/VIP扩展；原有环境、规模及指挥选择继续工作。

## 副 API 合约

九个地图字段：布局、主要朝向、主题地形密度、掩体密度、墙段密度、路线形态、主路宽度、局部地标、地标相对位置。地标坐标使用上敌下我，左/右按画面；不以进攻方翻转。字段均为有限枚举，模型不能输出逐格数组、执行代码或更改单位数值。

VIP候选来自 hp > 0 且状态 ready 的对应阵营。模型使用 unit_0 等临时别名；实际 ID 只在本地映射。不存在/阵营错误/死亡/溃退对象无法成为任务目标。超过 31 个候选或重复 ID 时不截断名单猜测，沿用默认选择。无明确依据可选择 default。任务生成时再次验证资格。

地图扩展返回缺项或非法枚举时，整份地图设计回退本地随机；VIP无效时沿用主控优先、否则首个合法对象。回退原因在开战摘要展示。必需的环境/指挥字段无效、网络失败、取消或准备信息变化仍然不直接开战。关闭的功能忽略模型擅自返回的字段。

地图 tiles、实际解析后的设计记录、任务VIP及出口随快照冻结。战斗快照仍为 version 2；旧 7×9 / 7×11 / 7×13 / 5×7 地图无需新增 generation 元数据。

## 验证入口

`npm test -- engine/tests/field-generator.test.ts engine/tests/map-design.test.ts panel/src/llm-context.test.ts panel/src/llm-map-design.test.ts panel/src/llm-settings.test.ts panel/src/battle-setup.test.ts panel/src/main.integration.test.ts`

新增压力测试覆盖六骨架 × 五环境标签 × 四尺寸 × 二十种子 = 2,400 张定向地图。每张检查复现、连通、开放面积，以及逐一堵住任意内部通行格仍存在上下贯通路线。另有密度实际效果、无效参数、存档冻结、独立开关、一次请求、候选过滤、旧配置、无效返回和取消回归。

完整测试与主分支已有失败的对比见本次 PR 说明。第三方真实模型的语义理解质量不由 mock 测试保证；实际仍取决于所选模型和正文信息。
