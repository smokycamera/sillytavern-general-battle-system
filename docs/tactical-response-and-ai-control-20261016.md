# 战斗点选响应与「除主控」托管

2026-10-16。

## 行为

- 将战术地图及旧式小战界面的「我方」托管选项改为「除主控」。开启后，绑定的主控保持手动，其余我方单位默认由 AI 行动；没有绑定主控时默认托管全部我方。
- 「此单位」仍可单独调整任意我方单位，包括主控。切换「除主控」会清除单独设置；「全自动」包含主控并连续推进，关闭即暂停。
- 沿用原来的 `autoTurn` 存档字段，无需迁移。主控根据 `protagonistId` 判断，士气锁及指挥官身份不参与这个判断。

## 点选响应

之前每次切换行动类型、点选单位或目标，都会重新生成整套行动菜单。带有多个技能、范围预览的单位会重复计算大量预览；地图下拉选择还会进入界面任务锁。

现在由面板持有 `TacticalQueryCache`，在同一个未改变的战斗状态下按单位复用菜单。点选按钮与地图下拉选择直接完成只读更新，不进入保存队列。事实操作、AI 行动、保存和恢复之前清空缓存，换战斗或单位对象后重新查询。此缓存仅供面板查看使用；引擎与 AI 决策不使用跨操作缓存。

## 验证

相关 7 个测试文件共 22 项通过，TypeScript 类型检查通过。覆盖绑定主控、单独托管、全自动推进与暂停、旧存档恢复、保存中取消托管、读档与行动后重新计算、技能更换、移动反应及点选不写档。补充修改了回到当前行动单位时的缓存传递，相关两个文件的 11 项测试再次通过。

扩展 `scripts/benchmark-tactical-clicks.ts`，加入同输入的缓存/未缓存逐次 HTML 比较及战斗快照哈希检查，`--skills` 场景每单位准备 5 个技能。13×19 开阔分层地图、每编队 20 人、4 级长矛与轻甲，30 单位骑兵的同步点选加 HTML 生成中位耗时为 59.0 ms → 9.8 ms。原始结果为 `artifacts/tactical-clicks/cached-skills-20261016.json`；这是本机 Node 测量，不包含 DOM 和绘制。
