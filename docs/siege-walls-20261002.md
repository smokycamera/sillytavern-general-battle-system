# 攻城城墙形制与深水过河点（2026-10-02）

现象：攻城地图几乎总是只有一面城墙；有时生成一条横贯全图、没有桥的深水河。

## 原因

1. **第2步没有城墙形制可选。** 城写在 N/S/E/W 或角落时，生成器固定只在朝向地图中央的一面筑墙，只有写 C 才四面有墙。模型几乎总把城写在一侧，所以总是一面墙。正文写“三层城墙”也无从表达。
2. **这一面墙两端到不了地图边。** 城区四周各让出一格，墙的两端和城后各留一条一格宽的空地。攻方可以绕过墙端，从城的侧面走进城；城在角落时只有朝西的一面墙，南面完全敞开。原来只是在部署时把攻方限制在墙正面，开战后照样能绕进去。按当前源码统计，城不在中央的 384 张攻城图全部可以不破墙走进城。
3. **零桥的深水线没有任何过河点。** 提示词写“bridges 写出全部桥梁，[] 表示没有桥”，正文没提桥时模型常写 `[]`；生成器照做，于是一条贯穿全图的深水河或护城河把双方隔开，没有航渡能力的单位过不去。护城河默认的两座桥也与城门无关，固定放在左右两侧。

## 修改

### 城墙形制

第2步的 city 新增 `walls`，按正文选：

| walls | 含义 | 生成结果 |
| --- | --- | --- |
| `front` | 大城的一段城墙 | 城区延伸到正面以外的所有地图边，城墙从地图一边连到另一边；城在角落时两面筑墙成直角 |
| `ring` | 小城、城堡、营寨 | 城区离开地图边，四面都有墙，攻方可以绕到侧面和背后 |
| `double` | 多重城墙、内城外郭、瓮城 | 外墙后隔一格夹道再筑内墙，攻城核心在内墙之后 |

- 城区每一条不贴地图边的边都筑墙。河流把城区挤离某条地图边时，那一侧也筑墙，不再留缺口。
- 两重城墙：每座外门在内墙上配一座对应的门；外门开战时已毁，内门仍关闭。外墙的登城梯在夹道一侧，内墙的在城内一侧。战区放不下两重墙时改为一道，并在“查看布局依据”里说明。
- 未写 `walls` 时按种子选：一段城墙 45%，四面城墙 35%，两重城墙 20%；城在中央时总是四面城墙。不用副 API 的本地随机地图（城门前沿）也按这个比例变化。
- 城墙正面取攻方开局方位所对的一面，没写时取城外空地最大的一面。写了方位的城门开在那一面墙上，例如“东门”开在东墙。
- 守军上墙时优先站在正面城墙上。四面城墙和两重城墙原来会有人开局就站在后墙或内墙上；只有一面墙的城不受影响。
- 开战摘要的战场一项加上形制，如“城墙攻防 · 中型 · 君士坦丁堡在南 · 两重城墙”。
- 等级字段在提示词里改名为 `level`，旧的 `wall` 仍然读取。MCP 与手动 JSON 可用 `shape`（front 为一段城墙，enclosure 等为四面城墙）和新增的 `wallLayers=1|2`。

### 两重城墙的 AI 与规则

- 攻方进了夹道不再算“已进城”。它只攻打仍挡在自己与核心之间的墙：在城外打外墙，进了夹道打内墙，不会回头拆外墙。
- 夺门只能从门的内侧：外门从夹道，内门从城内。单层城墙的规则和 AI 不变。
- 城区记录新增可选的 `terrace`（夹道格），旧存档照常读取。

### 水系与桥

- 提示词：bridges 只写正文提到的桥；没提到就省略，由程序配桥；`[]` 只用于正文明确无桥可用。
- 深水河或护城河上没有完好的桥时（写了 `[]`，或桥都已断），留出两格浅滩可涉水：护城河留在城门正前方，河流留在与任务目标对齐处。不新增桥，回答写的桥数照旧校验。
- 护城河改为离外墙一格（原来空两格）。没写桥时每座城门前配一座桥；写了桥但没写位置时，按城门顺序放在门前。
- 攻城时只写了 water、没有写河流的计划（MCP 与手动 JSON）改用同一套水系生成，不再走旧的随机横河。
- 开局不站在浅滩里：和桥一样，浅滩是双方争夺的过河点。
