# 战场生成与正文空间关系：首轮实施说明

2026年9月30日。基于 `a7db2b8` 工作区，修改新战斗的准备与战场空间规则。

## 已落地的准备链

正文取材 → 带出处的场景事实 → 本地空间编译 → 城市、水系、道路与地标构建 → 高度初始化 → 部队部署 → 约束核验 → 冻结战场快照。

副 API 仍只提供有限的实体和关系，不生成逐格地图，也不修改单位能力。`scene-intent-v1` 区分正文明确事实 `explicit` 与合理补全 `inferred`，明确事实须引用本次请求实际发送的段落。准备时检查出处编号、实体引用及参战单位短编号，再在真实生成的地图和部署上检查可执行的空间条件。

长正文保留空间设定与近期变化，不再只取每条消息的尾部。提示词要求识别否定、回忆、假设和计划，以最新明确状态为准。出处验证能检查引用是否合法；系统没有独立的语义模型证明每项返回事实都由该段正文蕴含。

旧副 API 地图协议继续可读。返回显式空场景意图时可以没有地标；缺少有效意图和旧地标会中止本次地图准备，避免用固定地标掩盖遗漏。

## 地图布局与部署

- 城市位置采用绝对方位，支持上下左右、四角与中央，攻守身份不翻转这些方向。城外野战可以保留城市及其城门，任务仍按野战准备。
- 城区先铺街路与入口，再构建整块建筑、院落、市场或仓储区域。连接院落时只清理普通建筑，完整城墙和城门保持其结构含义。
- 城市、水系和桥头共同预留空间。河流是连续边界，桥梁按逻辑实体计数；双格桥仍只算一座，断桥保持不可通行的状态。明确零桥时不留额外过河缺口。
- 桥梁和城门支持独立数量、位置及状态。地标引用实际设施，城门实体编号贯穿编译、建造和标注，避免多门场景中名称与开闭状态相互错配。
- 真实中心与河岸采用不同定位规则。地标在请求区域内寻找合法位置，并记录局部调整；无法满足明确条件时重新选择有限的本地候选或扩容，仍失败则报告原因。
- 部队可驻守、占据、位于地点内部，或从指定岸区接近。单位关系与阵营关系绑定到实际地标区域；桥头驻守会检查通达性，并按完整名单扩大近旁防区。
- 地图准备后冻结初始部署，开始战斗复用同一位置和表面，避免预览与正式开局重新掷出不同部署。容量不足时扩容，不丢弃单位卡。
- 正文的争夺地点可绑定占领任务，包括攻城场景；指定出口可绑定护送或拦截任务的撤出地点。普通撤离边缘按实际部署方位推导。

场景词表目前注册21类原型，包括老城、市场、仓储、滨河、山城、城门前沿、城外、农田、渡口、缓丘、林道、林溪、林缘、山口、谷地、台地、住宅、大厅、堡垒、前沿壕线和纵深堑壕。它们组合现有场景骨架、街区规格、水系、植被、道路和高差；本次没有做全词表的平衡或统计多样性验收。

## 实际高度与显示

新生成地图使用 `spatialRulesVersion: 2`。`groundHeight` 保存0—3级自然地表高度；平台高度和桥面高度单独存储，单位站立高度由地表、结构和所处表面共同决定。

- 高地周围生成逐级坡脚；同高度台面可正常移动。上坡增加移动消耗，陡台阻断跨越，明确坡道或阶梯可连接高差。
- 路径预览、实际移动及 AI 的反向寻路使用相同的有向移动成本。
- 视线计算射线穿过格子时的高度；地形与结构遮挡按实际海拔判定，塔楼观测使用平台高度。
- 近战接触、高地防御和友军射线遮挡采用相对高度，避免只因地形名是“山地”就重复施加固定修正。
- 推拉落下台地或平台会显示并结算坠落损失；结构坍塌保留自然地面高度。
- 范围效果与持续区域在新地图中考虑高差、表面和视线。

界面显示高度数字、等高边界及坡面提示。查看格子显示实际高度和通行原因；点击地标定位并突出其完整区域。方向标注固定为上北下南，撤离提示读取本场边缘数据。

旧快照没有空间规则版本时保持原有地形、平台和观测规则，加载不会重新生成地图、部署或海拔。本次采用一层地面加既有平台，不实现完整的多层建筑。

32卡示例、界面截图和检查记录位于本地 `artifacts/scene-rework-preview/`。这是本地场景与渲染验证，没有宣称已完成真实宿主或真实副 API 的端到端验证。本次没有运行完整测试套件、批量地图审计或长程战斗平衡模拟。

交付构建命令为 `npm run build:extension`，生成原生候选包 `release/native-candidate/` 并同步仓库可安装的 `dist/`；`npm run verify:dist` 检查打包内容与当前源码一致。实施说明与设计方案一并收入候选包。

## 代码入口

首轮战区编译范围为一座城市、一条主河、最多四座桥、四处门和五个主要地标。更复杂的正文需要选择局部战区；无法落实的明确约束会保留为准备失败原因。

## 副 API 提示词精简与浅水修正

同日按用户要求清理开战准备与目标抽取提示词，移除属性效果、本地扩容、纠正位置、旧字段兼容和保底处理等说明，统一输出格式要求。新地图请求采用 `battlefield.intent`，桥门和地标统一填写实体；明确空旷可以返回空实体列表。旧答案兼容由解析器处理。

水域说明明确写为：`ford代表浅水，可涉水的浅滩`。场景编译中保留用户或副 API 已选的 `ford`，避免 `river` 实体把浅水覆盖为深河。地图提示词长度较清理前减少约30%。

本次只执行两个直接受影响的用例：实际开战请求包含浅水说明，以及带河流实体的 `ford` 场景生成可通行浅水，均通过。当前提示词及占位请求结构导出到本地 `artifacts/api-prompt-review-20260930/`。

## 当前行动单位的地图点选

查看另一名友军后，点击地图上的当前行动单位会直接恢复该单位的操作。这个返回操作优先于正在查看的友军的移动或治疗选点，避免点击被当作落点或治疗目标；点选只改变界面选择，不消耗行动或修改战斗事实。
