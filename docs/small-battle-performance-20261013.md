# 小规模战斗第二轮性能优化

2026-10-13。在同日已完成的骑兵寻路与预览优化之上继续减少伤害抽样开销。

## 改动

- 实战和预估共用单段攻击的命中、伤害计算与伤损提交规则。预估只返回是否命中，并更新抽样副本，跳过完整攻击结果、骰子审计明细和伤损报表的构建。
- 伤害骰增加仅取总值的路径，保留取高/取低、固定加减值、暴击倍数及随机数调用顺序；实际战报仍使用完整骰子记录。
- 同次编队抽样攻击的各攻击包复用参数对象，减少逐包对象分配。
- 保留96次抽样、所有攻击包、AI候选范围与估值公式。

## 对照结果

运行 `node node_modules/vite-node/vite-node.mjs scripts/benchmark-cavalry.ts <输出JSON路径>`。
沿用13×19开阔地图、4对4、每队20人、等级4长矛轻甲无技能的场景。每种配置热身一次后测量3个固定种子，取单次AI激活的中位耗时。优化前基线包含上一轮尚未提交的优化，与Git HEAD不同。

| 场景 | 本轮修改前 | 本轮修改后 | 降低 |
| --- | ---: | ---: | ---: |
| 分层地图步兵 | 157 ms | 116 ms | 26% |
| 分层地图骑兵 | 446 ms | 332 ms | 26% |
| 旧地图步兵 | 150 ms | 109 ms | 27% |
| 旧地图骑兵 | 427 ms | 297 ms | 30% |

12组完整战斗快照SHA-256全部一致，各组实际抽样计算次数也全部一致。诊断原始结果在本地 `.diagnostics/small-battle-before.json` 和 `.diagnostics/small-battle-after.json`。

这是本机Node引擎基准，不代表浏览器帧率或用户实际存档的延迟。单次AI仍同步运行，骑兵场景仍接近300 ms，因此本轮减少卡顿，但没有消除主线程长任务。
