# JEV 0.2.0-rc.8 上下文选择验收

日期：2026-09-22。配套核心与服务 0.2.3，原有 AI 仍默认，许可证未改。本轮只验证新增上下文选择及直接受影响的开战、指挥恢复流程，未重复上一轮全量引擎或长局测试。

## 定向检查

- 核心 1 项 HTTP→SDK 批量选择测试：鉴权、非法候选、输出校验、一次批处理以及输入不变。
- 酒馆 19 项相关测试通过：新增上下文 5 项、现有指挥控制器 10 项、开战设置 4 项。覆盖手动覆盖、零窗口、未知值回退、消息去重、指挥官更换、能力配置实际进入恢复后的控制器、失败与取消。修正映射后仅重跑受影响的上下文文件。
- 两仓库类型检查与构建通过，酒馆内置核心来源与哈希校验通过。
- 一条原生合成宿主浏览器流程通过 8 个断言：原 AI 默认、开战判定可取消、夜间室内护送实际创建、敌方配置保存、每次开始仅一批选择、刷新恢复不重复调用、战斗中场景固定、无未处理页面异常。浏览器接口回放同一真实模型返回，不增加模型调用。

## 一次真实模型调用

通过酒馆实际准备控制器→本机 HTTP 网关→JEV SDK 调用 `jev-1.13.0`。合成正文描述夜间城堡室内护送，敌方为谨慎且擅长迂回的专家。一次批量调用耗时约 **4.9 秒**，原输入未改变。

模型选择专家（0.96）、高迂回（0.98）、低风险（0.99）、高保全（0.99）、小战（0.94）、室内（0.93）、护送（0.98），也选择了夜间，但夜间置信度只有 0.10。首次映射统一使用置信度门槛，误保留了白天。修正为场景使用合法非 unknown 选项，能力/风格保持 0.6 门槛；随后使用**同一份返回离线回放**确认夜间和其他选项实际落地，没有再次调用真实模型。

最终原生浏览器同样回放这份结果：创建 5×7 夜间室内地图，胜利任务为护送出口；敌方能力为专家，迂回 80、风险 20、保全 80。刷新仍保留上述配置。

本记录不证明所有剧情都可准确识别，也不代表新增了自由绘图、任意战斗规则或敌方指挥胜率提升。JEV 选择引擎支持的项目，部署、伤害与胜负由原引擎执行。全部使用合成输入，未修改用户聊天。
