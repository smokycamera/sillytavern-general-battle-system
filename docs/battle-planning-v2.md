## 地图设计：独立维度，不额外请求模型

同一次开战准备请求使用顶层紧凑 `battlefield`。城市轮廓与损伤不再互斥：

```json
{"battlefield":{"shape":"riverside","gates":"double","gateState":"closed","breaches":{"count":2,"width":2,"sector":"front_left"},"obstacles":"dense","cover":"sparse","breadth":"broad"}}
```

- `shape`: front、enclosure、riverside、hillside。旧返回的broken仍可读取，并映射到有一处初始破口的封闭轮廓；明确breaches优先。
- `breaches.count`: 0—3；`width`: 每处连续1—2格；`sector`: auto/front_left/front_right/left/right/rear。不同破口不邻接，不把同一大洞计成多个洞。不摧毁城门来凑墙体破口数。
- 明确给出设计但不指定破口时，初始城墙完整。纯本地随机地图可以独立随机损伤，不影响明确完好城防的模型选择。
- 非封闭战段没有侧后墙，或指定方位容纳不下所需破口时，在合法墙段回退并显示原因。尺寸不足可以本地升级；不会再次调用模型。
- `gates`: none/single/side/double；`gateState`: closed/open/destroyed。墙体破口与城门状态分别选择。
- 原有size/layout/topology/water/fortLevel和最多5地标保留；补回orientation/relief/cover/obstacles/breadth独立选择。城市cover为可通行普通掩体，relief影响废墟瓦砾，不会把普通城市全部换成自然地形。
- urban仍为城区，不因返回城防字段擅自变成有外围城墙的攻城任务。地图标签、名称、坐标和未支持字段不能生成额外能力或脚本。
- 仅发送有依据的可选字段，模型不输出逐格地图、HP或推理解释。请求次数仍为1；真实第三方响应时延未测，不承诺具体百分比。

## 32张小战／64张场景容量

按双方实际参战**卡片总数**计数，不按hpMax人数、车辆数或单位等级计数。默认1—32张小战（仍需双方有合法单位），33—64张会战，65张及以上在准备阶段拒绝。档案库可以保留更多单位；上场选择不叠加上场历史名单。已开始的旧战斗不因更新被切换模式。

用户明确开启LLM规模选择后，可以在32张以内选择会战；超过32张不能借“室内/攻城/VIP”退回容量不足的小战。会战尚无格子旗点/逃离区域，自动任务在摘要说明转为歼灭；明确要求不兼容任务时拒绝开战而不是暗中换目标。

正文批次最多160个事件、64000字符，可以同一批处理64单位的部署及更新；spawn.count每条20张不变。65张事务失败仍整体回滚。仅治疗老存档不强制删除历史超限名单。

## 部署适配

格子地图先试放完整名单，使用与实际SmallBattle.start共用的部署函数、空地分层和城防平台规则。容量不够时在合法尺寸中上调，最高13×19；不删单位、不改体型、不凭空挖穿完整城墙。显式非法位置继续拒绝，不静默搬动。模型设计的局部修复和尺寸升级写入设计摘要。重点覆盖31:1、16:16、1:31，包括巨体、飞行、先锋和交换攻守。

新会战阵位每层容量在开战时从3—7确定并写入快照，依据人数较多一方/9个阵位计算；阵亡后不缩容量。32:32为4，极端63:1为7。人物有合法编队宿主时仍按原规则随队，没有宿主时在新会战中独立占位、下令，仍是hero而非虚构编队。普通移动、起落、被推拉、先锋、AI候选和召唤均使用同一冻结容量。

没有formationSlots字段的旧会战快照继续使用3容量和旧人物依附规则。新增容量字段校验整数3—7，不能用损坏存档绕过占位。所有部署在副本上进行，保留原档案、人数与偏好。

## 默认设置

新的/缺失字段默认为：selectBattleScale=false，designMap=true，selectVip=true。保留用户已经显式保存的布尔选择，不每次启动强行覆盖。LLM连接本身仍默认关闭，不擅自发送正文到外部API；需要用户启用并配置连接。VIP只为实际护送/拦截格子任务选择，不给普通歼灭或会战强加VIP规则。

## 验证边界

`npm run audit:planning` 覆盖独立地图组合、32张多体型部署、64张会战及存档恢复，并执行有界的32单位逐行动与64单位逐轮战斗。它不是全兵种全等级平衡测试，执行到指定轮数不算“整场完成”。

运行 `npm run typecheck`、`npm test`、`npm run test:extension`、`npm run verify:worldbook-scope`、`npm run audit:planning`、`npm run build:extension && npm run verify:dist`。普通全量测试仍保留5项历史回放和2项旧生命上限失败；对照脚本不允许新增失败，也不改变正常CI结论。

本地Chromium无法访问测试回环服务器（ERR_BLOCKED_BY_ADMINISTRATOR），不把该环境阻止标成浏览器通过。独立GitHub Actions重新执行浏览器操作，结论见本轮validation报告。合成宿主测试不是ST/TT、Android实机验证。
