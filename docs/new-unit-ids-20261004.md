# 新建单位的自编编号（2026-10-04）

现象：正文 AI 新建单位时常给它自编一个编号，例如 `<unit_set id="u9" name="王芳" side="ally" scale="hero" level="4" …/>`，或 `<spawn id="u7" …/>` 之后在同一个 `<tb>` 里用 `u7` 学技能、上场。入账时整批报“档案 u9 缺失或版本过期”，同批的其他新单位、补员和物品也一起作废；自动批准时因为报错里有“过期”二字，这条记录还被标成“已过期”，看不出是编号写错。

## 原因

编号由插件分配，AI 看到的是单位资料里的 `u1`、`u2`……；新单位在入账前没有编号，AI 想在同一回复里继续修改它、或把 `unit_set` 当成完整建档写法时，只能自己编一个。事务层只认已有档案，编号不存在就整批拒绝；错误文字把“编号不存在”和“回复生成后档案又被改过”合在一句里。

## 修改

- `spawn` 写的 `id` 一律略过：不提示、不写进事件，新单位的编号由插件分配，与 AI 写没写无关。同一回复里再 `deploy` 这个编号是多余的（新单位自动上场），直接略过，并在“识别与格式整理说明”里注明；用它学习、祝福或修改时，新单位此时还没有编号，整批留作“待补全”，提示写进 spawn 或下一次回复按单位资料里的编号修改，不会改到同号的已有单位。
- `unit_set` 写了不存在的编号：
  - 名字与某个已有档案完全相同（且只有一个），就是修改那个档案，不重复建档；
  - 否则写全了新单位字段（name、side、scale，编队还要 hpMax），就按 `spawn` 的规则新建入档：个体的 hp/hpMax 按比例表示伤势、生命上限仍由训练推导；经验进度、备注、盾牌规格、data 等 `spawn` 没有的字段在建档后补上。这样新建的单位只入档，不替换出场名单；同批再写 `deploy` 才上场；
  - 两者都不是，报“档案 u9 缺失：这个编号不是已有单位。修改已有单位请用单位资料里的编号，新单位用 spawn 新建”，自动批准时留作“待补全”，不再标成“已过期”。回复生成后档案又被改动时才报“版本过期，请重新扫描”。
- `unit_set` 新建时，AI 写的 u 编号如果没被占用（已删除单位保留的编号也算占用），新单位就沿用它，下一条回复按这个编号修改的就是同一个单位；被占用时另配编号，同一回复里的引用仍指向新单位。
- 面板预览把这类 `unit_set` 写成“新建档案「王芳」（不改出场名单）”，同批用该编号的学习、祝福等写成“「王芳」（本批新建）…”。
- 单位资料里有 `training` 一栏（训练等级），AI 照抄成 `unit_set training="5"` 时按 `level` 处理，不再整条报“未知属性”。
- 本次输出约束（插件注入的提示词）改为：已有单位的 id 照抄单位资料里的编号，资料里没有的单位不自编编号；新单位一律用 spawn，不写 id。AI 扫描的系统提示同样补上这一句。内置世界书正文没有改。

射击技能保持原规则：“射击”使用单位实际的远程武器，没有远程武器就不可用；呼叫炮击、投弹这类不靠手中武器的攻击写“投射”。同日试过“没有远程武器时射击改由技能自带投射”（新规则 V13），考虑到会让同一技能随装备换算法、与“投射”的分工变模糊，没有采用。

## 验证

- 真实模型：用仓库内置世界书和插件注入的单位资料、本次输出约束，让 DeepSeek（deepseek-flash、deepseek-v4-pro）对四种情形（休整补员换装、新人入队、单位不在资料里、祝福与改造）各回复2次。这16次回复引用已有单位都用了正确编号；有一次照抄单位资料写出 `unit_set … training="5"`，修改前整批报“未知属性”，修改后按训练等级入账。
- 新增测试：`panel/src/narrative-new-units.test.ts` 10项（spawn 的 id 不提示且由插件编号、同回复 deploy 该编号被略过、用该编号修改时报错且不改同号单位、unit_set 自编编号新建并沿用编号、同批学习/祝福/补字段/出场落到新单位、同名档案优先、缺失报错与自动批准状态、被删除单位占用的编号、只入档与恢复出场名单、training）。
- 浏览器预览（单独构建的候选包）：副 API 扫描返回 `<spawn id="u20" name="灰羽弓兵" …>`、`<deploy id="u20"/>`、`<deploy id="u1"/>`、`<unit_set id="u12" name="王芳" …>`、`<bless id="u12" …>`。预览写出“新增 灰羽弓兵”“新建档案「王芳」（不改出场名单）”“「王芳」（本批新建）获得「剧情祝福」”，整理说明只有“已略过 deploy u20…”，没有关于 spawn id 的提示；确认后灰羽弓兵由插件编号为 u13 并上场，王芳编号 u12、只入档、带备注和两场快速祝福。控制台没有错误。
