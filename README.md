# 战阵 · Tavern Battle

面向 SillyTavern / TauriTavern 的原生前端战斗扩展。包含小战与会战、单位档案、装备与库存、技能效果、战果成长、战报归档，以及聊天正文事件的预览和确认。

原生运行包不依赖酒馆助手。战斗规则以 2026-09-18 用户提供的 V4 成品为基线，迁移保留原有引擎、规则和存档内容。

当前发布为 **0.2.0-rc.1**，首个原生扩展候选版。采用[非商业使用许可证](LICENSE)：非商业用途免费使用、修改和分享；商业用途须事先获得 **smokycamera** 的书面授权并按约定付费。详情见[商业授权](COMMERCIAL-LICENSE.md)。

## 安装

1. 在酒馆的 **扩展 → 安装扩展** 中填写 `https://github.com/smokycamera/tavern-battle`，安装后刷新页面。
2. 停用旧的战阵助手脚本，再使用原生扩展。酒馆助手可继续用于其他脚本。原生战阵检测到旧战阵运行器时会停止写入。
3. 打开一个角色的聊天，点击右下角 **⚔ 战阵**。首次打开时才创建完整面板。
4. 如需正文事件联动，在酒馆世界书中导入并启用 [!通用战斗系统约束.json](assets/worldbook/!通用战斗系统约束.json)。已有同版世界书时无需重复导入。可选的[标签折叠正则](assets/regex/tavern-battle-collapse.json)只改变显示，不改写事件。

仓库已包含可运行的 `dist/`，安装时无需 Node.js 或编译。也可下载 Release 的原生安装 ZIP，将 ZIP 内文件放进扩展目录中的独立 `tavern-battle` 文件夹；`manifest.json` 应直接位于该文件夹根部。

更新使用酒馆的扩展更新功能，再刷新页面。本候选版关闭自动更新，安装和数据迁移分别进行。

## 从旧脚本迁移

打开原有聊天后，扩展只读取该聊天持久保存的旧 `variables.panel`。发现旧档会显示单位、库存、战报数量以及需要核对的内容；先导出原档，再选择 **采用当前聊天旧档** 或 **从空档开始**。

迁移前自动保存并核实原档备份。旧本地镜像不会自动覆盖当前聊天，不会因为安装扩展而恢复已经清理的数据。真正空档直接初始化为空；主动清空会留下带新代次的清理标记。

新存档存放在当前聊天元数据 `tavernBattle` 中。每次事实写入都有版本、操作身份与内容校验，并通过宿主聊天读取接口独立核实。保存结果不明时，面板保留已确认状态并暂停写入；使用 **核实并重试保存** 重试同一候选，不重新掷骰或再次结算。只有确认候选尚未落盘时，才可以放弃候选。不要用重复点击战斗按钮代替恢复。

恢复日志和迁移备份保存在当前浏览器 / WebView 的 IndexedDB；清理浏览器站点数据会移除它们。建议用 **存档管理 → 导出完整原生存档** 保存可携带的备份。

## 回退、导入和发送战报

- **回退旧脚本**：在存档管理预览并确认回退，工具会将最新原生进度交回当前聊天旧变量和已确认归属的镜像，停止原生写入。随后停用原生扩展、启用旧脚本。不会恢复迁移前旧进度来覆盖之后的战斗。若旧镜像归属不明确，自动回退会停止，可先导出兼容存档。
- **迁回原生**：先停用旧脚本，再启用原生扩展，预览并确认采用旧脚本阶段的新进度。
- **文件导入**：支持原生导出文件、原生存档容器和兼容旧版面板存档；先预览、备份，再替换当前聊天。助手脚本安装 JSON 不是存档文件。
- **战报发送**：使用结构化消息，不执行战报中的斜杠命令。投递身份防止重发；生成失败时可单独重试生成。输入框草稿和待发附件保留。

## 原生迁移带来的变化

| 项目 | 当前原生实现 |
| --- | --- |
| 安装与维护 | 直接使用酒馆扩展管理、Git 更新和版本入口 |
| 助手依赖 | 正式运行包没有助手调用或远程 JavaScript 加载 |
| 面板生命周期 | 按需创建；关闭重开复用面板，保留表单草稿；关闭后暂停全自动战斗 |
| 代码组织 | 引擎与公共逻辑采用共享构建模块，面板 HTML 与脚本分开缓存 |
| 保存可靠性 | 异步队列、独立读回、恢复候选、版本冲突检测、切聊天隔离 |
| 正文联动 | 使用宿主事件与稳定消息身份，删除前方楼层不会把旧事件误当新事件 |
| 界面偏好 | 主题和桌面窗口位置放在扩展设置中；窄屏切换全屏布局 |

这些是已实现的结构和行为变化，不代表固定百分比的运行速度或内存提升。比较和设计依据见[迁移评估](docs/extension-migration-assessment-20260919.md)与[迁移方案](docs/native-extension-migration-plan-20260919.md)。

## 支持与验证范围

详细证据与限制见[验收记录](docs/native-extension-validation.md)。当前面向单角色聊天；群聊和临时聊天不开放事实写入。390px 布局经过桌面浏览器模拟验收，尚未在 Android/iOS 真机上验收。

本次迁移使用合成档案及隔离酒馆目录验收，没有自动迁移作者的真实聊天。多窗口环境通过 Web Locks 保持一个原生写入器；不支持 Web Locks 的宿主应只打开一个酒馆窗口。

## 开发

使用 Node.js 20.19+；当前构建验收环境为 Node.js 24。克隆仓库后：

```sh
npm ci
npm run typecheck
npm run test:extension
npm run verify:compatibility
npm run build:extension
```

`npm run verify:extension` 还运行浏览器流程测试；Windows 默认使用系统 Edge，可通过 `TB_BROWSER` 指定 Chromium 可执行文件。测试产物保存在忽略的 `artifacts/` 中。真实 SillyTavern 验收脚本只能用于单独准备的测试实例，见验收记录。

`npm test` 包含基线时代的完整测试集，其中 22 项旧断言在冻结原版成品上同样失败；不能把这些断言当作迁移新增回归。当前原生验收使用上面的专用命令，保留旧断言以便后续单独整理。

目录职责：`engine/` 是规则引擎；`panel/` 是共享界面；`host/` 对接宿主；`runtime/` 管理存档、事务与迁移；`extension/` 是原生入口；`assets/` 是配套世界书和正则；`release/baselines/user-20260918/` 是测试用冻结基线。新构建不会覆盖冻结原版。
